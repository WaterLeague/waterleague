# 지도 장애 복구와 조작 대안

2026-10-16. `08-experience.md`의 WebGL 장애 대안·키보드 선택·렌더링 품질 구체화. 계산 모델·예산·저장 버전·연구 적합성 변경 없음.

## 표시와 상태

3D 기본 표시, 사용자가 언제든 2D 평면도로 전환 가능. 두 화면은 같은 공개 건물·도로 경계와 현재 모델의 구역 좌표·시설 배치를 사용. 2D는 지형·침수 결과가 아니며 설치 가능성 가정 표시 유지. 구역 이름·배치 시설·면적을 텍스트로 제공. 표식은 화면에서 32×24px·11px 글자 유지, 겹침 시 표식만 이동하고 실제 구역과 연결선 표시. 작은 화면에도 OpenStreetMap 출처 링크 제공.

WebGL 초기화 실패·실행 중 context loss·장면 오류 시 2D 대안 제공. 설계 이름·메모·선택·배치·undo/redo·계산 결과는 지도 렌더러 밖에 유지. 재시도는 렌더러만 다시 생성하며 자동 무한 재시도 금지. 오류 내부 정보·스택은 화면에 노출하지 않음. 수동 2D 전환은 오류로 표현하지 않음.

구역 목록은 WebGL과 별개로 항상 접근 가능. 목록 열기 시 선택된 구역 또는 첫 구역에 초점, Escape·닫기 시 여는 버튼으로 복귀. 구역 선택 시 목록을 닫고 설치 면적 입력으로 초점 이동. 목록 상태·선택은 ARIA로 노출. 2D 구역도 Tab·Enter·Space 선택 가능하며 색상 외 구역 번호·설치 여부 제공.

## 렌더링

정적인 장면은 변경·카메라 조작 시 렌더링하는 demand 방식 사용. Drei OrbitControls의 invalidate 연동 확인. DPR 상한 유지. 시스템 reduced-motion 설정 변경을 반영해 관성 회전 해제. 자동회전 없음. 이벤트 리스너·텍스처·기하 객체 정리, 해제된 캔버스의 context loss가 새 장면을 장애 처리하지 않도록 리스너 해제.

서울 공통 장면(2026-10-18): 카메라 이동으로 필요 없어진 건물 형상은 Web Worker를 종료하여 다음 형상 생성을 즉시 시작. 취소한 대기 작업은 실행 중인 형상과 분리하고 종료한 스레드의 지연 이벤트 차단. 후보 조회는 새 요청·화면 종료 시 AbortSignal로 통신 취소. 같은 구·시설·빈자리 조건의 이동 중에는 기존 후보 형상을 유지하고, 구·시설 조건이 바뀌면 이전 후보를 즉시 숨김. 설치 가능 여부는 서버가 최종 검증.

주간·재해 모드의 `CityExplorer`·`CityScene`·`CityPlan`·강우 효과 공통 사용. 재해 초 시계 변경은 지도 입력이 같으면 3D 장면을 다시 렌더링하지 않음. 2D 도형·SVG 경로는 실제 2D 표시 또는 장애 대안 진입 시에만 생성. 시설 도형은 좌표·전체 면적·설치 면적이 달라질 때만 재계산하며 카메라 이동으로 생성한 객체의 참조 변화와 분리. 강우 입자는 확대 단계별 영역을 재사용하고 카메라 범위를 여유 있게 포함하되 실제 강우 구 경계·구멍 제외 조건 유지. 재생·일시정지·reduced-motion 동작과 관측량·수문 계산은 미변경.

구 이름·대표 블록 버튼 위의 휠은 같은 3D 캔버스에 전달. 표식 클릭과 키보드 선택은 유지. 카메라 거리 2,400m 미만의 건물 상세 단계에서는 두 표식을 모두 숨기고, 상단 구 선택과 위치 목록을 유지. 2D도 같은 상세 표시 기준 적용. 2D는 드래그 이동과 포인터 위치 중심 휠 확대·축소 지원. 드래그 종료 후 클릭 선택 차단, 페이지 스크롤 방지, 프레임당 표시 변경과 200ms 간격 타일·후보 조회 보고 적용. 공개 경계·건물 경로는 데이터 변경 시에만 재생성.

## 검증 기준

실제 공개자료 화면에서 미배치/배치·2D/3D·그래픽 강제 손실·재시도·키보드 목록 선택·입력 복귀 확인. 좁은 화면 및 키보드 focus 표시 확인. 테스트용 장애 주입은 로컬 QA 화면에서만 제공하며 프로덕션 번들에 포함 금지. 재시도 후 서버 입력·저장 기록 변화 없음 확인.

렌더링 성능은 장치·브라우저·화면 크기·건물/구역 수·측정 구간을 함께 기록. 조작 프레임과 정지 구간을 구분. 단일 로컬 측정만으로 일반 노트북·모바일 전체의 30fps 달성을 주장하지 않음.

## 로컬 장애·성능 재현

`pnpm --dir frontend dev`와 API 실행 후 `http://127.0.0.1:5173/qa/scene.html` 사용. 동일 GamePage와 공개자료를 불러오는 별도 개발 화면이며 로그인·저장·계산은 검증에 필요하지 않음. 실제 환경 계정으로 테스트 데이터를 저장하지 않음.

1. 시설 배치·메모 입력 → 그래픽 연결 강제 손실 → 2D 구역·비용·메모·undo/redo 확인.
2. 다음 3D 초기화 차단 → 3D 다시 시도 → 대안 유지. 초기화 허용 → 다시 시도 → 같은 배치의 3D 복구 확인.
3. 정지 상태의 3초 실제 GL draw 포함 프레임 수 기록. 10초 연속 렌더 버튼은 R3F invalidate로 동일 장면을 연속 재그리는 부하. 실제 GL draw가 있는 루프만 집계. 사용자 조작 지연·발열·전력·실기기 모바일 시험과 구분.
4. QA는 개발 모드·loopback 호스트에서만 실행. Vite 기본 빌드 진입점에 포함하지 않으며 `dist`의 QA HTML·장애 주입 UI·측정 후크 부재 확인. Three.js 자체의 정상 정리용 WebGL 확장 사용과 구분.
