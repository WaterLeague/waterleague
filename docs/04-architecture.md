# 도메인·레이어 아키텍처

기준일: 2026-10-20. 현재 구현의 책임·자원 수명·캐시 계약이다. 화면 동작은 [UX](08-experience.md), 미완료 확장은 [구현 목표](09-delivery.md)에 둔다.

## 수치지형도 전환의 연결 계약

[P0](09-delivery.md#p0--서울-수치지형도-전환과-공통-공간-기반)의 일반 지도·설치 API·워커는 원형 공간으로 전환했다. 접합·표고 검사의 미해결/미확인 범위를 보존하고 전체 공간/화면 대조·로컬 타일 로드/재사용을 검증했으며 P6 대상 기기의 전체 성능·흐름 검증은 별도다. 프로젝트에 보관한 25개 구 원본을 해시 검증 → 도엽 중복 제거 → 실제 레이어/속성 정규화 → 공통 공간 카탈로그 순으로 처리하고, 그 카탈로그에서 표시 타일·설치 후보·집수면/모델 참조를 만든다. 화면 타일의 단순화·절단은 표시 최적화이며 계산 면적이나 유역 경계를 변경하지 않는다.

공간 객체·시설 설계·강우/토양/피복·배수 연결·평가 입력은 같은 원본 버전과 파생 해시에 결속한다. 기존 SWMM/ANUGA에 이 입력을 공급하며 지도 전용 효과 엔진을 추가하지 않는다. 표시 캐시와 수문 계산 캐시를 분리하고 공간 입력 버전 변경 시 관련 계산 캐시를 무효화한다. 서비스 경로의 OSM 의존 교체와 과거 원본/재현 근거 보존을 분리하며 원본 ZIP/PDF를 브라우저에 일괄 전송하지 않는다. 세부 검사·연결 규칙은 [공간 적용 계약](19-spatial-source-audit.md#서울-25개-구-전환-계약)을 따른다.

일반 화면의 `GamePage`는 주간·재해·기록·데이터·관리자 진입과 계정 세션만 조정한다. 사용하지 않는 설계실 분기/컨트롤러와 시작 시 연구 모델·구형 설계 목록 조회를 제거했다. 계정 도메인의 `AccountSessionService`와 `useAccountSession`은 초기 요청 공유·세션 만료·로그인/로그아웃의 세대 검사를 맡고, 늦은 응답이 새 계정/소속을 덮어쓰지 않게 한다. 일반 화면은 연구 모델 조회를 진입 조건으로 사용하지 않는다. 현재 Native 연구/기관 서버 API와 원 수치 재현 자료는 각 도메인에서 유지한다.

## 도시 장면 도메인 (2026-10-19)

`frontend/src/domains/urban`은 repository의 해시·Zod 검증, controller의 도로 타일/인구 로딩과 재생 시각 ref, service의 태양/인구/경로/도로 형상 수학, view의 조명·도로·보행/차량·창문 재질로 분리한다. API키·새 외부 브라우저 요청·의존성 추가 없음. 고정된 카탈로그 해시→타일별 해시를 확인하고 경로·크기·좌표·객체 수를 제한한다.

건물·도로면·보도·수면·중심선은 원형 서울 장면의 같은 686개 압축 타일에서 읽는다. 최대 9타일·건물 7,000개·기타 객체 12,000개·원문 24MiB 시야 예산을 적용하되 첫 타일은 전체 보존한다. 해제 후 해시와 실제 화면 DTO를 검사하고, 24타일 메모리 캐시와 원문 128MiB 기기 캐시를 구분한다. 지상 후보는 150ms 조정 조회·이전 요청 취소·별도 32MiB 캐시를 적용한다. Worker에서 지형 삼각면에 정합한 도로 표면을 생성하고 교체 이후 이전 GPU 형상을 해제한다. 도시 객체는 인스턴싱으로 최대 차량 300·보행자 180·가로등 500개, 근처 후보 1,600개만 사용한다. 시선과 선분 사이 거리로 긴 도로도 선택한다. 프레임별 React 상태 변경 없이 공통 demand 렌더와 시각 ref를 사용하며 인구 배분은 구/시간 단위로 캐시한다.

태양 uniform·장면 조명·빗방울은 수면 캡처보다 먼저 갱신한다. 그림자 범위는 시야 거리에 맞추고 지도 전체/밤에는 끈다. 주간 천문 시계는 1초, 연속 교통은 기존 30Hz 수면 깨움과 공유한다. 과거 시각 변경은 구독자 invalidate로 즉시 반영하고 일시정지에서는 독립 타이머로 렌더하지 않는다. 장면 종료 시 타이머·구독·Worker·재질·형상 정리. 원 수문 계산·강우·시설 제원·점수 경로는 변경하지 않는다.

`backend/urban`은 121장소 고정 카탈로그 repository, 서울시 HTTPS repository, 원문 검증 mapper, 단일 진행 요청을 공유하는 service, 비회원 GET controller로 구성한다. 한 요청은 유효한 장소 ID 1~6개만 받으며 외부 연결은 최대 4개, 요청별 10초·본문 1MB·리디렉션 금지다. 성공 응답은 각 필드 유효기간 안에서 최대 5분, 부분 실패는 최대 1분 캐시한다. 인구와 교통의 실패는 독립적이며 자료 만료를 연장하지 않는다.

프론트는 250m 시야 단위·300ms 지연으로 가까운 최대 6장소를 선택한다. 1분 조회, 이전 요청 취소, 숨긴 탭/재해/원경 조회 중단을 적용한다. 현재 수치지형도의 명시적 양방향 도로중심선만 차량 표시 경로로 사용하며 미확인 방향·보행 경로·주차 칸은 생성하지 않는다. 실제 이동 지점이 공식 장소 안에 있을 때만 인구 범위의 중간값/면적으로 표시 예산을 계산하고, 유효한 장소 평균 속도를 차량 이동량에 적분한다. 0km/h 정지, 속도 갱신 위치 연속성, 장소 밖/만료 시 참고 프로필 복귀를 보장한다. 수면·빗방울은 같은 도시 시계의 사건 시작 기준 초를 사용하여 정지·배속·앞뒤 탐색과 연결한다. 주간 수면은 장면 시작 이후 실제 시간 차를 사용하고 모션 축소 시 정지한다.

동일 출처 HTTPS의 React 앱·Spring Boot API, PostgreSQL/PostGIS, 격리된 Python SWMM 워커. Oracle 4 OCPU·24GB의 모듈형 모놀리스로 시작. 측정된 필요에 따라 분리.

초기 작업 큐는 PostgreSQL 트랜잭션·lease 기반. 전략 저장과 Redis enqueue의 이중 쓰기를 피하고, 필요 시 outbox로 Redis Streams 연계. Redis는 초기 필수 구성 아님. 세션은 프레임워크 기반 서버 저장.

공개 관망 회원 연구는 `watershed` 도메인의 V20 불변 요청·서버 카탈로그·소유자 조회로 연결. `WATERSHED` 큐는 기존 입장 잠금/180초 lease/3회 한도/오래된 결과 차단을 공유하며 공용 활성 수에 포함. 독립 프로세스는 150초 벽시계·75초 프로세스 CPU·64MiB 파일 한도, 비밀 환경 미전달. 공개 원 관망의 수치 파생과 문헌 시설 컴파일러를 사용하여 기준안/공동안 2실행. 실패 결과도 보고서에 보존하고 계산 품질과 작업 완료 상태 구분. 실행 시점 코드·엔진·라이선스 포함 원 소스·파생/원 입력·프레임을 보관하며 모든 산출물의 해시를 DB 결과에 결속. 현재는 서버/워커 경로이며 공통 게임 화면의 설계·결과 연결은 다음 범위.

재해 시작 수분 비교는 별도 큐를 추가하지 않고 기존 historical 요청에 선택한 배치 한 곳과 `SELECTED_SURFACE_7_DAY_DRY_WET_V1` 정책을 고정한다. 워커의 일반 계산 후 같은 선행 관측·제원으로 `initialization_sensitivity.analyze(days=(7,))`를 실행하며, 비교 없는 요청은 기존 비용 유지. 결과는 일반 결과와 분리한 `initializationSensitivity`, 재현 파일은 같은 소유자 경계의 `sensitivity/`에 보존한다. 요청 대상 변경 멱등 충돌·추가 대상 수 제한·기존 CPU/시간/파일 크기 제한 유지. 화면은 공통 설치 패널과 물리 근거 컴포넌트 사용, 프레임 재생·지도 렌더가 추가 계산을 유발하지 않는다.

실제 책임이 생길 때 파일 생성. 이름만 있는 빈 클래스·중복 exception 디렉터리 금지. backend view는 JSON 표현이며 React와 중복 화면 템플릿 아님.

## 의존 방향

view → controller → service → repository. mapper는 DTO/entity/view 변환. 서버 service가 소유권·규칙·트랜잭션, entity가 불변식 담당. 다른 도메인 repository 직접 참조 제한, 공개 service/port·ID로 연결. 공통 영역은 기술 횡단 관심사로 제한. 프론트 순수 service는 React·fetch·Three.js에 비의존, renderer는 공식 점수 미계산.

## 실행 경로·일관성

입력 → 사용자·기간·동의·배치·예산·검증 수준 재검사 → 불변 전략과 작업 원자 저장 → `FOR UPDATE SKIP LOCKED` lease → 승인 모델 격리 계산 → lease token·입력 hash·품질 검증 → 결과 확정 → 자격 있는 공식 제출만 랭킹 반영.

at-least-once 작업 처리, run/hash unique·fencing token으로 결과 한 번 확정. 만료 워커 결과 거부. Idempotency-Key는 사용자·endpoint·요청 해시에 연결, 같은 키 다른 본문은 409. 제출 한도는 DB 트랜잭션으로 보호. 공식 제출·기관 열람 때마다 동의·권한 재검증.

## 버전

Java 25·Spring Boot·React 19·TypeScript·Three.js/R3F를 사용한다. 정확한 현재 버전은 `backend/pom.xml`, `frontend/package.json`/lockfile, `simulation/pyproject.toml`/lockfile과 배포 lockfile이 기준이다. 변경 시 공식 안정 배포·호환성을 확인하고 고정한다. [Spring 시스템 요구사항](https://docs.spring.io/spring-boot/system-requirements.html) 확인. PostgreSQL/PostGIS·Python/SWMM은 ARM64와 수치 재현 검증 후 고정.

## 지표 원 계산 프레임

`engine/surface_frames.py`가 명시적 `frameOutput` 설정이 있는 계산에서만 격자 원형과 중심 수심/운동량을 읽기 전용 보관. `native-frames/catalog.json`은 입력·파일 해시·실제 출력 시각·수치 상태·좌표/수직 기준·출력 한도를 연결. 꼭짓점 xyz/중심 xyz/면적은 `<f8`, 삼각형 꼭짓점 색인은 `<u4`, 각 프레임은 삼각형 순서의 `[depthM, xmomentumM2s, ymomentumM2s]` 행렬 `<f8` little-endian. 좌표는 입력의 로컬/투영 좌표 그대로이며 서울 화면 좌표로 임의 치환하지 않음.

`engine/surface_frame_reader.py`는 외부에서 고정한 결과 해시→카탈로그→입력/격자/요청 프레임의 해시를 확인. 프레임 하나만 읽고 명시한 화면 범위와 교차 가능성이 있는 삼각형을 선택하며, 이 조회 범위가 계산 경계나 점수 영역을 바꾸지 않음. 수치 실패·파일 링크·경로 이탈·형식/크기/해시 불일치·시간 외삽은 도메인 예외. 이 reader 자체는 공개 API가 아니다. 서버의 공통 지도 전달 경로에서 작업 소유·동의를 매 요청 검사한다. 원 지표는 엔진 내부 집계에서 유지하고 화면 프레임으로 다시 집계하지 않음.

### 지표 결과의 공통 지도 전달

`presentation/surface_playback.py`는 `NativeFrameReader`로 전체 원본 무결성·수지를 확인한 뒤 원 지형 WKT·원점에서 도시 EPSG:5186 원점으로 수평 좌표만 변환한다. 비근사 변환을 사용하고 변환식·정확도 메타데이터 보존. 원 수심·운동량 바이너리를 그대로 복사하며 표시 지표 높이와 물리 기준고를 혼합하지 않는다. `surface-playback/catalog.json` 해시를 작업 결과에 고정한 실행만 서버 도메인의 repository→service→controller에서 조회한다. 요청마다 권한과 해시를 검사하며 권한 캐시는 사용하지 않는다.

공통 `CityExplorer`의 계산 침수 제어와 `SurfacePlan/SurfaceLayer`를 주간·재해 지도에 연결. 2D/3D는 동일 격자·수심/속력 색상표·실제 기록 시각 사용. 3D는 Worker의 Float32 표시 형상만 사용하며 원 Float64 계산값 불변. 표시 지형+2cm 위에 원 수심의 상대 두께를 1:1로 올리고 외곽·수심 단차의 측면을 생성한다. 수직 기준 계약 `TERRAIN_DRAPED_SCALAR_NOT_WATER_ELEVATION`을 유지하며 실제 절대 수면고로 승격하지 않는다. 지도 투영 전 운동량을 방향 화살표로 사용하지 않는다. 재해는 공통 강우 시간축과 연동, 주간은 선택한 본인 설치의 저장 프레임 조회. 시간 밖 외삽 금지, 이동 요청 250ms 조정 및 이전 요청 취소. 결과 없는 작업의 안내·좌표 원점 불일치·오래된 다른 실행 응답 거부. 결과 전체 정확도·30fps·서울 연결 유역의 운영 게시 완료는 이 전달 기능만으로 주장하지 않는다.


### 3D 수면 재질과 자원 수명

`WaterScene`이 모든 수면을 제외한 장면 색상·깊이를 프레임당 한 번 공유 캡처한다. 긴 변 1024px 상한, 화면 공간 반사 32보행·5회 교차 세분화, 화면 밖/고도 16km 초과의 하늘색 대체를 적용한다. 굴절은 깊이 재구성으로 전경 물체를 제외하며 수면의 depthTest/depthWrite를 사용한다. 형상·재질·깊이 텍스처는 해제하고 Worker는 완료/실패/교체 시 종료한다. 하천 경계·섬 구멍을 보존한 Worker는 먼저 표시 지형에 맞춘 뒤 80m 변을 목표로 분할하되 14단계·12만 삼각형 예산으로 제한하며 원 삼각형을 버리지 않는다. 원본이 예산을 넘는 경우 원본 보존이 우선이다.

공통 30Hz 요청 타이머와 demand 렌더를 사용하되 실측 30fps 보장을 뜻하지 않는다. 재해 일시정지·접근성 reduced-motion·숨긴 탭에서 공통 물결 시간을 멈춘다. 시각 파고·반사·굴절은 조회 프레임·점수·질량수지에 반영하지 않는다. 자연 하천 flow 속성은 0이며 관측 풍향은 물결 방향에만 사용한다. 지표 계산 flow는 기존 프레임의 투영된 유향×유속을 보존한다.

무풍·풍향 결측·관측 공백에서도 공통 시간에 따른 제자리 법선 진동을 유지한다. 바람이 유효할 때만 방향 위상을 더하며 풍향과 풍속의 유효성을 따로 판단한다. 서울 전체 축척에서는 화면 미분으로 넓은 법선 대역을 혼합한다. 제자리 진동과 축척별 대역은 반사·굴절의 시인성을 위한 표현이며 실측 파장·수위·유속 입력이 아니다.


`terrainDrapeService`는 표시 삼각형을 지형의 행·열·대각선과 교차 분할하고, `terrainMeshData`와 같은 삼각면 보간을 적용한다. 하천·침수 기록·계산 수심 상면과 측면에서 공유한다. 지형 외곽은 기존 가장자리 높이 고정을 유지하고 원 평면 범위는 자르지 않는다. 각 수면 형상의 위치 버퍼 9백만 성분 상한 초과 시 오류 경로로 반환하며 일부 영역을 조용히 생략하지 않는다. 원 계산 Float64 및 원 기록 파일은 불변이다.

`FloodTraceLayer`도 `WaterScene`에 등록하여 반사의 자기 참조를 제외한다. 기록에는 수심·유속을 만들지 않고 깊이 판정을 적용한다. 축척별 물결 법선·색상 대비는 실제 게임 지도 축척에서 식별되도록 구성한다. 하늘의 반사 패턴은 화면 밖 반사의 그래픽 대체이며 현재 구름 관측을 표현하지 않는다.


### 침수 경계와 이동체

`urban/service/floodFieldService`는 표시 중인 계산 프레임과 재해 사건의 삼각화된 침수흔적을 128m 공간 인덱스로 조회한다. 원자료 객체별 WeakMap 인덱스와 최대 4개 조합 캐시, 도로/차선별 경로 교차 캐시를 사용한다. 도로 중심선에 실제 표시 차선·보도 편위를 적용한 뒤 삼각형 반평면 교차로 정확한 진행 거리 구간을 계산한다. 병합 구간과 개별 셀 접촉값을 별도 보존하여 서로 다른 셀의 최대 수심·최대 유속을 결합하지 않는다. 교량은 제외한다.

`floodMovementService`의 순수 표시 함수가 감속·정차·회피·대피·고립 위치를 결정한다. 재해는 사건 시계와 고정 배치로 되감기를 재현하고, 주간은 누적 이동량과 마지막 위치를 보존하여 관측 속력 변경·침수 자료 교체로 위치가 튀지 않게 한다. 계산 입력·점수 경로는 변경하지 않는다. `StreetLife`는 기존 인스턴스 렌더에 팔·경고 기호·차량 비상등을 추가하며 React에는 변경된 주변 표시 객체 수만 전달한다. 거리·인구 표시 예산은 유지한다.

## 지도 장애 복구와 캐시

WebGL 초기화·context loss·장면 오류 시 렌더러 밖의 선택·설계·결과 상태를 보존하고 평면도/목록·명시적 재시도를 제공한다. 자동 무한 재시도와 내부 오류 노출은 금지한다. 2D/3D는 같은 공개 형상·선택·중심/축척을 공유하며 원 계산 프레임과 표시 지형은 구분한다. 키보드 목록 선택·Escape/포커스 복귀·좁은 화면은 [UX](08-experience.md) 기준이다.

정적 장면은 demand 렌더링, 연속 물/도시 표현은 공통 깨움 타이머를 사용한다. 점수·재생 시각만 바뀌면 건물/도로 형상을 재생성하지 않는다. 카메라 위치 ref와 데이터 조회 상태를 분리하고 새 Worker 결과가 준비될 때까지 이전 형상을 유지한다. 종류 필터는 후보 재삼각화 대신 표시 속성으로 적용한다. 선택·설치·초안만 별도 강조한다.


3D 카메라는 매 조작 프레임 현재 위치 참조만 갱신하고, 휠 종료를 포함해 마지막 움직임 후 180ms에 타일 조회용 상태를 반영한다. 2D는 조작 중 SVG viewBox만 프레임별 변경하고 200ms 뒤 React 상태·자료 조회를 합친다. 자료 교체 중 기존 건물·도로·후보 메시를 유지하며 새 Worker 결과를 한 번에 교체한다. 필터는 재질 uniform만 변경하고 후보 삼각화를 다시 실행하지 않는다. 목록의 기본 200개 후보를 개별 메시로 중복해서 덮지 않으며 선택·설치·저류 계획 구역만 별도 표시한다.

도로는 로드한 파일 전체 대신 시야와 여유 범위가 겹치는 원 도로만 기하화한다. 원거리 개요·파일 캐시는 유지한다. 형상 법선·구역 경계 상자·전체 경계 구는 Worker에서 생성한다. 도로·지상 후보의 클릭은 구역 경계 상자 통과 면만 검사하며, 수면 반사 캡처는 수면이 카메라 절두체 밖에 있으면 생략한다. 도로·후보의 CPU 형상 버퍼 캐시는 각각 48MiB, 지상 후보 원문 캐시는 전송 바이트 기준 32MiB 상한이다. GPU 객체는 교체/언마운트 시 해제한다.

공개 `/data/*.json` 정적 자료는 SHA-256을 포함한 CacheStorage 키로 기기에 보관한다. 네트워크 수신과 캐시 재사용 모두 용량·해시를 재검증하며 손상 항목은 제거 후 다시 받는다. 저장 상한 128MiB를 넘으면 오래된 항목부터 제거한다. 로그인·점수·실시간 기상·API 응답은 저장하지 않는다. 저장소 차단/할당량 실패 때도 네트워크와 메모리 로딩으로 동작한다. 첫 접속은 필요한 도시 개요와 현재 시야의 파일을 취득하며 서울 전역 상세 파일을 강제로 선로딩하지 않는다. [Cache API](https://developer.mozilla.org/en-US/docs/Web/API/Cache), [저장소 할당량](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria) 기준이다.

`qa/streets.html`은 운영의 도로·수면·지형·설치 후보 컴포넌트와 해시 검증 저장소를 사용해 한강대교/횡단보도를 확인하는 로컬 전용 화면이다. 고정 조명과 구조 제원 안내를 쓰며 실제 기상·피해 관측 화면으로 제공하지 않는다. 운영 빌드에 포함하지 않는다.

설치 목록·패널 또는 지형 로딩으로 캔버스 크기가 바뀌어도 시선을 유지하고 명시적 `CityFocus.key` 변경만 이동 요청으로 처리한다. 공개 시설·후보 외곽/높이와 조작 영역 여백을 고려해 초점을 잡는다. 근처 선택은 현재 확대를 유지한다. 형상·재질·텍스처·Worker·구독·타이머를 교체/종료 때 해제한다.

개발 전용 `frontend/qa/scene.html`, `qa/flood-interaction.html`, `qa/streets.html`은 장애·표시·부하 재현용이다. loopback/개발 모드에 제한하고 운영 빌드에 포함하지 않는다. 합성 QA 입력은 공개 관측/현장 검증 근거가 아니다. 측정은 기기·화면·자료량·조작 구간과 함께 [검증 기록](12-validation-log.md)에 보존한다.

## 동일 물리 입력 계산 캐시

캐시 적중은 새 관측이나 독립 물리 실험이 아니다. 아래는 현재 저장 설계/후보 계산 캐시의 범위이며 모든 새 계산 경로에 적용 완료를 뜻하지 않는다.

### 식별과 재사용 범위

모델 원문 SHA-256(강우·초기 수분·시설·평가 경계·수치 조건 포함), 서버 inputHash, 실제 배치 JSON 해시, SWMM 바이너리 해시·버전·소스 revision, 빌더 해시, 실행 정책 코드 해시, OS/아키텍처·Python 버전과 캐시 규약 버전으로 키 생성. 하나라도 다르면 재계산.

성공한 기준안·배치안·두 민감도 계산의 산출물만 보관. request.json·사용자 ID·작업/lease ID·제목·메모·이력·동의·기관·리그 정보는 캐시에 저장하지 않음. 대상 작업의 request.json을 그대로 유지하고 파일 복사 후 결과 실행 메타데이터와 manifest를 대상 작업에서 다시 생성. 공유 하드링크 금지.

result.json의 execution은 규약·동일 조건 식별자·COMPUTED/REUSED만 기록. 원본 계산의 다른 회원 식별자나 작업 경로를 노출하지 않음. 원본 SWMM 보고서 시각은 재사용된 산출물의 시각일 수 있으며 해당 회원의 새 계산 작업 생성/완료 시각과 구분.

### 권한·경합·보관

API의 소유 버전·허용 모델·회원별/전체 큐 한도·요청 멱등성 검사를 거친 작업만 실행. 캐시 적중도 새 작업·새 lease 산출물로 기록하고 worker fencing 유지. 제출 기간·리그 조건·동의·철회·다운로드 권한 재검사를 우회하지 않음.

Unix 로컬 파일시스템의 비공개 디렉터리 0700·파일 0600, 소유 UID 검사. 루트·항목·파일 링크와 비정규 파일 거부, 고정 허용 파일명·크기·내용 hash 검사. 짧은 전역 파일 잠금과 임시 디렉터리→원자적 게시. 잠금 중 계산하지 않으며 잠금 경합 시 새로 계산. 동시에 미스한 워커는 각자 계산할 수 있으나 부분 파일이나 다른 조건의 결과를 게시하지 않음.

최대 128개·2 GiB·7일, 항목별 64 MiB 미만. 오래된 항목부터 정리, 보관 한도 초과 결과는 캐시 없이 완료. 캐시는 소모성 보조 자료이며 영구 재현 산출물과 분리. 손상·누락·만료·권한 오류·캐시 잠금 실패는 재계산, 엔진·모델 품질 오류는 기존 실패 처리. 공유 NFS·다중 호스트 캐시 지원으로 해석하지 않음.

### 설정과 검증

기본 `data/private/simulation-cache`. `.env.local`의 `SIMULATION_CACHE_PATH`로 변경 가능, `SIMULATION_CACHE_ENABLED=false`로 비활성화. 비밀값 추가 없음, 예시 설정만 `.env.example` 갱신.

조건별 키 분리·파일 손상·누락·경로/링크·한도·만료·동시 게시·잠금 경합 검사. 실제 공개 모델과 EPA 엔진으로 첫 계산/재사용의 기준·전략·민감도·분 시계열 동등성과 대상 request 보존 확인. 서로 다른 소유자의 작업별 접근 격리와 재현 ZIP 재실행 확인. 캐시 사용 여부가 점수나 랭킹 가중치를 변경하지 않음.

구현 근거: [Python flock](https://docs.python.org/3.12/library/fcntl.html#fcntl.flock), [Python 원자적 rename/replace](https://docs.python.org/3.12/library/os.html#os.replace). 파일 캐시 실패가 과학적 품질 검사를 생략하는 조건이 되지 않음.


## 편집 가능한 설계의 배치 이력

기존 설계 편집 reducer는 실제 변경 50개를 보관하며 동일 배치 재적용은 추가하지 않는다. 되돌린 뒤 새 편집은 redo 분기를 폐기하고 배열/객체를 복제해 과거 상태를 보호한다. 새 설계·저장본 열기·모델 전환은 이력을 초기화하며 선택 구역의 시설/면적 입력도 복원 상태와 맞춘다. 제목·메모·서버 revision·완료 결과·제출은 이력 조작으로 바꾸지 않는다.

키보드 되돌리기는 지도에 포커스가 있을 때만 적용하고 입력/편집 요소의 텍스트 조작은 유지한다. 저장/불러오기 중 또는 이력 없음은 비활성화한다. 이 구성요소를 새 게임에 재사용할 때도 현재 주간 확정 잠금·재해 revision 검증을 우회하지 않는다. 클라이언트 이력은 서버 원장의 대체물이 아니다.

등록된 탐색 모델의 `generatorSha256`는 해당 고정 생성기와 일치해야 하며, 새 시설 배치를 추가하려고 원 생성기를 수정하지 않는다. 6종 실시간·재해 시설의 LID 배치 생성은 연속 계산 계층에 둔다. 변경 시 기존 INP 바이트 동일성과 고정 모델·캐시 재생을 함께 검사한다.
