# 서울 공간 원자료 품질 검사·적용 계약

## 공개 서초 관망과 지형의 교환 가정

`PUBLISHED_SURFACE_CONNECTION_EXPLORATION_V1`은 원 연구 입력과 도로 대조 위치·강우 분할 격자에서 26개 접합점의 포함 삼각형을 선택한다. 경계 위 점은 최소 삼각형 ID로 결정하고 둘 이상의 유입부가 같은 격자를 차지하면 거부한다. 위치와 지형의 EPSG:5186 기준을 대조한 후 투영 원점을 빼며, 원 관망의 수평/수직 기준 미확인 상태는 유지한다.

원 관저고·맨홀 깊이와 지형 표고를 일치하도록 수정하지 않는다. 지표 오프셋은 별도 시나리오이고 교환 문턱은 원 맨홀 지표고와 해당 격자 평균 바닥 중 높은 값이다. 문턱의 격자 표현 차이·등가 원형 개구부·방류계수·추가 허용 수두를 절점별로 보존한다. 미확인 절대 기준고 입력은 원본과 생성 결과 전체의 재생 대조를 거친 이 탐색 정책에서만 허용하며, 검증 플래그를 true로 바꾸지 않는다. 일반 입력의 높이 확인 검사는 유지한다.

실제 엔진에 전달한 원 INP/지표와 생성 입력을 대조하고 개구부 변조·높이 기준 명칭만 변경·추가 강제 유입·현장 검증 등급 승격을 거부한다. 원 집수 강우와 직접 지표 강우의 면적 분할은 유지하며, 원 시간 강우의 관측소/시간대와 추정 외부 유입을 실측으로 표시하지 않는다. [실행·교환 간격 비교](../data/benchmarks/seocho-surface-connection-v1.json)는 20m 지형·명시적 폐쇄 직사각형 경계 조건의 수치 검증이며 현재 서울 침수 지도나 당시 피해 복원이 아니다.

범위: 취득 시점별 공간 원본·도형·좌표/표고 품질과 모델 편입 근거. 아래 날짜별 후보 수·시험 사례는 해당 버전의 기록이며 현재 전체 게임 범위는 [제품 계약](01-product.md), 확보 여부는 [자료 현황](13-data-access.md)을 따른다.

`scripts/verify_seocho_terrain.py`는 원 레코드로부터 삼각망·격자·ANUGA 입력을 다시 생성해 일치 여부를 검사한다. 서초 관측 강우의 시간/공간 해상도·전달/차단 경계 비교와 반복 실행을 [검증 기록](../data/benchmarks/seocho-terrain-v1.json), [그림](../data/benchmarks/seocho-terrain-v1.png)에 보존한다. 게임 지도 표시 지형이나 현재 순위 입력으로 자동 교체하지 않으며 연결 수리 경계는 P3 후속 구현이다.

## 서울 25개 구 전환 계약

2026-10-20 서울 25개 구의 `수치지형도v2.0(1:1000)` SHP ZIP과 데이터 설명서를 `data/private/vworld-seoul-topography-20260307/originals/`에 복사했다. [원본 목록](../data/manifests/vworld-seoul-topography-20260307.json)의 프로젝트 상대 경로·크기·SHA-256을 기준으로 읽으며 개인 다운로드 경로에 의존하지 않는다. 공통 입력·원 레코드 공간·객체 카탈로그에서 일반 게임 지도·후보/API·워커를 연결했다. 현재 결속은 [서비스 연결](#현재-서비스의-원형-공간-연결), 공간 전환의 검증 범위는 [2026-10-20 전환 검증](12-validation-log.md#2026-10-20-원형-지도-첫-로드타일-재사용과-p0-종합-확인)를 따른다. 아래 성수 4도엽의 기존 적용·재현 기록은 그대로 구분한다.

사전 검사: ZIP 25개 540,518,560바이트, 도엽 참조 3,075개, 고유 도엽 2,488개, 반복 참조 587개. 반복된 같은 도엽의 SHA-256 충돌은 없고 원본/고유 도엽 내부 CRC 검사 통과, 레이어는 121종이다. 선택한 건물·도로경계·교량·등고선·표고점의 PRJ 10,847건은 EPSG:5186이다. 이는 모든 레이어의 CRS·도형 유효성·서울 전역 피복·필드값의 완전성·실측 정확도 통과가 아니다. 상세 검사 파일은 원본 목록에 경로·해시로 결속했다.

`연속수치지형도_데이터_설명서.pdf`의 표제는 「전국 연속수치지형도 코드 및 레이어 설명서」, Version 5.1.1, 작성일 2014-12-30, 153쪽이다. 설명서의 DB 설계를 현재 배포 SHP의 동일 스키마로 가정하지 않는다. 예를 들어 설명서 16쪽 보도는 `N1L_A0033320`이지만 확보 파일에는 면 레이어 `N1A_A0033320`도 있으며, 설명서의 `SCLS`·`FMTA`가 실제 DBF에 있다고 가정할 수 없다. 실제 레이어·도형 종류·필드·코드 값을 대조하고 차이/결측을 기록한다. 설명서 작성일·페이지의 배포 갱신일 2026-03-07·개별 도엽 제작연도는 서로 다르다.

전환 시 다음 규칙을 적용한다.

- 원본 ZIP을 보존하고 도엽 ID+해시로 중복을 제거한다. 다른 버전 충돌은 자동 선택하지 않는다. 원본 레코드 ID는 도엽·레이어·레코드 위치·원본 해시에 결속하고 UFID의 공백/중복/도엽 분할을 검사한다. 실제 시설 단위 병합은 대응표·방법·오차를 가진 별도 파생 과정이다. 도형 건수를 고유 건물 수로 표시하지 않는다.
- 원 도형의 구멍·다중 도형·좌표를 보존한다. 보정 전후·도엽 접합부·중복 면적·서울 경계 안 누락을 검사한다. 유효하지 않은 도형은 자동 복구 후 정상 원본으로 표시하지 않는다. 표시 타일/단순화 형상과 계산용 원형상을 같은 식별자로 연결하되 면적·집수 계산에는 원형상을 사용한다.
- 같은 공간 버전으로 건물/도로·시설 선택·설치 면적·집수면·관망/지표 격자 연결을 생성한다. 공유 집수면과 시설 연결은 면적·유량 배분을 한 번만 계산하며 중복 유입을 거부한다. 구 경계는 소속/집계 기준이고 유역·관망·상하류 경계를 절단하는 기준이 아니다.
- 기존 SWMM/ANUGA에 기상청 강우·기상, 토양·피복, 공개 관망/시설·운영, 경계 수위를 출처/시점/단위/수평·수직 기준으로 결속한다. 시설 위치점·지도 분류는 관경·관저고·연결·운전의 증거가 아니다. 확인되지 않은 배수 경로는 연결 모델로 등록하지 않고 직접 강우 탐색 또는 미지원 상태를 표시한다.
- 등고선/표고점·DEM의 한계를 유지한다. 보간·3D 돌출을 실측 지면/지붕으로 사용하지 않고 정밀도를 축척이나 출력 격자 간격에서 추정하지 않는다. 현재 지형과 과거 강우의 조합을 재해 당시 도시 복원으로 설명하지 않는다.
- 새 기본 지도·후보·공개 시설 결속·모델 경로에서 OSM 의존을 제거한다. 수치지형도에 없는 속성은 검증한 공개 보완자료와 별도 출처 또는 미지원으로 처리한다. 기존 OSM 원본/파생물의 출처·라이선스와 수치 재현 근거는 보존하고 신규 수치지형도의 계보에 섞지 않는다.
- 서울 전역 공간 자료 전환, 유역별 입력 연결, 수치 검증, 현장 대조의 완료 상태를 구분한다. 자료가 확보된 한 유역부터 검증한 뒤 동일 계약으로 확장하며 비공개 자료나 기관 협조를 개발의 선결조건으로 두지 않는다.

### 공통 입력 카탈로그

`scripts/prepare_seoul_topography.py`는 등록 원본 전체의 크기·SHA-256을 검사하고 고유 도엽 ZIP을 원 바이트 그대로 한 번씩 보관한다. 같은 ID의 다른 해시, 경로/파일 링크, 정규화·대소문자 중복 이름, 암호화·지원하지 않는 압축 방식, 선언/실제 해제 크기와 전체 크기 제한 위반은 거부한다. 검사 중 원본 변경과 기존 출력 덮어쓰기도 거부하며 실패한 부분 출력은 제거한다.

`catalog.sqlite`의 `tiles`·`tile_sources`·`layers`에는 도엽 해시, 구별 원본 대응, 구성 파일 해시, 원 PRJ, DBF 필드·레코드 수·삭제 표식·인코딩, SHP/SHX 도형 종류·레코드 수·오프셋을 보존한다. 원 레코드 식별은 `ngii:{도엽}:{레이어}:{1부터 시작하는 레코드 번호}:{도엽 SHA-256}`이며 UFID 공백·중복을 고유 자산으로 병합하지 않는다. ZIP 안의 도형·구멍·다중 도형·속성 바이트는 수정하지 않는다. 미분류·결측·알 수 없는 속성값을 정상 코드나 0으로 치환하지 않는다.

모든 레이어의 데이텀·투영 매개변수·미터 단위를 EPSG:5186과 대조한다. ESRI WKT의 각도 단위 반올림을 허용하되 원 PRJ와 저장 좌표 순서 `x=easting,y=northing`을 보존한다. 문자셋은 명시적 CP949 엄격 해독이며 CPG의 원 선언도 보존한다. 일부 `EUC-KR` 선언에 CP949 확장 문자가 있는 차이는 레이어·행 수로 기록하고 대체 문자로 바꾸지 않는다. 원 DBF 값의 의미·설명서 코드 대조는 별도 미완료 항목이다.

```sh
simulation/.venv/bin/python scripts/prepare_seoul_topography.py
```

기본 출력은 `data/private/vworld-seoul-topography-20260307/catalog-v1/`이고 `summary.json`은 모든 검사가 끝난 뒤 생성한다. 다른 빈 출력 경로를 `--output`으로 지정해 재생성할 수 있다. [공개 검사 요약](../data/manifests/seoul-topography-catalog-v1.json)은 원본 목록·생성기·SQLite 해시와 집계·도구 버전만 포함한다. 원본/카탈로그/좌표는 Git 제외 경로에 보관한다. 이 단계의 통과는 압축·구성·좌표계·문자셋 검사이며 도형 유효성·접합·서울 피복·현장 정확도·서비스 전환 검증이 아니다.

구성 검사 근거: [Esri SHP/SHX 기술 설명](https://www.esri.com/library/whitepapers/pdfs/shapefile.pdf), [GDAL Shapefile 문자셋](https://gdal.org/en/stable/drivers/vector/shapefile.html), [Python ZIP 해제 제한](https://docs.python.org/3.13/library/zipfile.html#decompression-pitfalls).

### 원 레코드 공간 카탈로그

`scripts/prepare_seoul_spatial.py`는 위 입력 카탈로그에서 모든 원 레코드의 도형·속성·출처를 `spatial.sqlite`로 정규화한다. 원 식별자와 SHP 레코드·DBF 행의 해시를 보존하고 유효 도형의 원 좌표 WKB·미터 면적/길이·부분 대응을 저장한다. 링을 자동으로 닫거나 방향을 뒤집거나 `make_valid`로 복구하지 않는다. 구멍은 ESRI의 시계 방향 외곽·반시계 방향 내부 링 규칙과 유일한 포함 관계가 확인될 때만 연결한다. 해석할 수 없는 링·자기교차·퇴화 선은 원본 대응과 오류 상태를 보존하고 계산용 면적을 부여하지 않는다.

R-tree는 범위 후보 검색에만 사용하며 조회 결과는 원 WKB의 실제 교차로 다시 검사한다. 완성 파일에 인덱스 통계를 저장하고 조회는 범위 검색부터 수행한다. 지도 절단·단순화·공간 인덱스의 부동소수점 범위를 설치/집수 면적으로 사용하지 않는다. 동일한 조회 객체에 원 식별·형상·면적·속성·축척·공간 카탈로그 해시를 반환한다. 구 경계 병합·도엽 접합·후보 생성·모델 편입은 이 단계에 포함되지 않는다.

[레이어 해석 계약](../data/manifests/seoul-topography-semantics-v1.json)에 설명서 해시·페이지, 실제 121종 레이어의 이름/도형/축척 대조, 필드표와 게임 관련 12개 코드군을 결속했다. 실제 레이어의 110종은 목록과 일치하고 8종은 해당 축척이 목록에 없으며, 2종은 공간형태가 다르고 1종은 목록에 없다. N3는 1:5,000 자료로 구분하며 N1의 1:1,000으로 표시하거나 도형을 합치지 않는다. 실제 보도 면 `N1A_A0033320`과 목록에 없는 선 `N1L_A0033330`을 같은 객체로 간주하지 않는다.

코드 또는 설명서의 유일한 정확한 명칭만 해석한다. 결측·미분류·기타·미등록 값·설명서의 축척 범위 밖 값을 구분하고 알려진 코드로 대체하지 않는다. 복합 용도·미등재 포장 재료도 원문 그대로 보존한다. 다른 레이어의 중심선 속성을 도로 면 전체에 복사하지 않으며 일방통행 여부에서 선의 정/역방향을 결정하지 않는다. 원 수치 속성의 값/범위와 미확인 단위는 분리하므로 표고 수치로 지형·수직 기준·미세 경사를 생성하지 않는다. 나머지 코드군 해석과 설치 적합성 검증은 미완료 상태다.

```sh
simulation/.venv/bin/python scripts/prepare_seoul_spatial.py
simulation/.venv/bin/python scripts/verify_seoul_spatial.py \
  --output data/private/vworld-seoul-topography-20260307/gdal-spatial-v1.json
```

기본 공간 출력은 `data/private/vworld-seoul-topography-20260307/spatial-v1/`이다. 기존 출력 덮어쓰기·입력 해시 불일치를 거부한다. 공간 카탈로그·원 값 프로필·상세 진단은 Git 제외이며 [공개 공간 검사 요약](../data/manifests/seoul-spatial-catalog-v1.json)에 집계·원본/코드/산출물 해시·실행 도구 버전과 독립 GDAL 대조 결과만 보존한다. 검사 통과를 서울 전역 피복·도엽 접합·현장 정확도·게임 지도 전환 완료로 표시하지 않는다.

### 자치구 소속·도곽 피복·공간 객체·지도 파생

소속·집계 경계는 서울시 [상권분석서비스(영역-자치구), OA-22161](https://data.seoul.go.kr/dataList/OA-22161/A/1/datasetView.do)의 공개 25개 다각형과 행정코드를 사용한다. 공공누리 제1유형이며 서울특별시·서울신용보증재단 출처를 표시한다. 원 ZIP·PRJ·UTF-8 CPG·원 속성·행/도형 해시를 보존하고 EPSG:5181에서 5186으로 변환한다. 파일 수정일 2023-10-31은 실제 조사 기준일이 아니다. [경계 스냅샷](../data/derived/seoul-district-boundaries-v1.json)의 조사 기준일은 결측으로 유지한다. 원형 복구·단순화·수문 유역 절단은 수행하지 않는다.

도엽 피복은 설명서 143쪽의 원 도곽선 `N1A_H0010000`·`N3A_H0010000`으로 검사한다. 객체 분포의 사각 범위나 수치지형도 행정 경계로 서울 면적을 대체하지 않는다. [도곽·접합 검사 요약](../data/manifests/seoul-topography-coverage-v1.json)의 면적은 **등록 도엽의 범위**이며 모든 지물이 존재하거나 현장 정확도가 검증됐다는 의미가 아니다. 확보한 1:1,000 도곽 밖을 1:5,000 또는 OSM 자료로 자동 채우지 않는다. `prepare_native_coverage.py`가 같은 원 도곽과 행정 경계의 차집합을 `seoul-coverage-v1.json`으로 생성한다. 미확보 37.6412km²와 1:5,000만 확보한 0.3158km²의 원 피복 검사 자료는 재현을 위해 보존한다. 게임의 2D/3D 사선 표시와 ‘지도 자료·표시 범위’ 펼침 영역은 제거했으며 런타임에서 피복 도형을 조회하지 않는다. 이 영역의 지형 배경은 유지하지만 없는 건물·도로·수면을 추정하지 않는다. 25개 구 전체를 검사하며 원형 차집합의 구멍을 유지하고 수치 오차 조각 1e-6m² 이하만 제외한다. 자료 부재와 로드 지연/오류를 같은 상태로 표시하지 않는다.

`prepare_topography_objects.py`는 원 공간 카탈로그의 1:1,000 건물·도로면/중심선·보도·교량·터널·철도·하천수면·호소·경지계 면을 파생 객체로 연결한다. 원형의 양의 교차 면적/길이가 가장 큰 구를 소속으로 정하고 동률이면 공개 행정코드를 사용한다. 구별 교차량과 원형 전체를 함께 저장하며 구 경계로 자르지 않는다. 서울 밖에만 있는 원 레코드는 이 화면용 객체 목록에서 제외하지만 원 공간 카탈로그에 보존한다.

- 도형 키는 레이어와 정규 순서 WKB의 SHA-256이다. 같은 레이어에서 좌표가 정확히 일치하는 도형만 묶고 대표 원 WKB와 모든 도엽·레코드·SHP/DBF 해시 대응을 보존한다. 좌표 스냅·근접 병합·UFID 단독 병합은 금지한다. 도형 그룹은 고유 시설 식별이 아니다.
- UFID를 제외한 원 속성의 모든 차이를 보존하고 속성 충돌은 배치 제외 상태로 반환한다. 서로 다른 건물 도형의 양의 면적 겹침도 그대로 보존하며 해당 건물 모두를 배치 제외 상태로 반환한다. 겹친 면적을 두 번 집수면으로 배분하지 않는다.
- 동일 UFID의 건물 조각은 속성 일치·면적 비중첩·공유 선·양쪽 원 도곽선에 놓인 공유 선·합집합 면적 보존이 모두 확인될 때만 접합 근거가 있다. 현재 대조에서 이 조건을 만족한 쌍은 없으며 접합을 적용하지 않는다. 같은 UFID의 별개 도형을 강제로 하나의 지붕으로 만들지 않는다.

[객체 검사 요약](../data/manifests/seoul-topography-objects-v1.json)은 역할/구별 집계·출처/코드/객체 해시·배치 제외 정책만 공개한다. 원 레코드 대응·속성·WKB가 든 `objects.sqlite`와 접합 상세 기록은 Git 제외 경로에 보관한다.

`prepare_topography_scene.py`는 같은 객체 ID·소속·원 면적/길이·배치 상태로 시야별 파일을 생성한다. 고정 원점 `[198128,551989]`을 뺀 EPSG:5186 미터 좌표를 사용하며 원 도형·구멍·다중 도형을 타일 경계로 자르거나 반올림하지 않는다. 대표점으로 파일을 배정하되 각 파일의 조회 범위는 객체 전체의 경계를 포함한다. 타일 좌표만으로 파일을 선택해 경계를 가로지르는 객체를 누락시키지 않는다. 계산은 이 표시 파일에서 재구성하지 않고 해시가 연결된 원 객체를 사용한다.

건물 층수×3.2m는 표시 가정이고 유효한 정수 층수가 없으면 `UNKNOWN_HEIGHT_FLAT_DISPLAY`의 0.3m 평면 표시다. 도로의 일방통행 여부만으로 정/역방향을 추론하지 않고, 원 도로폭의 단위 미확인을 유지한다. 실제 주차 칸·교량 고도·시공 적합성·관망 연결을 생성하지 않는다. [지도 파생 요약](../data/manifests/seoul-topography-scene-v1.json)의 `serviceMigrated=false`는 해당 생성 시점의 상태로 보존한다. 현재 서비스·홈 하단 데이터 영역의 원형 공간 연결과 잔여 성능 검사는 [현재 연결](#현재-서비스의-원형-공간-연결)로 구분한다.

```sh
simulation/.venv/bin/python scripts/fetch_seoul_observations.py district-boundaries
simulation/.venv/bin/python scripts/prepare_seoul_boundaries.py
simulation/.venv/bin/python scripts/prepare_topography_objects.py
simulation/.venv/bin/python scripts/audit_topography_seams.py \
  --output data/private/vworld-seoul-topography-20260307/seam-audit-v1-final.json
simulation/.venv/bin/python scripts/prepare_topography_scene.py
simulation/.venv/bin/python scripts/verify_topography_scene.py \
  --output data/private/vworld-seoul-topography-20260307/scene-verification-v1.json
```

기본 출력은 `objects-v1/`·`scene-v1/`이고 입력 불일치·기존 출력 덮어쓰기·생성 중 입력/코드 변경을 거부한다. 독립 출력은 `--output`으로 지정한다. 지도 대조는 전체 파일의 크기/해시·객체 중복/누락·원 형상/면적·파일 조회 범위를 검사하며 현장 정확도와 브라우저 성능 검증을 대신하지 않는다. NGII 지도 이용조건 근거는 [수치지도 V2.0 공공누리 제1유형](https://www.data.go.kr/data/15059719/fileData.do)이며 브이월드 배포 출처도 함께 표시한다.

### 원형 대응 설계 영역과 계산 입력

`prepare_topography_sites.py`는 위 객체 카탈로그와 같은 원 공간 버전에서 옥상·지상 설계 영역을 만든다. [설계 영역 검사 요약](../data/manifests/seoul-topography-sites-v1.json)은 형상 후보의 검사 결과이며 시설별 제원/단가 결속이나 일반 게임의 설치 허용 목록이 아니다. 모든 시공 적합성은 UNKNOWN이다.

- 옥상은 아파트·연립주택·일반주택·주택외건물 분류의 원 footprint 전체를 사용한다. 구멍·분리된 면을 채우거나 합치지 않는다. 속성 충돌·건물 면적 겹침·그 외 종류는 제외하며 건물 분류를 실제 지붕 상태·구조 하중·방수/배수 확인으로 사용하지 않는다.
- 지상은 실제 보도·도로면·경지계 면 순서로 처리한다. 건물·교량/터널·철도·수면·횡단보도·안전지대·입체 교차 등 원 면을 제외하고 먼저 배분한 지상 영역도 뺀다. 원 면적·잔여 면적·차이·제외 원 레코드 또는 앞선 후보 대응을 보존한다. 경지계 면은 포장면 분류가 아니며 형상 후보만으로 투수포장 등 시설을 승인하지 않는다.
- 잘못된 원 제외/지상 도형의 범위와 닿는 영역은 보수적으로 제외한다. 제외 연산 실패·0.01m² 내림 상한 미만·서울 소속 교차 없음도 별도 판정이다. 원 도형 복구·좌표 스냅은 수행하지 않는다. 제외 연산의 면적 허용오차는 1e-7m²이고 구 경계로 영역을 자르지 않는다.
- 후보 ID는 원 객체 ID와 파생 형상 해시에 결속하며 충돌은 거부한다. R-tree 범위는 후보 검색만 수행하고 중복 배분은 실제 도형 교차로 검사한다. 외부 집수면·관망 연결·시공 가능 면적을 생성하지 않는다.

주차장 추가본은 `prepare_native_parking_sites.py`와 [주차장 검증 기록](../data/manifests/seoul-native-parking-v1.json)에 결속한다. 원 주차장 1,199개 중 서울 밖 19개, 기존 후보/제외 면으로 덮인 48개를 제외한 1,132개를 추가했다. `PARKING_AREA`는 투수포장 공통 문헌 비교 조건이며 현장 재료·시공 적합성은 미확인이다. 기존 후보 1,023,100개의 식별자·원문·형상은 보존하고 총 1,024,232개 중 1,022,710개를 지원한다. 원형 DB와 추가본·추가 근거의 해시를 구분한다. 이전 설치 버전은 보존을 대조한 원 레코드에만 허용하며 새 주차장에는 이전 해시를 허용하지 않는다. 기존 행정구 관측 결속은 원 후보/강우 자료를 그대로 사용한다.

`prepare_native_site_labels.py`는 지원 원 후보 1,021,578개를 건물명·도로명·원 주소 속성과 결속한다. 건물명+옥상, 도로명+도로, 보도/지상 종류와 구별 번호를 사용한다. 명칭 991,254개와 주소 986,594개를 결속하고 옥상 주소는 원 도로명과 건물번호가 확인된 경우에만 제공한다. 지상은 30m 이내 원 도로명으로 구역을 설명할 수 있지만 이를 건물 주소로 바꾸지 않는다. 주차장 추가 후보는 원 명칭과 구별 번호를 자체 보관한다.

계산용 `geometry`는 절대 EPSG:5186 원 좌표의 Polygon/MultiPolygon이다. `waterleague_sim.spatial.geometry`는 열린 링·잘못된 구멍·자기교차·중복 면·비유한/3차원 좌표를 거부하고 면적·상한·유출 폭/장축 입력을 검사한다. 표시 도형이나 외곽선만으로 구멍 면적을 다시 더하지 않는다. 장축 기반 폭은 기존 탐색 설계의 집약 매개변수이며 실제 유출 방향·다중 면 사이의 배수 연결을 뜻하지 않는다. 관망/집수 경로는 별도 검증 대상이다.

SWMM 연속 입력은 전체 `geometry`가 있으면 `geometryCrs=EPSG:5186`과 같은 도형에서 계산한 면적·폭만 받는다. 원형 검사 코드 해시를 엔진 식별에 결속하고 결과/초기화 민감도 재현 묶음에도 코드를 보존한다. 과거 수치 재현의 단일 `coordinates` 입력은 원 생성기와 구분해 유지한다. 이 단계의 두 사례 대조와 현재 일반 게임의 원형 공간 연결·공개 운영 유역 등록을 구분한다.

```sh
simulation/.venv/bin/python scripts/prepare_topography_sites.py
simulation/.venv/bin/python scripts/verify_topography_sites.py \
  --output data/private/vworld-seoul-topography-20260307/sites-verification-v1.json
simulation/.venv/bin/python scripts/verify_topography_site_engine.py \
  --output data/private/vworld-seoul-topography-20260307/sites-engine-v1
```

마지막 명령은 구멍/다중 면을 가진 실제 옥상·도로 설계 영역 두 곳에 보관 AWS 421 관측과 기존 탐색 수문 조건을 적용한 엔진 연결 대조다. 해당 위치의 현장 강우·물성·경사 대조가 아니며 점수/순위·공개 연결 유역 모델로 등록하지 않는다. 현재 홈 하단 데이터 영역은 아래 서비스 전환에서 실제 사용하는 서울 원형 자료·공통 참조 조건을 안내한다.

### 원형 후보의 시설·공통 문헌 조건 결속

`prepare_native_play_catalog.py`는 위 설계 영역과 원 객체 속성을 읽어 원형·면적·공개 행정코드·허용 시설·제원 v4·참고 단가 v5·개인 예산 정책을 하나의 불변 SQLite로 결속한다. 구별 경계로 자르거나 OSM 식별자로 치환하지 않는다. 생성 결과는 [시설 조건 검사 요약](../data/manifests/seoul-native-play-v1.json)에 연결하며 일반 게임의 지도/API/워커 전환과 구분한다.

- 정상 건물 옥상은 녹화지붕, 도로면·보도는 투수포장의 독립 표면 비교 조건을 가진다. 경지계의 밭은 건조 경작지, 과수원·목초지는 초지 참조 조건으로 빗물정원·생물저류를 연결한다. 논·조림지·미해석 분류는 형상을 보존하되 `UNSUPPORTED_SURFACE_PROCESS`와 빈 허용 목록을 반환한다. 경지계를 포장면으로 채우지 않는다.
- [공통 참조 조건](../backend/src/main/resources/facilities/reference-surfaces-v1.json)의 출처는 EPA SWMM User's Manual 5.2의 표 A.2·A.5·A.6과 초기 수분 설명이다. 공통 Loam의 투수계수 0.13in/h→3.302mm/h, 흡입수두 3.5in→88.9mm, 공극률 0.463·포장용수량 0.232·시들음점 0.116을 보존한다. Green–Ampt 초기 부족률 0.231은 공극률−포장용수량의 설계 시드이며 측정 수분이 아니다. LID의 시들음점·빈 저류층 시드와 구분하고 실제 사건 평가는 기존 선행 관측 초기화 계약을 따른다.
- 평활 콘크리트 조도 0.012와 불투수율 100%는 옥상/포장면의 공통 비교 조건이며 재료 관측이 아니다. 투수 참조의 조도는 밭 0.06·초지 0.15, 저류 깊이는 불투수 1.27mm·투수 2.54mm의 문헌 범위 하한 설계값이다. 경사 1%도 공통 설계 조건이다. 현장 토성·경사·포장재는 각각 `UNRESOLVED`, 시공 적합성은 UNKNOWN으로 유지한다. 기존 WFS 토성이나 지역 DEM을 새 원형의 실측값으로 재명명하지 않는다.
- 식생수로 폭 2m·침투도랑 폭 1m는 가장 큰 실제 연결 면 안에서만 길이를 탐색한다. 동일 면적이면 원 WKB 순서로 선택하며 구멍·분리된 면을 가로지르지 않는다. 담기지 않는 시설은 허용 목록에서 제외한다. 전체 도형의 면적/장축은 집약 유출 폭일 뿐 분리된 면 사이의 배수 연결이 아니다.
- `NativePlayCatalog`는 전체 파일 해시·버전·공통 조건을 확인한 읽기 전용 조회를 제공한다. 시야는 실제 도형으로 교차 판정하고 결과 한도 초과 시 일부를 정상 반환하지 않는다. 같은 후보를 설치 면적·시설 종류·구 소속·고정 단가 검증과 SWMM 입력에 사용한다. 원자료/정책/코드 변경·기존 출력 덮어쓰기를 거부하며 현장 예측·순위 등록은 별도다.

```sh
simulation/.venv/bin/python scripts/prepare_native_play_catalog.py
simulation/.venv/bin/python scripts/verify_native_play_catalog.py \
  --output data/private/vworld-seoul-topography-20260307/play-verification-v1.json \
  --engine-output data/private/vworld-seoul-topography-20260307/play-engine-v1
```

공개 실행 묶음은 `package_native_play.py`가 같은 DB를 32MiB 이하 원문 조각의 gzip으로 보존한다. [묶음 매니페스트](../backend/src/main/resources/native-play/v1/manifest.json)의 해시는 API와 워커 코드에 고정한다. 조각·전체 해시 확인 뒤 읽기 전용 DB로 원자 복원하고 같은 자료를 Java 공간 조회와 Python 시설 계산에서 사용한다. `GET /spatial/play`와 범위/ID 조회는 [API 계약](06-api.md)을 따른다. [런타임 대조](../data/benchmarks/native-play-runtime-v1.json)는 25개 구의 전체 후보 JSON 비교와 공개 묶음의 6종 실제 EPA 연결 증거다. 일반 게임의 지도·설치·제출 전환 완료로 표시하지 않는다.

```sh
simulation/.venv/bin/python scripts/package_native_play.py
# Java의 공개 자료 시험이 기록한 조회 결과와 워커를 대조한다.
PYTHONPATH=simulation simulation/.venv/bin/python scripts/verify_native_play_runtime.py \
  --report tmp/native-play-runtime.json --engine-output tmp/native-play-engine
```

### 원형 공간과 독립된 관측 창 결속

`prepare_native_game.py`는 공개 자치구 경계의 5자리 코드·대표점과 원형 후보 DB 해시를 [관측 결속 목록](../backend/src/main/resources/native-game/v2/catalog.json)에 연결한다. 25개 구마다 2024-07-18 기본 창과 2022-08-08·2011-07-27·2010-09-21 재해 창을 따로 생성하며, 관측 결속 원문에 셀·OSM 형상/식별자·토양 가정을 넣지 않는다. 공간 후보 선택과 관측 입력을 같은 구 코드·공간 해시로 연결하는 준비 경로이며 일반 게임 전환과 구분한다.

선정은 각 창의 보관·검사 통과 지점 안에서 대표점까지 WGS84 지오데식 거리가 가장 가까운 10km 이내 지점이다. v2는 플랫폼별 마지막 부동소수점 차이를 제거하기 위해 거리를 정수 mm로 고정한 뒤 10km 한계·관측소 ID 동점 순서를 적용한다. 이는 계산 정밀도이며 관측소/대표점의 위치 정확도가 아니다. v1 목록·관측 원문·생성기 원문은 보존한다. 재해는 같은 관측소의 7일 선행 강우와 증발산이 확보된 지점만 사용한다. 기본 창 20개, 2010년 13개, 2011년 16개, 2022년 20개 지점의 집합을 원문에 남긴다. 모든 AWS 중 최근접 또는 구 전체/개별 시설의 현장 대표성으로 표시하지 않는다. 2026 형상에 과거 관측을 적용하며 사건 당시 자산·침수 상황을 복원하지 않는다.

원 강우를 다시 정규화해 깊이·총량·시각·관측소를 대조하고 관측소 좌표의 원문/시점 메타자료·파일 해시를 보존한다. 75개 재해 결속은 사건 증발산과 10,080분 선행 강우·증발산의 원문·시간 연결을 검사한다. 기존 계산 시계열은 바꾸지 않고 새 결속 목록에서만 관측 해시를 연결한다. 코드·PROJ 버전·1,790개 입력 파일 해시·별도 Java/Python 조회 해시와 대조 결과는 [관측 런타임 기록](../data/benchmarks/native-game-runtime-v2.json)에 연결한다.

```sh
PYTHONPATH=simulation simulation/.venv/bin/python scripts/prepare_native_game.py
# Java 시험의 100개 관측 원문과 워커 조회를 대조한다.
PYTHONPATH=simulation simulation/.venv/bin/python scripts/verify_native_game.py \
  --report tmp/native-game-runtime.json
```

### 현재 서비스의 원형 공간 연결

2026-10-20 일반 지도·주간/재해 설치 API·워커를 위 원형 공간으로 연결했다. 앞선 생성 요약의 `serviceMigrated:false`와 당시 검증 기록은 보존하며 현재 연결 증거로 덮어쓰지 않는다. 현재 결속은 다음 파일·검사로 구분한다.

- 지도는 `frontend/public/data/seoul-native-v1/`의 686개 gzip 타일·건물 1,014,532개·기타 객체 1,018,444개다. 원 객체의 구멍·다중 면·정점·소속·면적/길이·미확인 높이 상태를 보존한다. 원문 합계 1,446,417,404바이트·압축 합계 328,127,905바이트이며 최초 화면에서 전부 읽지 않는다. [전체 화면 입력 대조](../data/benchmarks/native-scene-frontend-v1.json)는 실제 Zod/mapper와 686개 원문·압축 해시, 전체 원 객체 형상, 지원 후보 1,021,578개의 대응 ID/허용 마스크, 옥상 후보 712,879개의 계산 형상을 검사했다. 지상 308,699개는 원면에서 제외 영역을 뺀 파생 도형이므로 배경 원면과 같은 면적이라고 검사하지 않는다. 지상 계산 형상은 원형 후보 DB와 API/워커 대조를 따른다.
- 주간·재해의 설치 `siteModelHash`는 `4ec7535e7cbaf41dc73f73519d77ba11f956f4c75c1a574fffa08f16625919b7`, 관측 목록은 v2 `f08b92fa00db08126e86b379583299a831764b958a4f131de4647ebde95e6fdb`다. 화면은 상대 미터 좌표, 조회·계산의 원형은 절대 EPSG:5186으로 구분한다. 이전 셀 ID·OSM 모델은 현재 워커의 대체 입력으로 사용하지 않는다.
- 재해의 선행/사건 기상은 `native-weather/v1`의 공개 원문 1,790개와 고정 계산 코드 10개를 해시 검사한 묶음에서 읽는다. [실제 API·워커 보관 증거](../data/benchmarks/native-primary-runtime-v1.json)는 6종 시설의 서버 원가·7일 초기화·설치 시각 이후 프레임·원 체적 차이·음수 효과·게스트 최종 결과 잠금·타 세션 404를 검증한다. [현재 Java/Python 대조](../data/benchmarks/native-play-runtime-v2.json)는 별도 25개 구 후보 1,787개 전체 JSON과 6종 실제 EPA 직접 강우 체적 대조다.
- 공개 시설은 EPSG:5186 근거를 확인한 위치점 9종을 새 카탈로그에 결속한다. 1,604개 표시 위치점과 후보 점 포함 대응 1,104개는 참고 정보이며 확인된 시설 부지·설치 제외는 0개다. 기존 OSM 저류/펌프 도형은 보관 근거로 남기고 현재 공간에 혼합하지 않는다. 원 설비 이력과 위치점의 출처 해시는 보존한다.
- 높낮이 배경은 [Copernicus 파생](../data/manifests/seoul-terrain-native-v1.json)의 90m 평균 DSM 격자와 원 수치지형도 수면, 인구는 [공개 구 코드 파생](../data/manifests/city-population-native-v1.json)을 사용한다. 지형·인구 생성은 공개 원문 해시·도구 버전·결측을 보존하며 OSM 경계/녹지/주차장으로 복귀하지 않는다. 도로 폭 단위·미확인 일방 방향·실제 보행망 연결·주차 칸·교량 실측 고도를 생성하지 않는다. 아래의 원 면 내부 보행 선·정차 차량·교량 높이 표시 가정과 구분하며 차량 이동은 명시적 양방향 도로중심선 범위에 한정한다.
- 현재 연구 API·워커의 `models/current/catalog.json`은 기존 수치지형도 연구 모델 4개만 등록한다. 일반 게임 원형 후보를 과거 OSM 연구 모델로 변환하지 않는다. 보관 모델·원 생성기·수치 재현 증거는 현재 서비스 목록과 분리해 유지한다. V30의 소속 구·종료/예산·설계 버전 분리는 [데이터 모델](05-data-model.md)을 따른다.

### 121종 지형지물 표시와 이동 복원

`prepare_native_features.py`는 원 공간 카탈로그의 121종을 모두 2D/3D 표시 경로에 결속한다. 기존 원형/교통 표시 6종과 공통 지형지물 표시 115종으로 구분하되 화면 적용을 생략하지 않는다. 추가 738개 타일은 점 1,333,705·선 2,381,740·면 701,820개의 표시 레코드이며 분할 전 원본 레코드 수와 다르다. [원본·표시 결속](../data/manifests/seoul-native-features-v1.json)은 카탈로그/코드/표시 해시와 모든 레이어의 원 축척·표시 경로를 보존한다. 자전거·보행 도로 `N1L_A0033330`은 오래된 설명서의 미등재 상태를 바꾸지 않고 실제 DBF의 자전거보행자/자전거자동차 겸용·자전거전용 구분을 근거로 표시한다.

추가 지물의 타일 경계 분할은 표시 전용이다. 원본 공간 DB·계산 후보·설치 면적은 변경하지 않는다. 행정·도곽·하천 경계와 등고선은 지표 기준선으로 유지한다. 가로수·조명·전력/통신주·신호등·소화전·정류장·우체통·공중전화·놀이시설 등은 공개 위치의 종류별 3D 모형으로, 담장·옹벽·분리대·방지책·철도·계단·보도 턱·저장조 등은 원 선/면에 결속한 입체 형상으로 표시한다. 지명은 원본 명칭을 사용한다. 실측되지 않은 높이·단면·형태는 표시 가정이며 시설 제원이나 수문 계산 입력으로 사용하지 않는다. 1:5,000 레이어도 원래 축척으로 표시하며 1:1,000 후보 미피복을 설치 후보로 채우지 않는다. 원 도형이 해석되지 않은 레코드는 좌표를 만들어 채우지 않고 원 상태를 보존한다. 유효한 경계가 있는 잘못된 도형은 경계 표시만 사용하며 자동 보정하지 않는다.

조명·가로등은 원본 점에서만 만들며 도로를 따라 45m마다 생성하던 기둥·등기구·조명 영역을 제거했다. 야간 발광은 원본 위치의 등기구 부분에만 적용한다. 도로·보도·터널·철도·경지 면은 건물 상세 타일 예산과 독립적인 공통 지형지물 타일로 옮겨 중복 표시를 제거한다. 지표 종류별 표시 높이와 접속부 깊이 오프셋을 구분하고, 새 건물/이동 타일의 첫 묶음이 도착해도 시야에 필요한 기존 타일을 유지한다.

`prepare_native_candidate_display.py`는 게임 후보 DB 해시를 고정하고 지원 지상 후보 309,831개를 666개 타일로 분할한다. 모든 표시 조각을 원 후보의 면·자치구·허용 시설과 대조하며, 원 후보 ID로 서버 상세 조회·설치를 이어간다. 색상은 도로·보도 위 0.18m의 표시 오프셋을 사용하고 깊이 검사는 유지한다. 기존 1,800m 거리·2,000건 응답 제한에 따른 전체 누락을 제거했으며 시설 선택·설치 점유·소속 구의 색상 규칙은 유지한다. 이 표시 타일은 원 설치 형상·면적·물리 입력을 변경하지 않는다.

`prepare_native_street_life.py`는 원 보도·횡단보도에서 경계 0.4m 안쪽의 표시 선 106,962개, 횡단보도 원면 45,652개와 내부 줄무늬, 주차장 원면 1,180개를 연결한다. 정차 차량의 보수적 외곽 33,613개는 주차장 내부에서 건물·교량/터널·철도·수면을 제외한 표시 위치이며 실측 주차 칸·용량·점유가 아니다. 실제 주차 칸은 그리지 않는다. 주차장 자료 유무와 차량 이동 생성을 분리하고 보행 선만 사람 경로로 사용한다. 이동체는 표시 모형이며 실시간 위치나 관측 교통량이 아니다.

`prepare_native_bridges.py`는 교량·육교·입체교차 원형 4,616개를 3,420개 구조로 결속한다. 원 명칭·종류가 호환되는 접합만 합치며 같은 이름의 도로교/고가차도 중복 외곽은 합집합으로 그린다. 원 도로/철도 끝점 연결을 따라 도로 접속 1,402개·철도 접속 287개·계단 접속 72개를 보존하며, 교량 내부를 따라 1km 이상 이어지는 경로를 100m에서 자르지 않는다. 하부 교차만으로 고가 경로를 만들지 않는다. 원 보도 교차면 2,557개·보행 경로 2,554개는 상판 높이에 결속한다. 육교 268개 구조는 원 외곽·계단·난간·하부 지지를 표시하고, 별도 계단 면이 없는 경우 자기 원형 안의 양 끝에 표시 계단을 둔다.

한강 교량은 [서울시 한강 교량 자료](https://hangang.seoul.go.kr/files/2013/12/korean.pdf)의 구조 종류와 [월드컵대교](https://mediahub.seoul.go.kr/archives/2002596)·[올림픽대교](https://mediahub.seoul.go.kr/news/article/newsArticlePrintPopup.do?articleNo=2002038)의 공개 주탑/케이블 제원을 참조한다. 아치·트러스·사장교를 원 교량 경로에 결속하고 원 도로의 차로 수로 상판 차선을 그린다. 반포/잠수교와 청담의 상하층을 분리한다. 표시 높이 여유 6.5m·상층 추가 7m·상판 두께 0.65m, 부재 단면·색상·구조 위치 보간은 표시 가정이며 실측 3D 복원이 아니다. 보행로·차량·교량·접속부는 같은 높이 함수를 사용한다. 가까운 1,400m 구간에는 난간/차선/교각 상세를, 먼 구간에는 상판과 주요 구조를 유지한다. 표시 형상은 설치 판정·지반고·피해 점수에 사용하지 않는다.

도로 중심선만 있는 구간도 지형을 따르는 면으로 표시한다. 원 도로면은 그대로 유지하며 중심선의 표시 폭 2.8m, 자전거/보행선 1.8m를 실제 도로 폭이나 설치 가능 폭으로 사용하지 않는다. 지형을 불투명하게 표시하고 건물 바닥은 외곽의 표시 지형 최고점에 맞춰 산과 경사면 건물이 지형에 가려지는 문제를 줄인다. 축소 건물은 가까운 순서로 상세를 선택하며 선택 밖의 배경 건물을 유지한다.

`package_native_overview.py`는 같은 원 건물에서 100m 격자 43,401개·25m 격자 381,499개의 대표 경계 상자를 만든다. 이전 전체 보기의 큰 건물 200개만 표시하던 빈 영역을 보완하며 선택·면적·물리 계산에는 사용하지 않는다. 확대 원형은 최대 16타일·건물 28,000개·기타 48,000개·64MiB 범위에서 가까운 묶음을 먼저 표시하고 배경을 유지한다. 121종 공통 표시 경로는 시야 타일을 건수 상한으로 자르지 않고 가까운 타일부터 처리한다. 해독·삼각분할·지형 결합은 지속 작업 스레드, CPU 버퍼는 96MiB, 원문 기기 캐시는 별도 96MiB 상한으로 재사용한다. 점 모형은 종류·100m 공간 구획별 인스턴스를 재사용하고, 거리별 200m/500m 묶음과 단순 입체 모형을 사용한다. 시야 밖 묶음은 그리지 않으며 임의 객체 수 제한으로 원 지물을 제거하지 않는다. 2D는 3D 메시를 생성하지 않는다.

`prepare_native_bridge_levels.py`는 기존 `prepare_native_bridges.py` 결과에 결속과 하층 표시 모형을 추가한다. 입력 교량/원 공간 DB 해시를 확인하고 새로운 출력 폴더에만 기록한다. 입력 교량 인덱스 SHA-256, 생성 코드 SHA-256, 외부 출처, 표시 가정은 `seoul-bridges-v1/index.json`의 `levelSupplement`에 보존한다. 제품 로더는 새 인덱스·본문 해시와 DTO를 검증하고, 공통 지형지물 워커는 결속 자료를 한 번 읽어 재사용한다. 2D는 이 복층 메시를 생성하지 않는다.

### 서울 등고선·표고점의 높이 기준 검사

`audit_native_elevation.py`는 해시 고정 원 공간 DB를 읽기 전용으로 조회하여 등고선·표고점 144,509기록의 원 수치·분포·SHP 종류와 PRJ를 대조한다. [검사 기록](../data/manifests/seoul-topography-elevation-v1.json)에 소스/코드 해시·도엽별 건수·EPSG:5186 5km 격자의 도형 bbox 중심 분포·도구 버전을 보존한다. 격자 집계는 수문 유역·면적 계산이 아니다.

1:1,000 등고선은 137,108기록·2,453개 비어 있지 않은 도엽, 표고점은 7,384기록·2,468개 도엽이다. 등고 원 수치는 −5.0000~835.0000, 표고점은 −7.7170~836.3300이며 음수·0을 임의 결측/정상 고도로 치환하지 않는다. 1:5,000 등고선 13·표고점 4기록은 별도 집계한다. 원 레코드 수를 고유 지형 지점 수로 표시하지 않는다.

PRJ는 2축 EPSG:5186·수평 m를 확인하지만 높이 속성의 단위·수직 기준은 확인되지 않았다. 수평 좌표 단위를 높이 속성의 단위로 전용하지 않으며 EGM2008의 Copernicus DSM과 기준고를 자동 결합하지 않는다. 이 검사로 보간 지형·현장 경사·수문 지형을 생성하지 않는다. 현재 화면의 별도 90m DSM은 건물/수목을 포함한 표시 배경이며 도로 턱·배수구·미세 경사·수심 계산의 근거가 아니다.

```sh
simulation/.venv/bin/python scripts/audit_native_elevation.py --report tmp/native-elevation-audit.json
```

## DEM 적용 제한

현재 파일은 90m 격자이며 실험 구역은 약 0.3km 블록. 영역과 교차하는 원본 셀 수·유효 값·범위 및 두 연도 동일 격자에서 값 차이 확인. 유효 표고가 있어도 수직 기준과 취득/제작 이력 확인 전 정확한 현장 높이·도로 경사로 승인하지 않음. 두 파일의 차이를 실제 지형 변화로 단정하지 않음.

미세 배수 경사·우수받이·도로 턱·관망 연결·침수 깊이는 90m 자료로 복원할 수 없음. 보간한 조밀한 격자도 원자료 90m와 가정 표기 유지. 확보한 서울 25개 구 1:1,000 수치지형도의 등고선/표고점·건물·도로를 먼저 검사하고 공개 관망의 연결 적합성을 검토한다. 추가 공개자료가 꼭 필요한 항목만 [자료 현황](13-data-access.md)에 모으며 확보 자료를 재요청하지 않는다.

## 토지피복 적용 제한

원문 CRS에서 전체 유효성·중복·결측 검사 후 명시한 변환으로 실험 경계를 대조. 원도형을 자동 복구하지 않고 잘못된 도형의 위치/수·영향 범위 보고. 실험 경계와 교차하는 도형의 L3별 면적, 합/합집합/중복/미피복 면적을 별도로 계산. 단위는 투영 좌표의 m², bbox를 실제 배수 유역으로 간주하지 않음.

영상 날짜는 개별 필드·도엽 XML·XLSX의 범위를 구분. 전국 메타데이터의 0.25m 영상 해상도는 피복 경계의 측량 정확도나 DEM 해상도가 아님. 공업/상업/도로 등 토지 이용 분류를 불투수율 100%·침투율·설치 가능 면적의 실측값으로 변환하지 않음. 기존 OSM 건물/설치 후보와 충돌하면 출처/시기/분류 차이를 공개하고 추가 확인.

## 모델 편입 조건

원본 이용조건·출처 표시·파생물 재배포 범위, 공간/시간 정합과 사용 목적에 맞는 정밀도 확인 후 별도 모델 버전 생성. 모델·시설 가능 면적/토양/관망 등 연관 입력 변경과 기본안·민감도·수지·재현을 함께 검증. 원자료 확보만으로 보정/독립 사상 검증·현장 적용 가능 등급을 부여하지 않음. 기관 보고서와 화면은 공개자료·계산·가정·미확인을 구분.

## 첫 검사 결과

`scripts/audit_spatial_sources.py`로 등록 원본 hash·ZIP CRC/경로/중복/크기를 검증한 뒤 임시 디렉터리에서 읽기 전용 검사. GDAL 3.8.5, pyproj 3.8.0 및 실행 당시 PROJ/GEOS 버전 기록. 네트워크 좌표계 격자 자동 취득과 GDAL 원본 보조 파일 저장 비활성화. 원문 WKT 유지, 대상지 AreaOfInterest·항상 x/y·경계 변별 20분할 적용. 수평 변환 연산의 정확도를 측량 정확도로 표현하지 않음.

- DEM 두 연도 모두 79,380개 원본 격자 값. 실험 경계에 걸친 16개 셀은 유효하며 NoData 없음. 격자는 90m, 표고 단위 필드·수직 기준·취득일 미제공. 두 연도 투영 격자 수치는 같지만 원문 WKT와 모든 원본 값은 다름. 제작 차이를 지형 변화로 판정하지 않음.
- 토지피복 12,330개 중 원도형 4개에 자기교차 오류. 그중 도로 분류 2개의 envelope가 실험 구역과 겹쳐 검사 상태 `INCOMPLETE_INVALID_GEOMETRY`. 오류점 자체가 블록 안에 있다는 의미는 아님.
- 유효 도형만 교차 계산한 경우 173개·9개 세분류·약 52.73% 면적 포함. 제외한 잘못된 도로 도형 때문에 남은 비율을 실제 미피복/결측으로 해석할 수 없음. 원도형 자동 보정이나 불투수율 대입 없음.
- 교차한 유효 도형의 IMG_DATE 필드는 모두 `2023-12-31`. XML은 2023년 영상 기반 2024 현행화 표기. 실제 촬영일·2024 강우 당일 현장 상태는 별도 확인 대상.

해시·도구 버전·오류 수·승인 제한은 `data/manifests/seongsu-spatial-audit.json` 보존. 원본·각 셀 값·상세 CRS/변환·도형 식별/면적이 포함된 전체 보고서는 `data/private/seongsu-official-20261017/`에만 보존. 같은 실행 코드·입력으로 두 번 생성한 보고서의 byte 일치 확인. 기존 모델·기하·랭킹 입력 변경 없음.

## 자기교차 도형 진단 계약

원본 검사와 별도 명령으로 `make_valid`의 `linework`·`structure` 두 보정 후보를 비교. 원본 ZIP 검증 후 임시 디렉터리에서 계산하며 원본/기존 검사 보고서/모델은 덮어쓰지 않음. 원도형을 수정한 파생 데이터는 공개하지 않고 로컬 진단 보고서만 생성. [Shapely 공식 문서](https://shapely.readthedocs.io/en/stable/reference/shapely.make_valid.html)에 따라 전자는 선분과 꼭짓점 보존, 후자는 외곽/내부 링의 분류가 맞다는 가정에 기반. 두 방식의 일치도 현장 경계의 정확성 증명은 아님.

- 각 오류 도형의 원본 순번·속성 hash·원도형 WKB hash·오류 이유 기록. 후보의 WKB hash·유형·면적·꼭짓점 수와 비면적 선/점 성분을 별도 기록. 단순 `buffer(0)`·반올림·격자 스냅 없음.
- 면적 성분만으로 대상 구역 교차를 계산하되 선/점 성분의 수·길이는 버리지 않고 보고. 두 방식의 대상 구역 내 대칭차 면적과 각 분류별 합/합집합/중복·전체 빈 영역 비교. 오류 원도형의 수치 면적은 참고값이며 실측 기준으로 사용하지 않음.
- 원래 유효한 도형과 속성은 동일하게 보존. 보정 후 빈 도형·비면적 성분·방법 간 불일치·전체 중복/빈 영역은 검토 대상으로 유지. `modelEligible=false`, `calibrationEligible=false`, `DIAGNOSTIC_ONLY` 고정.
- 공개 보고는 원본/코드/로컬 결과 hash와 요약 수치만 포함. 기존 EXPLORATORY 모델과 랭킹은 불변. 최종 후보 채택은 이용조건·현장/영상 대조·좌표/시기 정합 검토 이후 별도 계약.

2026-10-17 [EGIS 저작권 정책](https://aid.mcee.go.kr/bbs/copyright.do) 확인. 정책은 자료별 공공누리 표시 확인과 출처 표시를 요구. 제공 XML에는 저작권자 `환경부`가 있으나 이 ZIP에 적용되는 공공누리 유형은 아직 확인되지 않음. 사이트 전체 정책을 개별 원본/파생 좌표의 무제한 재배포 허가로 취급하지 않음. 현재 GitHub에는 원자료/파생 좌표를 제외한 코드·검사 요약만 저장.

새 모델에서 시설 3종·관측 강우 4개 실제 SWMM 및 독립 재실행의 수치 일치. 신규/기존 모델을 실제 PostgreSQL API→워커→저장→ZIP→재계산하고 각 18개 파일 해시·물리 결과·계산 키 일치 확인. 캐시 사용 여부 REUSED/COMPUTED는 실행 이력으로 구분. 브라우저에서 두 저장본의 지도 출처·배치·서버 결과 복원, 같은 지도 내 강우 변경의 복사, 지도 변경의 배치 초기화, 20m² 허용/21m² 차단·2D 전환 확인. 시험 계정/전략/계산 제거와 기존 자료 수 보존.

DEM·토지피복·배수 연결·토양 보정 및 현장 예측 검증은 미완료. 서로 다른 공간 버전의 배치·결과는 혼합하지 않는다.

## 표고점·DEM 공간 지지 범위 진단

2025 수치지도 4개 도엽의 `N1P_F0020000` 표고점과 `N1L_F0010000` 등고선 목록, 2024/2025 DEM을 대조한다. 원본 hash/CRS·유효 2차원 도형/유한 속성·중복 ID를 검사한다. 표고점은 구역 밖을 포함한 전체 12개를 보존하고 값 차이가 큰 점을 임의 제외하지 않는다. 등고선의 전체 수·연구 경계 교차·최근접 거리를 기록하며 등고선 없이 표고점만의 Delaunay 삼각망 선형 보간을 별도 진단한다. 원본 점의 볼록껍질 밖 외삽은 금지한다.

원본 표고점 위치와 새 모델 13개 구역 중심에서 DEM의 해당 원본 격자 값을 읽는다. 90m 셀 중심의 값을 위치의 실측값으로 부르지 않는다. DEM과 표고점의 차이·삼각망 보간과 DEM의 차이는 해상도·시점·수직 기준이 통일되지 않은 자료 간 수치 차이다. 어느 자료를 정답으로 삼거나 RMSE를 현장 정확도 지표로 사용하지 않는다. DEM 단위/수직 기준 메타데이터 부족을 보존하며, 차이만으로 보정량·도로 경사·유출 경계를 결정하지 않는다.

전체 점·삼각망·좌표 변환·DEM 원본 셀 번호/값·구역별 진단은 로컬 비공개 보고서로 보존한다. 공개 요약에는 원본/도구/코드/상세 보고서 해시, 건수, 수치 차이 범위와 적용 제한만 포함한다. 공개 요약 파일은 수문 모델 입력과 구분한다. 자료 화면 연결은 서울 전역 맵 확장 우선순위 이후 진행한다. 이번 진단에서 모델·지도 지형·과거 기록·순위는 변경하지 않는다. 실제 공개 원본 반복 실행과 합성 평면의 보간·외삽/중복/비유한 입력 거부를 검증한다.

진단 구현 결과: 전체 표고점 12개 중 연구 경계 내부 1개, 등고선 전체 5개 중 경계 교차 0개, 최근접 등고선 약 267.37m. 원본 점의 볼록껍질은 현재 13개 후보 중심을 포함하나 지형 정확도 근거는 아님. `scripts/audit_terrain_support.py`의 실제 원본 반복 결과 일치, 합성 평면·격자·누락·형식·공개 요약 검사 7개 통과. 모델 반영과 자료 화면 연결은 미완료.


## DEM 삼각형별 토양·피복 면적 연결

`prepare_surface_coverage.py`는 원본 2025 DEM 288삼각형(1,166,400m²)에 보관 공개 심토토성 8,266개와 2024판 피복 12,330개 도형을 연결. CRS를 덮어쓰지 않고 PROJ의 비근사 변환을 사용하되 두 연산의 정확도 값 -1(미확인)·좌표 epoch 미확인을 보존. 원본 꼭짓점 변환 후 직선 연결이며 변환 정확도를 현장 측량 정확도로 표시하지 않음. [PROJ/pyproj 변환 정의](https://pyproj4.github.io/pyproj/stable/api/transformer.html), [Shapely 좌표 변환](https://shapely.readthedocs.io/en/stable/reference/shapely.transform.html), [공간 교차 인덱스](https://shapely.readthedocs.io/en/stable/strtree.html) 기준 적용.

미수정 원본의 내부 구멍·다중 도형 유지, 경계 접촉 면적 0 제외. 동일 분류라도 양의 면적 중첩은 중복 영역으로 제외하며 원본 순번/ID 보존. 오류 도형은 복구하지 않고 변환 후 envelope의 영향 가능 범위를 기록. 정상 도형이 그 범위를 덮더라도 독점 배정으로 확정하지 않음. 모든 작은 양의 면적을 원값으로 남기므로 수치 반올림 크기의 조각이 실제 필지의 존재를 뜻하지 않음. 미피복·중복·오류 영향 지표는 서로 겹칠 수 있으며 단순 합산 금지.

실제 결과: 토양 원본 유효 8,244개/오류 22개, 연구 창에 오류 영향 없음. 토양 정상 합집합 1,166,399.895518m², 미피복 0.104482m². 피복 원본 유효 12,326개/오류 4개, 정상 합집합 521,876.227649m². 오류 도형 envelope의 영향 가능 면적 971,055.047457m²를 보수적으로 제외한 피복/토양 공동 배정은 17,071.676395m². 이는 실제 피복 자료가 나머지 지역에 없다는 뜻이 아니며, 오류 도형 전체를 아직 채택하지 않은 판정 결과. 앞선 두 복구 후보의 일치 진단도 원본 검증 등급으로 자동 승격하지 않음.

상세 원본·좌표·변환·배정은 `data/runs/surface-coverage-20261018-v2/`에 보존, 공개 요약은 `data/benchmarks/surface-coverage-v1.json`. 실제 포장률·표면 다짐·수분 근거가 없으면 공간 교차 결과를 침투 입력으로 자동 전환하지 않음. 명시적 재료/토양 매개변수와 전체 공간 분류가 충족된 경우만 침투 v2로 변환. 미분류를 불투수로 채우거나 확인된 조각만 잘라 유역 계산하지 않음. 원본 이용조건 미확정 자료의 좌표·속성 전체는 GitHub에 배포하지 않음.


## 명시적 파생 도형과 도시생태 표면 구성

원본 감사와 분리한 탐색용 파생 정책 `EXPLICIT_TWO_METHOD_AREA_CONSENSUS_v1` 추가. 원본 투영 좌표에서 `linework`·`structure` 양쪽이 유효한 Polygon/MultiPolygon이고, 선/점 퇴화 성분이 없고, 면적 도형이 위상적으로 같은 경우에만 파생 도형 생성. 정점 순서 정규화 외 스냅/반올림/buffer 처리 없음. 불일치·퇴화는 오류 상태 유지. 원본과 파생 입력의 배정을 각각 보존하며 이 채택은 현장/영상 정확도 검증이나 운영 모델 승인과 구분. 원본·기존 결과/순위 불변.

불투수율의 직접 근거로 서울도시공간포털 자료실의 2025·2020·2010 도시생태현황도와 2025 최종보고서 추가 확보. 공개 첨부파일은 키·사용자 로그인 없이 수신 가능. 원본 ZIP/PDF와 메타자료를 프로젝트에 보관하고 파일별 URL·크기·SHA-256을 `data/manifests/seoul-biotope-20261018.json`에 기록. 2025 원본의 조사 블록은 42,544개이며 고유번호 중복 72건을 삭제/병합하지 않고 원문 순번으로 구분. 원본 값과 모순·범례 차이를 분리하고 전체 면적을 자동 정규화하지 않음.

`prepare_seoul_biotope.py`는 원본 WKT(EPSG:5174로 식별)에서 대상 DEM 원문 좌표계로 변환, 삼각형과 조사 블록의 교차 면적으로 건물·불투수포장·투수포장·녹지·나지의 면적을 배정. 변환 후 새로 발생한 도형 오류도 원본 오류와 함께 제외하고 임의 복구하지 않음. 원본 블록 내부 균질 배정은 명시적 근사이며 실제 포장 위치 분포와 다름. 숫자 불일치·겹침·미피복 면적을 미해결로 남기며 물리 입력 전체 완성을 주장하지 않음. 투수포장 제원·수면/습지·조사불가능지의 추가 물리 조건을 원지반 침투 후보와 구분. 2010/2020의 필드 이름이 같아도 2025 조사의 세부 방식·정확도·사건 당일 유효성을 소급 적용하지 않음.
