# CPU 탐색 기준안·강우별 결과

2026-10-17. 계약: [0008](decisions/0008-reference-comparison.md). 실제 EPA SWMM 5.2.4 계산 결과. 현장 미검증 EXPLORATORY.

## 고정 탐색·비교

공간 버전별로 독립 생성·보존한다. 아래 첫 표는 기존 OSM 모델이며 새 수치지형도 모델의 결과와 혼합하지 않는다.

성동 421의 2024-07-18 104mm 창에서만 후보 선택. 10m² 증분으로 추가 원당 평가체적 저감이 큰 배치를 채택하는 결정적 탐욕 탐색. 기존 셀 시설 유형 교체를 탐색하지 않으므로 전역 최적해 아님. 모든 예산의 배치를 확정한 뒤 6월 22일·7월 2일과 같은 날 서울 108에서 계산. 별도 강우 입력의 비교이며 독립 유출 관측 검증 아님.

| 예산 상한 | 배치 비용 | 배치 | 선택 단계 | 후보 요청 수 | 네 강우 점수 최저–최고 |
| --- | ---: | --- | ---: | ---: | --- |
| 30,000,000원 | 29,700,000원 | G1~G3 투수포장 각 50m², G4~G5 각 60m² | 27 | 356 | 3.35363075–3.61596917 |
| 100,000,000원 | 33,000,000원 | G1~G5 투수포장 각 60m² | 30 | 424 | 3.57760484–3.66994221 |
| 300,000,000원 | 33,000,000원 | G1~G5 투수포장 각 60m² | 30 | 424 | 3.57760484–3.66994221 |

실제 고유 후보 424개, 중복 캐시 포함 요청 1,204회. 같은 배치는 한 번 계산한 값을 재사용. 모든 비교의 물수지 오차 절대값 1% 이내. 최저/최고는 선택된 관측 창의 기술 통계로 신뢰구간 아님. 큰 예산에서 미사용액이 남았다는 사실은 현실에서 추가 투자 효과가 없다는 결론이 아니다.

평가체적 = 기간 유출 + 최종 잔여저류 − 초기저류. 점수는 기준안 대비 평가체적 감소율. 다른 강우에서 악화될 경우 음수 보존. 탐색 개선 문턱은 SWMM 보고서의 깊이 반올림·체적 차분 오차를 고려하며 원장에 값 기록.

## 수치지형도 2025 기준안

새 지도 `seongsu-ngii-2025-v2`의 성동 104mm 모델에서 동일 탐욕 탐색을 실행했다. 지상 구역은 각 25m²이며 모델의 설치 상한은 20m²다. 설치 비율은 설계 가정이다.

| 예산 상한 | 배치 비용 | 배치 | 선택 단계 | 후보 요청 수 | 네 강우 점수 최저–최고 |
| --- | ---: | --- | ---: | ---: | --- |
| 30,000,000원 | 11,000,000원 | G1~G5 투수포장 각 20m² | 10 | 144 | 1.27539991–1.28711156 |
| 100,000,000원 | 11,000,000원 | G1~G5 투수포장 각 20m² | 10 | 144 | 1.27539991–1.28711156 |
| 300,000,000원 | 11,000,000원 | G1~G5 투수포장 각 20m² | 10 | 144 | 1.27539991–1.28711156 |

고유 후보 144개·중복 캐시 포함 432회 요청. 세 예산 모두 수치 허용오차보다 큰 추가 개선이 없어 종료. 미사용 예산은 현재 알고리즘·설계 구역·시설 가정의 결과이며 실제 투자 효과의 상한이 아니다. 기존 OSM 기준안과 지도·면적·모델이 달라 점수를 직접 경쟁 비교하지 않는다.

## 사용·계보

- 기록 경쟁 → CPU 기준안: 세 예산의 선택 단계·면적·비용·강우별 점수·평가체적·종료 저류·수지 오차 표시
- 현재 선택한 호환 모델의 새 개인 설계로 배치 복사, 이후 별도 저장·계산·공개 제출
- 사람 순위나 회원 기록에 CPU 결과를 자동 삽입하지 않음
- `GET /api/v1/references?modelHash=…`: 해당 공간 버전의 보고서와 원문 해시. `/source`, `/ledger`도 같은 모델 인자로 다운로드. 생략 시 기본 모델, 미등록 모델은 404
- `data/derived/cpu-reference.json`, `cpu-search-ledger.json`: 기존 OSM 근거. `cpu-reference-ngii-v2.json`, `cpu-search-ledger-ngii-v2.json`: 새 지도 근거. `reference-catalog.json`으로 8개 모델 해시를 연결하며 서버 리소스 원문과 바이트 일치
- 보고서에 탐색 알고리즘·생성기·엔진 빌더·엔진 바이너리·입력 모델·후보 원장·각 결과/manifest의 해시 및 계산 환경 기록
- 전체 엔진 파일은 로컬 `data/private/references/<id>/` 보존. 재현에 필요한 모델·알고리즘·빌더는 저장소 포함, 원문 강우 수집 키 불필요

```bash
# 새 기준안 생성: 동일 소스 식별자 폴더가 존재하면 덮어쓰기 거부
simulation/.venv/bin/python scripts/build_references.py
# 수치지형도 기준안 별도 생성: 기존 원문·생성기는 보존
simulation/.venv/bin/python scripts/build_topography_references.py
# 기존 원장을 다시 탐색해 후보 선택·비용·해시 검증
simulation/.venv/bin/python scripts/verify_references.py
# 지도 2종 × 예산 3개 × 강우 4개의 기준안·배치안·민감도 재계산
simulation/.venv/bin/python scripts/verify_references.py --rerun
# 원장의 모든 고유 후보도 실제 SWMM으로 다시 계산
simulation/.venv/bin/python scripts/verify_references.py --rerun --rerun-candidates
```

## 확인한 동작

원장 424개 재생으로 세 예산의 모든 선택 단계와 중단 사유 일치. 실제 엔진으로 12개 비교의 수치·점수·민감도 일치. CI에서도 실행. 다른 플랫폼은 바이너리 해시 차이를 허용하지만 모델·빌더·알고리즘 계보와 수치 비교는 필수.

실제 브라우저에서 1억 원 상한 배치를 성동 55mm 개인 설계로 복사→저장→PostgreSQL 큐→워커 계산. 점수 3.64142094와 기준/배치 모든 보고 지표가 CPU 자료와 동일. 사람 순위 미제출. 데스크톱·390px 화면 배치와 전체 문서 가로 넘침 없음 확인.

새/기존 원장의 고유 후보 144/424개와 지도별 12개 최종 비교를 실제 SWMM으로 재계산해 수치 일치 확인. 서버에서 8개 모델별 보고서·원장 선택, 미등록 모델의 세 경로 404, 호환 모델의 배치·비용 검사 통과. 프런트 83개·타입/빌드/포맷 통과.

새 기준안을 브라우저에서 성동 55mm 설계로 복사→저장→실제 SWMM 실행. 점수 1.28347301·기준/전략 집계·민감도 전부 기준안과 일치. 다운로드 ZIP 21개 항목과 18개 manifest 해시 확인, 캐시 없는 재실행에서 전체 시계열·물리 결과·계산 키 일치. 이전 OSM 전환 시 후보 424개와 이전 모델의 다운로드 링크 복원 확인. 공개 순위 제출 없이 검증 계정·전략·계산·다운로드 사본 정리, 기존 완료 계산 13개·공개 제출 2개 보존.

일반 사용자의 저장 버전 다강우 비교는 [문서 14](14-rainfall-comparisons.md), 기관 재계산·통계는 [문서 26](26-institution-analysis.md) 참조. 현장 관측 검증과 모델 등급 승격은 별도 잔여 항목.
