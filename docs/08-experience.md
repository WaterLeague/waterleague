# 3D·UX 설계

## 현재 기본 화면 계약

서울 전체 공동 지도를 홈으로 사용. 소속 구 강조, 타 구 낮은 불투명도·경계·이름으로 구분하고 모두 확대·조회 가능. 구별 점수와 현재 공유 시설, 개인 기여 순위, 주 종료·우승 표시. 설치는 로그인한 회원의 소속 구에 있는 빈 후보 위치에서만 제공. 점유 충돌은 서버 응답으로 확정. 실시간 관측은 직접 조회하고 관측 시각·조회 지연·실패를 지도에 표시. 상세 규칙은 [제품 계약](01-product.md) 기준. 아래 구별 도전 진입은 이전 구현 이력이며 기본 홈을 대체하지 않음.

## 시각 방향

도전 선택 → 3D 플레이 → 결과 → 재도전의 전략 게임 흐름. 큰 목표 문구, 실제 관측 이벤트와 원화 예산, 시설 배치에 대한 즉시 피드백. 잉크색 도전 화면과 밝은 도시의 대비, 플레이 중 지도 중심 배치. 상세 계약은 [게임 흐름](30-gameplay-loop.md) 참조.

실제 footprint, 근거 있는 높이와 미확보 표시. PBR 재질·일관된 태양광·접지 그림자·외곽선·시설 단면으로 입체감. 사선 조감·탑뷰·셀 확대, 카메라 범위 제한. 시각화용 형상과 계산 입력 구분.

## 조작·설명

위치 선택 → 시설·면적 → 강우 비교의 3단계 온보딩. 쉬운 설명과 정확한 단위 병기, 기술 상세는 확장 패널. 실측·모델·가정은 색상과 텍스트로 구분.

[첫 플레이 안내](33-first-play-guidance.md)는 선택·미확정 편집·확정 배치·실제 계산 상태에 따라 갱신한다. 안내 접기/재열기와 기존 입력으로의 초점 이동 제공. 시설 역할을 쉬운 말로 설명하고 면적·예산·개수 제한의 구체적인 사유를 표시한다.

hover·선택·미리보기·면적·확정·삭제·undo/redo. 제한 이유 구체화, 서버 거부 시 입력 복구. 키보드 셀 목록·버튼·focus·label·오류 연결.

3D 구역 표식은 카메라 투영 후 화면 좌표에서 충돌을 피한다. 선택 구역·미확정 편집·확정 배치 순으로 표시 공간을 확보하고, 이동한 표식에는 실제 구역 중심을 가리키는 연결선과 기준점을 표시한다. 표식 이동은 화면 표현이며 원본 좌표·시설 면적·계산 입력을 변경하지 않는다. 화면 밖 구역을 가장자리에 모으지 않으며 공간이 부족하면 일부 표식만 숨기고 구역 목록·2D 선택을 유지한다. 시설 편집 중 중복 건물 이름 표식은 생략한다. 프레임별 React 상태 갱신·상시 렌더 없이 회전·확대·선택 시에만 위치를 갱신한다. 실제 두 지도·좁은 화면·회전·선택·미리보기·2D 전환과 정지 렌더를 검증한다.

시설 표면·도식 식재와 구역 경계 안의 면적 비율 표시, 미확정 배치와 확정 비용의 분리는 [시설 표현 계약](31-facility-presentation.md) 기준. 2D도 같은 표시 도형 사용. 시설 도식은 실제 시공 위치나 관측 식생이 아님.

계산 전에는 면적·예산만 표시. 근사 점수를 공식 성과로 표시 금지. 큐·실행·품질거부·실패 구분. 물결은 설명용, 검증된 2D 수리모델 없이 침수깊이 생성 금지. 임의 랭커·효과 수치 금지, 빈 상태 명확히 표시.

## 서울 전역 맵 확장

2026-10-17 사용자 우선순위 반영. 공개 OSM 대한민국 원본을 프로젝트에 보관하고 서울 행정경계·구별 경계·건물·도로·수면·녹지를 추출한다. 자료 취득 시각·원본/변환/타일 해시·ODbL 출처 보존. 브라우저는 저장된 자체 타일만 읽으며 공개 API를 매번 호출하지 않는다.

도시 전체 보기 → 구 선택/검색 → 확대·이동 → 지역 플레이로 연결. 먼 시점에서는 행정경계·주요 지형/교통을 보여주고 가까운 시점에서 주변 건물 타일을 불러온다. 한 번에 전국 건물 객체를 React에 올리지 않고 화면 주변 로딩·기하 병합·캐시 상한·요청 취소 적용. 건물 높이는 원문 태그/층수 환산/표현용 가정을 구분하며 지도 완전성이나 실측 높이를 보장하지 않는다. 기존 성수 저장 기록의 지도·모델 해시는 보존한다.

서울 전역 지도가 실제 수문 유역을 뜻하지 않는다. 지역별 계산 모델과 배치 후보를 연결하는 후속 구현까지 완료해야 해당 지역의 게임 계산을 제공한다. 계산 불가 지역은 UI에 상태를 표시하고 성수 계산 결과로 대체하지 않는다.

서울 전역 표시 v1: Geofabrik 2026-10-16 대한민국 PBF 원본 289,438,576 bytes를 프로젝트에 보관, 제공처 MD5 일치와 SHA-256 `5844138cdd171124886805c0c943bdab9bc009b8102478e9b6e720bafa82f87f` 고정. 서울 OSM 행정경계 relation/2297418에서 25개 구·건물 166,238개, 표시 타일 623개·총 46,052,949 bytes 생성. 도시 전체 요약은 약 1.94MB, 가까운 16개 타일·동시 요청 4개·캐시 24개 상한. 원본의 수치 높이 태그/층수 환산/높이 미확인 표시 가정 구분. 전체 보기에서 대표 건물 1,200개, 확대 시 주변 전체 건물 표시. 표시 지도와 별개로 아래 구별 대표 블록 계산을 연결하며 모든 필지·유역의 계산 완료는 아님.

수집 재현 순서: 등록 PBF → `ogr2ogr -f GPKG korea-base.gpkg south-korea-261016.osm.pbf multipolygons lines -oo TAGS_FORMAT=JSON --config OSM_MAX_TMPFILE_SIZE 512 -gt 65536` → GeoPackage의 두 레이어를 `-spat 126.7 37.4 127.3 37.75` GeoJSON 추출 → `scripts/prepare_seoul_city.py`. PBF를 읽을 때 좌표 bbox를 먼저 적용하지 않아 관계 도형 구성의 외부 노드를 보존. GDAL 조립의 닫히지 않은 링 경고 보존 필요, 이번 표시 데이터의 완전성 검증으로 취급하지 않음. 추출 bbox 안 유효하지 않은 건물 1,509개·녹지 14개·수면 3개 제외 집계이며 서울 내부만의 누락 건수는 아님. 원본 도형 복구·실측 정확성 승격 없음.

## 서울 구별 플레이 연결

서울 25개 구에서 각각 공개 경계가 있는 건물과 지상 주차장 일대의 대표 구역을 선정한다. 서울 전역의 모든 필지에서 계산 가능하다는 뜻은 아니다. OSM 건물·주차장 형상과 원문 태그를 보존하며, 지상 주차 또는 포장 태그가 있는 후보만 지상 배치에 사용한다. 지하·다층·옥상 주차장과 명시적 비포장 표면, 건물 중첩은 제외. 후보가 부족하면 가짜 구역을 추가하지 않고 해당 지역 상태를 표시한다.

구별 새 지도·배치 구역·모델 해시와 별도 계산/순위 적용. 동일 지역 안에서만 강우 변경 시 배치 복사. v1은 보관된 성동 관측소의 3개 관측 창을 공통 비교 강우로 재생하며 해당 구에서 측정한 강우로 표시하지 않는다. 지역 중심까지 관측소 거리를 다시 계산하고 현재 좌표/과거 위치 이력 미확인 조건 유지. 지면·유출 경사·토양·설치 적합성·유입 동선 가정은 기존 탐색 계산의 한계로 명시한다.

서울 지도에서 구 선택→대표 구역 확인→지역 도전 선택→시설 배치→저장/서버 SWMM 계산/결과/리그 연결. 기존 성수 기록·자료 바이트 보존. 검사는 새 자료의 연결·좌표/면적·구역 중첩과 실제 엔진 실행, 신규 지역의 실제 저장/계산 및 화면 전환 중심으로 수행한다.

서울 지도 첫 화면에 25개 구 대표 블록의 플레이 가능 상태를 표시한다. 구 선택 시 실제 대표 블록 중심으로 이동하고 해당 구 이름의 도전 버튼을 제공한다. 전체 보기의 구 표식과 확대 시 지역별 직접 진입 표식을 구분하며, 성수만 플레이 가능한 것처럼 단독 표식으로 표시하지 않는다. 2D도 지역별 위치·키보드 선택을 제공한다. 선택 전 성수 도전은 빠른 시작으로 안내한다.

구별 플레이 v1 구현: 25개 구 각각 8개 옥상과 5개 25m² 지상 격자, 구별 3개 강우로 75개 모델 등록. 기존 8개와 기본 모델 해시 유지. `seoul-play-v1.json` 목록과 구별 지도·서버 모델 원문 해시 고정. 전역 탐색에서 구별 도전으로 이동, 지역 변경 시 새 배치, 같은 지역의 강우 변경 시 배치 복사. 기존 API의 지역 모델별 저장·계산·순위·리그 규칙 사용.

확인: 25개 구 실제 SWMM 실행과 공간·강우 연결 검사 통과. 강남구 실제 회원 저장/계산/재현 묶음 18개 해시 일치, 다른 구를 동일 설계 버전으로 저장하는 요청 거부 확인. 브라우저의 강남→강북 전환·배치·원화 예산 확인. 검사 회원과 계산만 정리했으며 공개 순위 제출 및 기존 기록 변경 없음.


구별 플레이 v2: 24개 구에 인근 AWS 관측 강우 69개 모델 추가, 기존 83개 모델 보존. `seoul-play-v2.json`의 기본 도전은 인근 관측의 최근 확보 창으로 연결한다. 선택 화면에서 인근/공통 구분·관측소·거리를 표시하며 같은 구역의 배치는 그대로 복사한다. 강서구는 인근 분자료 결측으로 공통 강우 3개를 유지한다. 실제 자료·제외 사유는 [서울 강우 관측](15-seoul-observations.md) 참조. 총 27개 지도·152개 모델, 새로운 강우를 현장 검증이나 공식 순위 조건으로 승격하지 않음.


## 대표 블록 주변 환경 표시

보관된 동일 OSM 원본에서 도로·보행로·지상 철도 중심선과 녹지·수면 경계를 추출한다. 각 대표 블록의 EPSG:5186 원점과 1 km 범위로 변환·절단하며 다중 도형과 내부 구멍을 유지한다. 원본 ID·태그 분류·출처·변환 코드·기반 지도 SHA-256 보존. 기존 계산 모델과 지도 원문을 바꾸지 않고 `modelInput=false`인 별도 표시 자료로 연결한다.

[OSM width](https://wiki.openstreetmap.org/wiki/Key:width)의 양수 미터 값만 폭 태그로 사용하고 범위·피트·비수치 값은 해석하지 않는다. 폭이 없으면 도로 분류별 고정 표시 폭을 사용하며 실측이나 수문 불투수면 입력으로 전환하지 않는다. [tunnel](https://wiki.openstreetmap.org/wiki/Key:tunnel)·covered·underground·음수 layer는 지상 표시에서 제외한다. [bridge](https://wiki.openstreetmap.org/wiki/Key:bridge) 표식은 보존하되 실제 높이를 만들지 않고 평면 투영으로 표시한다. 공원 경계는 실측 식생 분포를 뜻하지 않는다.

선택한 지도 주변 자료만 지연 로딩하고 해시·지도 ID·원점·범위를 검사한다. 3D·2D가 같은 주변 도형을 사용하며 표시 켜기/끄기를 제공한다. 주변 자료 로딩 실패는 기존 배치·계산을 막지 않고 재시도를 제공한다. 큰 면 도형은 종류별 병합으로 그리기 요청을 제한한다. 검사는 원본 계보·구멍/좌표·지하 도로 제외, 현재 게임의 배치·강우·모델 해시 보존과 두 표시 방식 중심으로 수행한다.

주변 표시 v1: 25개 지역에 도로·보행로 9,013개, 녹지 775개, 수면 33개, 지상 철도 185개 연결. 지역별 절단 도형 합계이며 지역 간 중복 원본을 포함한다. 자료 총 10,794,943 bytes, 선택 지역만 로딩·성공 캐시 10개 상한. 선형 9,198개 중 수치 폭 태그 143개, 표시 폭 가정 9,055개. 기존 152개 계산 모델·기반 지도 원문 보존. 원본 계보·좌표/구멍·폭·지하 제외와 브라우저의 강동구 진입, 3D/2D 전환·주변 표시 토글·서울 2D 키보드 지역 선택 확인.

지도 버전 선택 UI 미제공. 새 플레이에는 확보·검사된 최신 공간자료를 자동 적용. 현재 성수 연구 모드는 수치지형도 2025 v2, 서울 공동 지도는 구 전역 OSM 2026-10-16 추출본과 확장 후보 사용. 저장 기록·기존 공개 리그의 계산 입력은 재현용 원래 버전 유지. 지도 출처·기준일은 자료 설명으로 제공하며 사용자의 버전 선택 단계 없음.
