# 서울 강우 관측 교차 점검

범위: 2024년 서울시/KMA 강우 교차 점검과 이후 실시간 조회 계약. 대표 블록의 24개 구 연구 표본은 현재 재해 3사건의 25개 구 지원과 다른 자료 묶음이다. 현재 25개 구 피복 검사는 [검증 기록](12-validation-log.md)의 2026-10-20 결과를 참조한다.

2026-10-16. 기상청 421 분 관측과 서울시 성동구청·뚝섬펌프장 원자료의 시공간 차이 확인. 기존 모델·순위·CPU 기준안 입력은 변경하지 않음.

## 원본·시간 계약

- 서울특별시 치수안전과 [과거 강우 ZIP](https://data.seoul.go.kr/dataList/OA-22715/F/1/datasetView.do)의 2021~2024 파일과 [위치 XLSX](https://data.seoul.go.kr/dataList/OA-22824/F/1/datasetView.do)의 2026-09-15 자료 사용. 공공누리 1유형 출처 표시, 원본 SHA-256·다운로드 요청·취득 시각 보존
- ZIP 내부 CP949 CSV의 관측소명·시간·10분우량 보존. 2024년 성동구청과 뚝섬펌프장 파일만 선택, 전체 압축 해제 금지
- [공식 시각 안내](https://data.seoul.go.kr/bsp/wgs/dataView/data300View/1115.do): 13:09 표시는 13:00:00~13:09:59 누적량. KST의 `[13:00, 13:10)` 구간으로 정규화
- 선택 날짜 2024-06-22·07-02·07-18의 00:00~다음 날 00:00, 144구간 검사. 관측소 불일치·비수치·음수·비유한 값·중복·누락·불규칙 시각 거부. 결측을 0으로 채우거나 10분 값을 분 관측으로 분배하지 않음
- 연간 파일의 총 행·중복·불규칙 시각·누락 구간을 별도 보고. 선택 날짜 통과를 연간 자료 전체 품질 인증으로 해석하지 않음
- KMA 분 자료는 온전히 관측된 10분 구간만 합산. 앞뒤 부분 구간의 제외 시간·깊이 명시, 동일 시작·종료 구간끼리만 총량 비교

## 공간·과학적 해석

위치 XLSX의 코드 901 성동구청, 902 뚝섬P와 CSV 관측소명을 명시적으로 연결. WGS84 구역 중심까지 지오데식 거리 계산. 현재 위치와 과거 관측소명의 연결만 확인되므로 2024년 이전 이력은 `UNVERIFIED`. 거리만으로 관측 대표성·정확도를 결정하지 않음.

서울시는 해당 강우를 보정하지 않은 원시 계측 자료로 설명. 자체 완전성 검사는 계측 검보정·현장 강우 검증과 별개. 인접 관측값 차이는 공간·장비·시간 특성의 영향을 포함하며 보정계수나 참값으로 사용하지 않음. 이 비교는 강우 자료의 추가 증거이며 유출량·침수위·배수관망 검증이 아님.

## 재현 산출물

`scripts/fetch_seoul_observations.py`로 고정된 공개 원본 요청. 기존 manifest의 해시와 다른 응답은 거부하고 덮어쓰지 않음. `scripts/audit_seoul_rainfall.py`로 원본·위치·KMA 해시를 확인한 뒤 파생 관측과 비교 보고서 생성. 변환 코드 해시 포함, 원본은 git 제외·manifest와 파생 보고서는 버전 관리.

검사 항목: 10분 경계·자정 처리, 부분 구간 제외, 결측/중복/잘못된 시각/다른 관측소/음수/NaN 거부. 외부 실자료를 단위 검사 fixture로 복제하지 않으며 작은 명시적 입력으로 변환 계약을 검사.

## 서울 대표 블록의 인근 관측 강우

25개 구 대표 블록에 2024-06-22·07-02·07-18의 인근 AWS 분 자료를 추가한다. 기존 성동 공통 강우 모델과 저장 기록은 보존하고 별도 해시의 모델로 등록한다. 구역 중심에서 지오데식 거리가 가장 가까운 AWS 지점을 사전에 선택하며 강우량·점수에 따른 관측소 선택은 금지한다. 10 km 밖 지점은 연결하지 않는다.

기상청 지점정보 API의 `inf=AWS`, 빈 `stn`, 관측 창 시작·종료 `tm`으로 당시 지점 목록을 저장한다. 양 끝 지점 좌표가 같은 경우에만 연결하며 전체 이전 이력 확인이나 블록의 현장 강우 관측으로 해석하지 않는다. 가까운 지점이라도 지형·장비·강우의 공간 차이가 있으므로 대표성은 미검증이다.

분 원본의 연속성·관측소·음수/결측·자정 경계·15/60분 이동누적 일관성을 기존 변환기로 검사한다. 검사 실패 자료는 거부하고 공통 강우를 유지하며, 빈 구간 채움이나 다른 관측소로 자동 대체하지 않는다. 원본·인증값 없는 요청 조건·SHA-256·관측 창·관측소 거리·선정 근거를 프로젝트에 저장한다. 과거 연구 모드는 저장 자료를 사용한다. 기본 공동 모드의 최신 강우는 아래 직접 조회 계약 적용. 신규 모델은 `NEAREST_AWS_OBSERVED_REPLAY`로 구분하고 선택 화면에 관측소와 거리를 표시한다.


2026-10-17 확보 결과: 과거 시점 지점 목록 6개, 품질 검사를 통과한 20개 관측소의 57개 관측 창을 보관했다. 중복 사용을 포함해 24개 구·69개 강우 모델 연결, 거리는 0.209~3.413 km다. 강서구의 최근접 김포(공) 110은 세 날짜 모두 결측으로 제외했고, 동작 889·마포 411·서초 401은 6월 22일만 제외했다. 해당 구역의 성동 공통 강우 모델은 유지한다. 강남은 같은 세 날짜에 26/59.5/96.5 mm로, 성동 공통 18.5/55/104 mm와 구분된다.

수집 결과는 `data/manifests/seoul-regional-rainfall-v1.json`, 새 플레이 목록은 `seoul-play-v2.json`에 고정했다. 전체 152개 모델(기존 83개 보존), 25개 대표 블록의 144개 강우 조건을 등록했다. 인근 자료가 있는 24개 구는 가장 최근 확보 창으로 진입한다. 원본은 `data/raw/`, 정규화 배열은 `data/derived/rainfall/`, 모델 원문은 `data/models/`에 보관한다. 과거 연구용 자료이며 실시간 조회의 원천으로 사용하지 않음.

## 실시간 직접 조회

2026-10-22 갱신. `GET /api/v1/rainfall/live`는 서버에서 수집한 기상청 AWS 매분자료를 60초 동안 공유한다. 만료 뒤 최초 요청만 새로 수집하며 중첩 요청은 같은 수집에 합류한다. 공식 [AWS 매분 명세](https://apihub.kma.go.kr/apiList.do?seqApi=2&seqApiSub=239)의 `nph-aws2_min`, `stn=0`, `disp=0`, `help=1` 사용. 현재 분은 아직 생산 중일 수 있어 조회 시각에서 1분 전을 `tm2`, 그 4분 전을 `tm1`로 명시. 같은 직접 응답에서 지점별 최근 유효 관측을 선택하고 실제 관측·조회 시각과 경과 초 공개. 최신 행 결측을 관측 0으로 대체하거나 직전 관측을 현재 시각으로 다시 쓰지 않음. 15분·60분·일 누적 깊이(mm)를 구분하며 이를 분당 강우나 강우강도(mm/h)로 오표기하지 않음.

원문·해시·실제 수집 시각은 서버 공통 저장소에 보존하며 API·워커의 호출 원장을 공유한다. 만료된 응답으로 실패를 대체하지 않는다. 클라이언트는 60초 간격으로 서버를 조회하며 숨김 탭에서 중지. 날짜·분·지점·18개 필드·시작/종료 표식·중복·유한 범위 검사. 공식 결측 부호는 null, 부분 결측은 MISSING, 5분 초과는 DELAYED. 오류 응답에 원문·인증키·외부 요청 주소 노출 금지. 2MiB 본문 상한·5초 연결/15초 요청 제한·리다이렉트 금지·no-store 적용. 저장된 강우로 실패 대체 없음.

구별 관측소는 기존 대표 위치의 사전 선정 지점을 사용(강서는 110). 기상청 지점 관측이며 구 전체의 동일 강우를 의미하지 않음. 최신 관측만을 반환하며 점수 계산 입력의 불변 기록은 별도 계산 과정에서 보존.

직접 조회 확인: 2026-10-17 20:50 KST 기준 24개 구 CURRENT, 관악 509 결측 MISSING. 실제 성동 화면에서 20:51 관측·20:53 조회·60분/일누적 0 mm 확인. 결측/0 구분·중복/시각/수치 거부·실패 후 재조회/저장 대체 없음 단위 검사 3개와 공개/권한 검사 3개, 프런트 빌드 통과.


2026-10-18 강수 여부 보완: 같은 공식 페이지의 `1.8 AWS2 현천자료`를 `itv=1&range=1`로 병행 직접 조회. 1분 빈도·지점·장비·코드·좌표·시각 검증 후 기존 구별 선정 관측소와 정확한 지점번호로만 결합. 공식 코드 40~42·50~68은 비/이슬비, 71~76은 눈으로 분리. 같은 시각 장비 간 강수 판정 충돌은 미확인. 다른 관측소의 날씨를 서울 전역으로 복제하지 않음.

강수감지 센서 양성 또는 연속 1분 강수 증가, 현천의 강수 코드가 비 효과 근거. 센서 결측·누적 변화 0은 미확인으로 보존. 현천의 비 코드는 강수량 0mm이어도 표시하되 물리 입력량을 임의로 늘리지 않음. 별도 `rainObservedAt`·`rainEvidence`·`presentWeatherCode`를 전달하고 미래·5분 초과 근거 제외. 현천이 같은 시각 또는 더 최신이면 알려진 현천 판정 우선, 현천 결측 시 유효 AWS 강수 근거 유지. 현천 조회 장애로 정상 강수량까지 버리지 않음. 두 직접 조회 모두 실패하면 기존 오류 반환. 원문과 처리 결과는 위 60초 공유 정책을 적용한다. 공급자 오류·한도 초과의 공유 차단은 [운영 계약](10-operations.md)을 따른다.

## 주간 선행 강우 결측 보강

2026-10-22 구현. 주간·실시간 대회의 최초 계산에서 선행 7일 AWS 분 관측을 먼저 정규화하고, 복원할 수 없는 분에만 서울시 실제 10분 관측을 적용한다. 설치 이후 점수 구간의 원 관측 조건과 최신 날씨 직접 조회는 유지한다. 기존 성공 계산은 보관 선행 입력을 그대로 재생한다.

서울시 [강우량계 위치정보 OA-22824](https://data.seoul.go.kr/dataList/OA-22824/F/1/datasetView.do)의 2026-09-15 좌표와 기상청 2026-10-22 지점 조회 좌표로 가장 가까운 서울시 지점 하나를 10km 이내에서 사전 고정한다. 거리·지점번호·원본 해시와 생성 코드를 [고정 목록](../backend/src/main/resources/native-weather/v1/antecedent-fallback.json)에 보관하고 평가 정책 해시에 결속한다. 강우량·점수·자료 유무에 따라 지점을 바꾸지 않는다. 현재 목록의 적용 관측 기간은 2026-10-01 이후이며 과거 재해 관측소 연결에 소급 적용하지 않는다. 전체 이전 이력과 개별 부지 강우 대표성은 미검증이다.

공식 HTTPS 다운로드에서 정확한 강우량계 코드를 다시 필터링하고 지점 이름·구 이름·10분 종료 시각·중복·음수·비유한 수치·누락을 검사한다. 10분 누적량을 10으로 나누는 평균 강도는 모델 가정으로 기록하며 정상 AWS 분 관측은 바꾸지 않는다. 일부 분만 보강한 10분 구간은 적용한 분 수·깊이와 보조 관측 전체 총량을 구별한다. 선행 종료 시각을 넘어서는 미완결 10분 구간은 사용하지 않는다. 보조 자료도 부족하거나 응답 검사가 실패하면 계산을 보류한다.

원문·조회 시각·해시·고정 지점 목록·보강한 모든 분·비율·평균 분배 가정을 계산 재현 묶음에 보관한다. 시작 상태 설명에는 보조 지점·거리·보강 분 수와 한계를 표시한다. 양의 누적량을 실제 분 관측으로 표시하거나 결측을 임의 0으로 바꾸지 않는다. 최신 OA-23092의 이용 조건은 공공누리 2유형(출처표시·상업적 이용금지)으로, 기존 역사 ZIP 자료의 조건과 구분하고 홈 출처에 안내한다.


2026-10-22 공유 수집: 선행 AWS는 공통 6시간 경계의 요청 원문을 재사용하고 계산 요청 밖의 관측은 제외한다. 과거 절대 시각 요청은 24시간, 최근 2시간 이내 요청은 60초 공유한다. 서울시 보강 자료는 지점별 10분간 공유한다. 원 수집 시각·SHA-256은 유지하며 계산에 사용한 자료는 별도 재현 묶음에 보존한다.
