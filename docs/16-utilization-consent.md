# 기관 검토·사업 활용 동의

현재 상태(2026-10-21): 기존 연구·사업 동의의 서버 API와 기록 보존 계약이다. 미사용 기관 검토·동의 관리 프론트는 제거했으며 아래 화면 설명은 이전 동작 기록이다. 현재 [게임 대회](01-product.md#대회--2026-10-21)의 참가·결과 조회나 관리자 순위 권한은 연구·사업 활용 동의를 부여하지 않는다.

2026-10-16. 평가 제출·연구 공유·사업 활용 검토를 각각 구분. 운영자 가입 승인은 조직 회원의 접근 자격이며 플레이어 자료 이용 동의를 대체하지 않음.

## 목적별 범위

| 목적 | 부여 방식 | 범위·철회 |
| --- | --- | --- |
| 경쟁 평가 | 본인이 선택한 계산의 명시적 제출·리그 규칙 수락 | 해당 제출·공개 순위 요약. 연구·사업 권한 자동 부여 없음 |
| 연구 재사용 | 기존 기관별 연구 공유 설정 | 제출된 전략과 그 버전까지 이력. 기관별 연구 동의 철회 시 이후 연구 접근 차단 |
| 사업 활용 검토 | 승인 기관의 특정 계산·활용 목적 요청에 대한 소유자의 별도 동의 | 요청에 고정된 계산·버전·기관·목적만 해당. 연구 동의와 독립적으로 철회 가능 |

사업 활용 검토 동의는 실제 시설의 시공·안전·현장 효과 승인이나 권리 양도 계약이 아님. 현재 모든 계산은 EXPLORATORY이며 현장 적용을 확정하는 상태·버튼 제공 금지. 목적 변경·다른 계산 사용은 새로운 요청 필요. 기본 체크·일괄 동의·기관 가입으로 자동 동의 금지.

## 요청·동의 상태

기관은 연구 동의가 유효하고 본 기관에 열람 가능한 제출 계산에서만 요청 생성. 요청 제목(2~100자)·활용 목적(10~2,000자)·계산 ID·멱등키 필수. 요청 후 내용 불변, 정책 버전 `APPLICATION_REVIEW_2026_10_V1`과 요청 내용 SHA-256 고정. 개인정보·연락처·비밀 입력 안내 금지.

- `PENDING` → 소유자 `GRANT` → `GRANTED`
- `PENDING` → 소유자 `DECLINE` → `DECLINED`
- `GRANTED` → 소유자 `REVOKE` → `REVOKED`

반려/철회 요청의 재활성화 불가, 필요한 경우 새 요청. 요청 기관은 소유자 결정을 대신할 수 없음. 결정 요청은 예상 revision과 내용 hash를 포함해 오래된 화면·변경된 요청의 승인 방지. 요청별 결정 이벤트 불변, 상태·이벤트·감사 로그를 같은 트랜잭션에서 저장. 같은 기관·계산의 대기 또는 승인 요청은 한 개만 허용.

기관의 최초 요청은 연구 동의를 요구하되 승인된 사업 활용 검토 동의는 별도 범위. 연구 동의만 철회하면 사업 활용 검토 권한은 유지됨을 양쪽 화면에 표시. 전체 공유 중지는 연구 공유와 활성 사업 요청을 각각 철회. 어느 목적이든 소유자 계정 이용 정지·기관 승인 해제 시 자료 접근 중지.

## 기관 검토 기록

기관별 특정 계산에 대해 `CANDIDATE`(검토 후보), `NEEDS_EVIDENCE`(추가 근거 필요), `NOT_SELECTED`(현재 검토 제외) 중 하나를 기록. 이유·현장 미확인 조건 필수, 각 1~2,000자. 새 기록 추가만 허용, 수정·삭제 대신 후속 기록으로 판단 변화 보존. 실제 적용·인허가·모델 검증 완료를 의미하는 상태 없음.

연구 공유가 유효한 제출만 검토 기록 추가 가능. 기관은 자기 조직의 기록만 조회, 소유자는 자기 계산에 대한 모든 기관의 검토 기록 확인. 다른 기관·다른 소유자 요청은 404, 관리자 자동 열람 금지. 연구 공유 철회 후 기관 검토 기록의 원문 접근 차단, 소유자의 검토 이력은 보존.

## API·내보내기

- `POST /api/v1/institution/utilization/requests`: 요청 생성, MFA·승인 조직·연구 동의·멱등 검증
- `GET /api/v1/utilization/requests`: 본인 소유 계산에 대한 요청 목록
- `GET /api/v1/institution/utilization/requests`: 본 조직의 요청 목록
- `GET /api/v1/utilization/requests/{id}`: 당사자 요청 상세·동의 결정 이력
- `POST /api/v1/utilization/requests/{id}/decisions`: 소유자만 결정
- `GET /api/v1/institution/utilization/requests/{id}/bundle`: 본 조직·GRANTED·현재 계정 상태 재검증 후 지정 계산 재현 ZIP
- `POST /api/v1/research/strategies/{jobId}/reviews`: 기관 검토 추가
- `GET /api/v1/research/strategies/{jobId}/reviews`: 본 기관 검토 이력
- `GET /api/v1/utilization/reviews`: 본인 계산의 기관 검토 목록

요청·검토 목록은 시간·ID 커서로 페이지 처리, 상한 50개와 다음 커서 반환. 본문 범위·enum·CSRF·역할·rate limit 검사. 도메인 `utilization` 내부 dto/entity/repository/service/mapper/view/controller/exception 구성.

기존 소유자·연구 ZIP은 그대로 유지. 새 사업 활용 검토 ZIP은 목적·요청 ID·내용 hash·정책 버전·계산/버전·동의 revision/시각·기관·내보낸 시각을 access-scope에 추가. 파일 준비 전후 권한 재검사. 이미 받은 파일 자동 회수 불가를 동의 화면에 표시하고 후속 다운로드만 차단. 다운로드 감사는 목적·요청 ID 구분.

## 검증 기준

연구 공유만으로 사업 다운로드 거부, 다른 기관/소유자/관리자 거부, 명시적 승인 후 지정 계산만 다운로드, 연구 철회와 사업 철회의 독립성, 계정/기관 상태 재검사, 오래된 revision·hash 거부, 동시 중복 생성/결정 경합, rollback 시 이벤트·상태 불일치 방지, 커서 소유권·페이지 누락 방지. 플레이어·조직 회원 모두 본인 요청과 연구 공유 관리 가능. 실제 브라우저에서 요청→동의→다운로드→철회 및 검토 이력 확인.

인증 성공·MFA 등록 세션 발급 시 새 CSRF 토큰을 응답 전에 저장. 기존 토큰 무효화는 유지하면서 인증 직후 병렬 첫 조회의 JDBC 세션 속성 중복 삽입 경합 방지. 로그아웃은 세션 무효화 유지.

브라우저는 `AUTHENTICATION_REQUIRED` 응답 시 만료된 계정과 개인 조회 상태를 해제. 인증 전환 이전의 지연 응답으로 새 로그인 상태를 변경하지 않으며, 변경 요청을 자동 재전송하지 않음. 로그아웃 직전 CSRF 갱신, 이미 만료된 세션의 401은 로그아웃 완료로 처리. 네트워크·서버 오류를 로그아웃 성공으로 표시하지 않음.
