2026-10-16. 붙여넣은 기획의 시민 상위 패턴 학습·추가 후보 생성·동일 물리모형 재평가 구현 계약. 문서 26의 기술 통계와 별도 기능. EXPLORATORY 유지, 전역 최적·현장 효과·학습 성능 우월 주장 금지.

## 학습 표본·목적

현재 조직에 연구 동의된 동일 모델의 성공 제출 2~50개 선택. 서버 물수지에서 점수 재산출, 불변 버전·입력 hash·비용 재검사. 동일 물리 입력은 한 번만 사용하고 서로 다른 배치 최소 2개 필요. 요청 상위 기준 2~20개와 경계 동점 전부를 학습 집합으로 사용. 중복 대표 작업은 UUID 문자열 사전순으로 고정. 요청한 모든 원본의 현재 동의가 조회·생성·다운로드 권한 조건이며, 상위에서 제외된 원본도 요청 표본의 일부로 보존.

물리 중복 판정은 배치를 구역 ID 순서로 정렬하고 면적의 불필요한 소수 0을 제거한 별도 physicalHash 사용. 원본 inputHash·배치 원문·버전 ID는 변경하지 않고 함께 보존. 원본 점수·비용이 다른데 physicalHash가 같으면 품질 오류로 학습 거부.

예산은 1원~모델 예산의 정수 원. 모든 선택 원본의 비용이 요청 예산 이내여야 비교 허용. 모든 후보는 동일 모델·예산·시설/면적/개수 제약 적용. 서로 다른 리그의 추가 조건까지 동일하다는 의미가 아니며 해당 리그 순위에 제출하지 않음. 파생 후보는 시민 원본이 아니므로 일반/리그 자동 제출·개인 전략 자동 복사 없음.

## 생성 방법 V1

정책 `ELITE_CATEGORICAL_SEARCH_V1`. 상위 배치에서 구역마다 NONE 또는 허용 시설×면적 비율(25%, 50%, 75%, 100%)의 범주 빈도를 추정. 원본 면적/maxArea를 가장 가까운 비율로 분류하고 거리 동률은 작은 비율 선택. NONE은 미설치. 범주마다 가산 평활 1개 적용; 독립 구역 가정이며 구역 간 상관·인과를 학습한 모델이 아님.

분포 추정 탐색의 개념적 근거: [Dang·Lehre·Nguyen, Level-Based Analysis of the Univariate Marginal Distribution Algorithm](https://link.springer.com/article/10.1007/s00453-018-0507-5), 2018 온라인/2019 수록. 본 구현은 혼합 시설/면적 범주의 한 세대 생성 변형이며 논문의 이진 문제 수렴·복잡도 결과를 물환경 문제의 성능 보증으로 전용하지 않음.

- 입력: 고정 모델·검증된 물리 배치/서버 점수·예산·상위 기준·seed(0~2,147,483,647)·방법당 후보 수(1~4, 기본 3)
- 두 방법: 학습 빈도+1 가중치 `PATTERN`, 모든 범주 가중치 1인 `UNIFORM`. 같은 후보 수·예산·최대 128번 생성 시도로 비교
- 구역 순서: 각 시도의 SHA-256 키로 정렬. 고정된 앞 구역만 예산을 먼저 쓰는 편향 축소. 동률은 구역 ID 사전순
- 구역 선택: 남은 예산/시설 개수/면적 한도 안의 범주만 허용, NONE 항상 허용. SHA-256 정수의 누적 정수 가중치 추첨. 예산을 초과한 배치를 사후 비례 축소하지 않음
- 범주 누적 순서: NONE, 시설 enum 이름 사전순, 각 시설 안의 비율 오름차순. 보고서 구역 순서는 구역 ID 사전순
- 실제 면적: maxArea×비율, 소수 2자리 HALF_UP. 0이 된 범주 제외. 구역 ID 순서로 배치 정렬, 불필요한 소수 0 제거 후 기존 Java 배치 직렬화와 동일 형식
- 시드 규약: `policy + '\n' + modelHash + '\n' + seed + '\n' + arm + '\n' + attempt + '\n' + purpose + '\n' + cellId`. attempt는 0부터, purpose는 ORDER 또는 CHOICE. 전체 SHA-256 unsigned 정수 사용. ORDER는 hex 문자열 사전순, CHOICE는 허용 가중치 합으로 나눈 나머지
- 빈 배치·선택 원본과 같은 물리 hash·같은 방법 안의 중복 후보 제외. 두 방법 사이 동일 후보는 허용하고 중복 수 공개; 별도 시민 성과로 세지 않음
- 목표 수를 128회 내 채우지 못하면 `CANDIDATE_SPACE_EXHAUSTED` 422, 작업/그룹 생성 없음. 실제 생성 시도 수·거부 사유별 수·모든 범주 빈도와 가중치·포함 원본·생성 결과 보존

확률 모형은 이 요청의 상위 표본에서 한 번 추정. 실행 결과로 다시 학습하는 반복 최적화나 신경망 아님. 무작위 대조와 후보 수가 같아도 한 표본·한 seed 결과만으로 알고리즘 우수성 검증 불가. 원본 최고점·각 방법의 모든 성공/실패·최고점·비용을 함께 공개하고 실패가 있으면 완전 비교로 표시하지 않음.

## 단계 2: 저장·공용 워커

2026-10-16 V10 검색 그룹·원본 연결·후보 테이블, 후보의 모델/그룹 외래키·범주/순번/시도/상태 제약 추가. 전체 활성 500개와 기관 활성 9개 집계에 후보 포함. 개인 활성 3개와 개인 계산 조회는 개인 작업만 유지.

공용 입장 잠금 아래 두 큐의 가장 오래된 처리 가능 작업을 claim. 잠긴 작업 제외·생성 시각 동률의 결정적 정렬·180초 lease·3회 한도·만료/교체 token의 쓰기 차단. 후보의 독립 경로와 동일 SWMM·캐시 연결. 잘못된 입력 hash·손상된 JSON을 엔진 실행 전에 거부.

서버 전체 84개·기존 Python 35개 통과. 별도 PostgreSQL 18.4에 실제 Flyway V1~V10 적용 후 큐 상한/조회 격리 1개와 워커 통합 8개 통과. 8개 동시 claim의 중복 없음, 두 큐 FIFO/잠금/3회 만료 처리 검증. 결과 저장은 행 잠금을 먼저 획득하고 트랜잭션 시작 시각이 아닌 실제 시각으로 만료 여부 재검사. 잠금 대기 중 만료되는 두 큐의 결과 기록 거부 확인. 공개 모델의 실제 SWMM 개인 계산·후보 계산 모두 성공, 캐시 재사용 전후 물수지/점수/민감도/엔진 동일, 각 산출물 18개 hash 검증. 이 사례의 같은 입력은 캐시·소유권 분리 시험이며 실제 생성 알고리즘 성과 사례가 아님.

원본 로컬 DB 계산·제출·리그 수 보존, 시험 DB·임시 산출물 제거. GitHub CI에 같은 격리 PostgreSQL·SWMM 검사 추가. 기관 생성/조회 API·계보/ZIP 권한과 철회·화면 연결·시민 표본 기반 end-to-end 검증은 계속 미완료.
