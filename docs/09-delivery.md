# 확장 구현 목표·완료 기준

기준일: 2026-10-20. 현재 코드·공개자료와 초기 게임로직 PDF를 대조한 실행 계획이다. **아래 미완료 항목은 계획이며, 문서 갱신만으로 구현 완료를 뜻하지 않는다.** 현재 사용자 규칙은 [제품 계약](01-product.md), 계산의 의미와 제약은 [과학적 계약](02-scientific-validity.md), 실행 증거는 [검증 기록](12-validation-log.md)을 따른다.

## 목표와 구현 원칙

공개자료로 재현 가능한 시설 배치·침수 피해 저감 게임을 완성한다. 우선 자료를 연결할 수 있는 한 유역에서 설치 → 예산 → 강우 → 유입·침투·저류·배수·월류 → 설치 전후 비교 → 제출·순위를 끝까지 검증하고, 같은 구조로 적용 범위를 늘린다. 서울 전역 지도 제공과 서울 전역의 검증된 침수 예측은 별도 완료 조건이다.

- 아직 배포 전이므로 기존 게임 기록·규칙·스키마의 호환성을 확장 조건으로 두지 않는다. 구현 과정에서 중복 엔진·구형 화면·임시 호환 분기를 제거하고 현재 구조로 통합할 수 있다.
- 공개 원자료의 출처·해시, 의미 있는 수치 검증 사례와 재현 근거는 유지한다. 과거 사용자 기록 지원과 과학적 증거 보존을 혼동하지 않는다.
- 이번 변경은 문서 정리다. DB 초기화·기존 코드 삭제·시설 활성화·점수 변경은 실행하지 않았다. 후속 구현에서 정리 범위와 데이터 영향을 명시하고 검증한다.
- 공개 파일과 공개 API만으로 진행한다. 이미 확보한 키·파일을 다시 요청하지 않으며, 추가 접근이 꼭 필요하면 [자료 확보 현황](13-data-access.md)에 조사 근거와 필요한 항목을 한 번에 정리한다. 비공개 자료·기관 협조·배포 준비를 구현의 선결 조건으로 추가하지 않는다.
- 자료가 없는 값은 결측 또는 명시적 설계 가정이다. 임의 효과율·가상 관측·가짜 수심·가짜 순위를 사용하지 않는다. 가정 기반 탐색과 현장 검증을 결과에서 구분한다.

## 현재 구현과 남은 차이

| 영역 | 확인된 현재 구현 | 완료해야 할 범위 |
| --- | --- | --- |
| 게임 | 주간 개인 설치·구별 합산, 재해 게스트 실험·회원 제출, 20억 원 개인 예산 | 확장 시설·연결 유역·새 평가 기준을 두 모드에 일관되게 연결 |
| 설치 시설 | 빗물정원·투수포장·녹화지붕·생물저류·식생수로·침투도랑 6종 | 현장 적합성 근거와 외부 집수·배수 연결의 검증 범위 확대 |
| 빗물이용조 | 공간 초안 저장, 연결 관망의 이용조 계산, 일부 제원·견적 근거 | 일반 지도에서 설치 확정·예산·상태·결과·제출까지 연결. 현재 초안은 설치/점수 아님 |
| 소형 빗물통 | 일반 게임 선택 기능 없음 | 이용조 공통 기능 완성 후 공개 사양을 가진 소형 규격 추가 |
| 시설 효과 | 현재 일반 후보는 주로 시설에 직접 내리는 비를 계산 | 근거 있는 지붕/도로 집수면과 배수 경로 연결. 임의 주변 유출 가산 금지 |
| 평가 | 배출량 차이(m³) 순위, 표면 첨두 비교·연결 관망 침수 지표 계산 기반 | 비교 경계가 일치하는 유출·첨두·월류 지표와 평가 가능 범위 노출 |
| 도시 침수 | 관망·2D 교환, 프레임·재생·이동체 반응 기반 | 공개 운영 모형 등록과 유역별 검증. 현재 `surface/public-models-v1.json`의 `models`는 비어 있음 |
| 경제성 | 설치비·예산 원장, 이용조 일부 견적/연간 비용 근거 | 공종 누락·기준 연도·유지/교체 비용을 검토한 생애주기비용(LCC) |
| 유지관리·적합성 | 면적·표면 종류·일부 토양/경사 조건 | 막힘·관리 상태 시나리오와 근거 있는 적합성 판정. 실제 하중/지하수/지장물 미확인 |
| 기관 기능 | 서버의 리그·동의·재계산·후보 탐색 경로 | 현재 기본 UI는 준비 중/연구실 진입 미제공. 게임 핵심 완료 후 유지 범위 결정 |

현재 게임 점수는 `surfaceRunoff + lidDrainage + finalStorage − initialStorage`의 기준안 대비 차이다. 100점 종합 평가가 이미 적용된 것으로 설명하지 않는다. 수면 애니메이션·과거 침수흔적·현재 도시 배경도 실시간 침수 계산 완료의 증거가 아니다.

## P0 · 평가·설계 구조 통합

- [ ] 배치, 시설 규격, 유입면적 배분, 초기 상태, 비용, 평가 경계, 원자료/코드 버전을 하나의 현재 계약으로 정리한다. 필요한 DB·API·프론트·워커를 함께 변경한다.
- [ ] 주간·재해가 같은 시설 계산·물수지·지표 정의를 사용하게 한다. 시간 규칙은 유지한다: 주간은 설치 이후 관측, 재해 실험은 시간축 설치 이후, 제출은 동결 설계를 사건 전체에 적용한다.
- [ ] 구형 설계실·점수·리그 규칙 중 남길 기능을 결정하고 사용하지 않는 진입·분기·마이그레이션 호환 코드를 정리한다. 기록 유지 때문에 두 계산 체계를 병행하지 않는다.
- [ ] 기준안과 설계안의 강우·선행 상태·유역·보고 시각·수치 정책을 동일하게 고정하고, 단위/시각/좌표계/해시를 결과에 묶는다.

완료 기준: 같은 설계와 평가 입력의 API·워커·화면 지표 일치, 캐시 유무에 따른 결과 일치, 주간/재해 시간 규칙·권한·중복 제출 회귀 통과. 진행률 표시는 실제 작업 상태만 사용한다.

## P1 · 빗물이용시설 완성

시설 선택에는 **빗물이용시설**을 두고 규격으로 **소형 빗물통 / 빗물이용조**를 선택한다. 현재 이용조의 미완성 경로를 먼저 완성하고 소형 규격을 추가한다. 서로 다른 엔진이나 복제된 비용·점수 로직을 만들지 않는다. 용어를 가르는 보편적인 용량 기준을 임의로 만들지 않는다.

- [ ] `cistern_map_plans`의 `SPATIAL_DRAFT_NOT_INSTALLED` 초안을 실제 설치와 명확히 분리하고, 공개 근거가 충족된 규격만 확정 설치로 전환한다.
- [ ] 지붕 집수면·배관 연결·용량·설치 면적·유출구·넘침 경로를 명시한다. 집수면 중복 배분과 다른 시설로 보낸 유출의 재사용을 차단한다.
- [ ] 기존 관망 이용조의 유입·저류·수두 기반 배수·월류 계산을 공통 시설 흐름에 연결한다. 총용량이 아닌 현재 여유 용량을 사용하며 가득 차면 넘침이 발생해야 한다.
- [ ] 실제 사용 수요 근거가 있을 때만 재이용량을 계산한다. 저장량을 소비/영구 저감으로 간주하거나 비가 오기 전에 자동으로 빈 통으로 초기화하지 않는다. 수요 미확보 시 재이용량은 미산정으로 유지한다.
- [ ] 규격별 공개 사양·공종·가격 기준일·포함/제외 공사를 연결한다. 현재 2.35m³ 문헌 사례의 부분 견적을 모든 현장/소형 통의 완성 공사비로 사용하지 않는다.
- [ ] 예산 검증·설치 목록·3D 표시·시간축 아이콘·시설별 결과·제출·순위를 연결한다. 재해는 소속 구와 무관하게 모든 구에서 같은 허용 규칙을 적용한다.
- [ ] 소형 빗물통도 별도 공개 규격과 설치·월류 근거를 확보해 같은 경로로 추가한다. 단순히 용량만 줄인 가짜 규격은 만들지 않는다.

완료 기준: 무강우·빈 통·부분 충전·만수·배수·넘침·재이용 수요 없음/있음·중복 집수·예산 초과를 검증하고 물수지를 보존한다. 현재 미확정 공사비나 설치 조건이 남은 규격을 정상 설치 버튼으로 노출하지 않는다.

## P2 · 연결 유역 한 곳의 실제 게임 흐름

- [ ] 공개 관망의 수평/수직 기준·맨홀/관로 연결·지표/방류 경계와 강우 시점을 확인해 첫 적용 유역을 선정한다. 확보한 서초 공개 연구 관망도 이 조건을 검사하며, 서울시 공식 현장 관망으로 승격하지 않는다.
- [ ] 시설 외부 유입을 검증 가능한 집수면과 경로로만 연결한다. 자료가 없는 지역은 현재 표면 탐색 범위를 명시한다.
- [ ] 기준안/설계안의 유역 출구 유출 총량·첨두, 맨홀 월류량·지속시간, 계산 지표 수심/유속을 연결한다. 같은 시각의 합 유량에서 첨두를 구하며 개별 최대값을 더하지 않는다.
- [ ] 자연 하천, 과거 침수흔적, 계산 침수를 구분하고 실제 계산 프레임만 해당 시각에 표시한다. 자료 없는 시각/지역의 깊이를 만들어 채우지 않는다.
- [ ] 사람·차량 반응은 계산/기록에 따른 시각적 반응과 피해 평가를 분리한다. 피해 인원·금액을 점수로 쓸 경우 별도 공개 노출자료와 취약도 근거부터 정의한다.
- [ ] 관망·지표 교환 물수지, 역류·만관·건습 전환, 시간/격자 민감도와 독립 참조 대조를 검증한다.

완료 기준: 한 공개 유역에서 지도 설치부터 서버 계산·결과·저장·제출·재현까지 연결되고 실패/미지원 범위가 구분된다. 동일 수준의 근거가 있는 다음 유역으로 확장한다. 공개자료가 부족하면 미지원 범위를 남기되 다른 기능 구현은 계속한다.

## P3 · 성능 지표와 점수

초기 게임로직 PDF의 **유출량 35 + 첨두 30 + 월류 15(량 10·시간 5) + 비용효율 10 + 유지관리/실현성 10**은 기획 후보로 보존한다. PDF의 비용효율 10/15점 표기 충돌, 참가자 최고값 정규화, 0 분모 처리, 기간/평가지점 정의는 그대로 구현하지 않는다. 가중치는 과학 상수가 아니라 게임 규칙이다.

- [ ] 먼저 원 지표·단위·기준/설계 차이·증감률·평가 가능 여부를 제공한다. 표면 유출과 관망 유출/월류를 동일 이름으로 혼용하지 않는다.
- [ ] 지표별 평가 경계·기간·유효성·방향·0 기준값·음수 효과·동점 처리·배점 범위를 확정한다. 악화된 결과를 0으로 숨기지 않고 원값을 보존한다.
- [ ] 참가자 최고값 대신 평가 시작 전에 고정한 기준으로 정규화한다. 참가자 추가 때문에 기존 결과 점수가 변하지 않아야 한다.
- [ ] 필수 지표가 없으면 미산정과 사유를 반환한다. 결측을 0점/효과 없음으로 바꾸거나 나머지를 100점으로 재배분하지 않는다. 서로 다른 지표 집합·모델·조건의 기록을 같은 순위에 혼합하지 않는다.
- [ ] 종합점수 도입은 지표·비용·관리 근거가 준비된 뒤 확정한다. 그전에는 현재 체적 차이 순위를 그 이름과 범위로 유지한다. 주간의 관측 확정 범위와 재해의 전체 사건 평가를 명시한다.
- [ ] 안전상 금지 조건은 설치/평가 제약으로 처리한다. 다른 지표의 점수로 구조 하중·지하수·배수 안전 위반을 상쇄하지 않는다.

완료 기준: 같은 입력에 같은 점수, 참가자 증감에 불변, 무강우/0 기준값·악화·결측·동점 검증, 서버 계산·화면·랭킹·재현 자료 일치. 점수 확정 전 현재 순위를 임의 환산하지 않는다.

## P4 · 비용·유지관리·현장 적합성

- [ ] 설치비와 LCC를 구분한다. 공통 평가기간·가격 기준연도·할인 가정과 출처를 고정하고 설치·점검/청소·수선·교체 비용을 분리한다. 근거 없는 수명·교체 주기·금액을 생성하지 않는다.
- [ ] 현재 이용조의 부분 공종·연간 비용을 전체 설치비로 오인하지 않도록 미산정 항목을 표시한다. 한 시설 비용을 다른 시설의 계수로 복제하지 않는다.
- [ ] 새 시설/관리 지연/정비 이후 등의 관리 상태를 공개 문헌 근거에 따라 시나리오로 제공한다. 현재 신규·막힘 없음 설정과 구분하며, 몇 시간의 사건 재생에 수년간 노후화를 압축하지 않는다.
- [ ] 토양·경사·지하수·지장물·교통 하중·옥상 구조 하중·방수/배수 조건을 허용/조건부/금지/미확인으로 구분한다. 지도 배치 허용은 실제 시공 승인이 아니다.
- [ ] 유지관리와 실현성 점수의 근거·판정표를 먼저 정의한다. 공개자료에서 확인 불가능한 항목을 임의 상/중/하로 채우지 않는다.

완료 기준: 비용 포함 범위·결측·할인 가정·관리 시나리오를 재현하고, 미확인 안전 조건을 확정값으로 표시하지 않는다. LCC 비교 대상의 기간·금액 기준이 같아야 한다.

## P5 · 통합 화면·성능·보안

- [ ] [공통 UX 계약](08-experience.md)에 따라 시설별 현재 상태·효과·근거를 기존 목록/결과에 통합한다. 중복 안내·별도 임시 패널을 늘리지 않는다.
- [ ] 무거운 연결 계산은 서버 비동기 큐에서 실행한다. 같은 입력의 계산 캐시와 지도 시야별 파일 캐시를 분리하고, 카메라 이동/재생 프레임마다 물리 계산을 요청하지 않는다.
- [ ] 실제 대상 기기에서 첫 로드·근접 이동·확대/축소·긴 재생·시설 전환의 시간/메모리/프레임을 측정한다. 타일/객체 예산·취소·GPU 해제·이전 형상 유지와 오류 복구를 확인한다.
- [ ] 게스트/회원/기관 경계·소유권·CSRF·예산 경합·멱등 제출·작업 만료·결과 해시를 통합 검증한다. 게스트 최종 결과 잠금을 UI만으로 처리하지 않는다.

완료 기준: 두 모드의 실제 브라우저 → API → 워커 → 저장/조회 흐름 검증, 핵심 수치 회귀, 실패·재접속·캐시·권한 시험 통과. 기능별 증거를 [검증 기록](12-validation-log.md)에 남기고 이 문서의 체크를 갱신한다. 공개 운영 검증은 [운영 계약](10-operations.md)으로 별도 관리하며 구현을 막는 자료 요청으로 취급하지 않는다.

## 이후 범위와 참고 근거

기관의 다강우 비교·패턴 후보 탐색은 [기관 분석 계약](18-institution-analysis.md), 리그 운영은 [참가 계약](17-league-participation.md), 연구/사업 활용은 [동의 계약](16-utilization-consent.md)을 따른다. 핵심 게임 완성 뒤 필요한 화면을 통합하며 예전 화면 복원을 목표로 삼지 않는다.

- 초기 기획: 「1018 한동규 - 게임로직.pdf」 3쪽. 유출·첨두·월류·경제성·유지관리 제안의 출처다. 1쪽 저류조 취소선과 2쪽 시설 표, 비용 배점의 불일치는 위 완료 기준에서 정리한다. 개인 Downloads 파일을 저장소 필수 경로로 만들지 않는다.
- [EPA SWMM](https://www.epa.gov/water-research/storm-water-management-model-swmm): 시설 물수지·배수 연결의 계산 근거.
- [EPA 도로 유출 녹색인프라 유지관리](https://www.epa.gov/green-infrastructure/operation-and-maintenance-green-infrastructure-receiving-runoff-roads-and): 관리 항목 조사 근거이며 게임 점수표 자체의 인증이 아니다.
- [NIST Handbook 135](https://nvlpubs.nist.gov/nistpubs/hb/2022/NIST.HB.135e2022-upd1.pdf): 생애주기비용 산정 절차 참고. 미국 기준의 금액·할인율을 서울 사업에 그대로 적용하지 않는다.
