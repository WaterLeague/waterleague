# EPA 공개 참조 사례 수치 대조

2026-10-17. 문서 02의 독립 참조 사례 검증을 구현한다. 서울 현장 관측·LID 보정·검토자 승인과 별개이며 운영 모델과 등급·점수를 변경하지 않는다.

## 입력과 범위

[EPA SWMM 공식 배포 페이지](https://www.epa.gov/water-research/storm-water-management-model-swmm)의 Applications Manual ZIP을 고정 SHA-256으로 취득. ZIP 내부의 `files.zip`에서 Example 1의 개발 전/후 INP 2개만 읽는다. 외부 파일을 재귀 추출하거나 임의 INP를 실행하지 않는다. 원본·내부 ZIP·INP·매뉴얼 hash와 출처를 공개 manifest에 보존하며 원본 묶음은 로컬 취득 또는 CI에서 재취득한다.

이 사례는 미국 Fort Collins의 설계강우에 대한 교육용 수문모형이다. 서울 관측 강우나 실제 LID 효과 자료로 취급하지 않는다. 2년·10년·100년 설계강우 3개와 개발 전/후 2개 조건, 총 6개 실행을 대조한다. 원본에서 강우 시계열 선택만 변경한 CFS 입력과 동일 물리량을 SI로 단위 변환한 CMS 입력을 구분한다. 길이 ft→m, 면적 acre→ha, 깊이/강우강도 in→mm를 명시적으로 변환한다. 원본 입력을 덮어쓰지 않는다.

## 대조와 판정

1. 현재 고정 엔진 5.2.4를 C API와 별도 공식 CLI로 실행. 개별 유역 시계열은 같은 보고시각에 합산하고 최댓값 산출. 개별 첨두의 합을 사용하지 않는다.
   관망이 없는 이 사례의 O1 유입 시계열도 읽어 같은 시각의 유역 합과 대조한다. float32 출력의 합산 반올림 허용폭은 상대 1e-6·절대 1e-8 m³/s로 고정. 아래 진단에서 동일 시계열이라는 초기 가정이 기각됐으므로 차이 개수·최대 차이·첨두 시각을 따로 보존한다. 단순 합을 방류구 유량으로 대체하지 않는다.
2. CFS/CMS의 깊이·면적 환산 체적과 유량을 SI로 정규화. 1분 시계열·총량·침투·물수지, API/CLI 보고서와 OUT의 물리 결과 일치를 확인한다. 같은 바이너리의 실행 경로 비교이며 다른 수문모형의 독립성으로 표현하지 않는다.
3. 매뉴얼 인쇄 27쪽 Table 1-4와 33쪽 Table 1-8의 강우·유출 깊이·침투·첨두 값을 원문 정밀도와 함께 보존. 비교 허용폭은 인쇄 마지막 자리의 절반과 현재 보고서 반올림 폭의 합. 엔진 실행 전에 이 규칙 고정. 다른 엔진 버전의 차이를 통과시키기 위해 임계값을 늘리지 않는다.
4. 매뉴얼 Table 1-4의 개발 전 10년 유출 깊이는 0.22 in, Table 1-9는 0.24 in로 상충한다. 둘 다 기록하고 `SOURCE_CONFLICT`로 판정, 어느 값을 임의 정답으로 채택하지 않는다. 다른 항목의 차이도 `REFERENCE_DIFFERENCE`로 보존한다.
5. 출처/엔진/입력 오류·비유한 결과·API/CLI 불일치·엔진 내부 면적 환산 대조 실패는 실행 실패. 국제단위 정확 환산의 유량 차이와 인쇄 참조 차이는 별도 진단 결과로 남기고 전체 사례가 참조값과 일치했다고 표시하지 않는다. 관측·보정·SITE_VALIDATED·게임 공식 평가 승인으로 자동 승격하지 않는다.

## 산출물·검증

정규화 결과, 항목별 인쇄 참조·허용폭·차이·상태, 원본/변환 INP·RPT/OUT·실행 코드/엔진 해시를 묶는다. CI는 원본 고정·단위 변환·API/CLI 수치 일치·판정 규칙을 검사한다. 인쇄 참조 차이는 구조 검증 성공과 별도 표시하며 원문 충돌을 은폐하지 않는다. 원본 실행의 수치 게이트와 단위 변환 허용오차는 실행 결과를 보기 전에 고정하고 아래 구현 기록에 명시한다.

실행 전 고정한 수치 게이트: 유출 연속오차 절댓값 1% 이하, 경고 0개, 720개 분 보고시각·유한 비음수 유량. CFS/CMS 시계열·체적 비교는 상대 0.02%와 절대 1e-7 m³/s 또는 양쪽 보고 깊이의 반올림 체적을 허용한다. 고정 엔진 `swmm5.c`는 유량 변환에 0.02832, 면적에 2.2956e-5/0.92903e-5 등 반올림 상수를 사용하므로, 국제단위 정확 환산과의 차이를 이 허용폭에 포함한다. 시간 경계/사상은 동일하게 고정하며 허용폭을 현장 관측 오차 기준으로 사용하지 않는다.

## 첫 실행에서 확인한 단위 차이

국제단위 정확 환산 입력의 개발 전 100년 사례에서 720개 중 13개 유량 시각이 고정 허용폭을 초과했다. 이 실패를 삭제하거나 허용폭을 늘리지 않는다. 초과 시각과 차이를 `internationalUnitCheck.flowMismatches`, 전체 상태를 `internationalUnitStatus=REVIEW_REQUIRED`에 보존한다. 초기 중단 실행은 `tmp/epa-reference/run-initial`에 보존.

원인 구분을 위해 세 번째 입력을 추가한다. 이 입력은 면적 환산에 고정 SWMM 소스의 `0.92903e-5 / 2.2956e-5`를 사용하여 엔진 내부 ft²를 보존한다. 국제단위 면적 변환과 같은 입력이라고 표현하지 않으며 `cmsEngineArea`로 구분. 이 별도 대조도 기존 시계열/체적 허용폭을 그대로 적용하고 불일치 시 실행 실패. 국제단위 변환의 실패가 별도 대조 성공으로 덮이지 않도록 두 상태를 나란히 보고한다. CI의 실행 경로 검사 성공과 국제단위/인쇄 참조 적합성 판정을 구분한다.

## 유역 합·노드 유입의 관측량 구분

추가 교차 검사에서 개발 전 2년 사례의 유역 합과 O1 노드 유입은 720개 중 719개 보고시각에서 위 허용폭을 넘었다. 첨두 크기는 같지만 시각 차이와 초기/감수부의 값 차이가 있어 동일성 가정은 기각. `run-outlet-diagnostic`의 실패 자료 보존. 엔진 `routing.c`는 라우팅 단계 시작의 유출을 노드 유입에 전달하고, `output.c`/`node.c`는 유역과 노드의 이전/현재 값을 각 보고시각에 보간한다. 서로 다른 출력량을 비교한 실패를 숨기거나 임의 시간 이동으로 정렬하지 않는다.

산출물의 `outletComparison.status=DIFFERENT_SERIES`와 전체 노드 시계열·차이 파일을 유지한다. 현재 게임이 사용하는 표면별 유출 합과 실제 방류구 유량이 같다는 근거로 전용하지 않는다. 운영 점수/시계열 변경은 없으며, 첨두 평가 규칙 활성화 전에 평가 위치·보고시각 의미를 검토해야 한다.

매뉴얼 1.4절의 그래프는 outfall 총 유량을 사용하므로 인쇄 첨두 참조는 O1 노드의 합산 유입 최댓값과 대조한다. 유역별 시계열 합의 첨두·시각은 따로 보존하며 인쇄 참조의 관측량을 대체하지 않는다.

```sh
simulation/.venv/bin/python scripts/verify_epa_reference.py \
  --download --output tmp/epa-reference/verification-new
```

기본 명령의 종료 0은 고정 입력 실행·API/CLI·엔진 내부 면적 환산 검사의 성공이다. 인쇄 참조와 국제단위 대조의 `REVIEW_REQUIRED`는 별도 상태로 남는다. 모든 참조 일치를 요구하려면 `--require-reference-match` 추가. 미일치·충돌 시 산출물을 남기고 종료 2 반환. 기존 산출물 디렉터리 덮어쓰기 거부.

실행 경로는 C API 호출 전에 절대경로로 정규화하며 INP/RPT/OUT 경로의 파일시스템 인코딩 길이는 SWMM 5.2.4의 `MAXFNAME=259` bytes 이하로 제한한다. GitHub Linux의 첫 실행은 상대경로 처리에서 네이티브 버퍼 검사로 종료 134 발생. 고정 소스 `getAbsolutePath`가 상대경로를 260-byte `InpDir`에 `realpath`로 쓰는 분기를 사용하므로 이 경로를 피하고, 절대경로 분기의 길이도 호출 전에 검사한다. 엔진 바이너리·빌드 보호 옵션·수치 정책은 변경하지 않는다.

## 2026-10-17 검증 결과

[공개 결과 요약](../data/benchmarks/epa-applications-example1-result.json)에 실행 플랫폼·바이너리·계약·검사 코드 해시와 항목별 수치 보존. 6개 사례의 3개 입력 변형, 총 18회 API와 18회 CLI 실행에서 OUT 바이트와 보고 깊이 일치. 같은 플랫폼의 별도 반복 실행은 요약 JSON 21,151 bytes 전체 일치. 엄격 모드에서도 동일 요약·전체 산출물을 남기고 종료 2 확인. 7개 신규 검사 포함 Python 전체 67개 통과, 기존 4개 성수 모델·원문·빌더 계보 검사 통과.

개발 전 10년 첨두는 매뉴얼 7.34 cfs, 현재 O1 노드 7.334726810455322 cfs로 차이 약 -0.00527319 cfs이며 고정 허용폭 0.005 cfs 초과. 같은 사례의 유출 깊이 0.225 in는 원문 0.22/0.24 in 충돌과 함께 보존. 참조 차이를 버전 차이 때문이라고 확정하거나 허용폭 변경으로 통과시키지 않는다. 유역 합과 O1 노드의 첨두 시각은 1개 보고 간격 차이이며 표면 유출을 현장 방류구 관측으로 해석하지 않는다.

서울 부지의 실제 유역·관망 연결, 세 LID 단면, 관측 보정·독립 사상, 전문가 목적 적합성 검토는 잔여 작업. 이 진단으로 운영 모델·점수·검증 등급을 변경하지 않는다.

Linux CI 경로 오류 후 절대경로 정규화·259-byte 상한 회귀 검사 추가. 상대경로 요청의 실제 API/CLI 실행, 정확한 상한 성공, 다중 바이트 경로 초과의 엔진 호출 전 거부 확인. Python 전체 68개 통과. 18개 입력 재실행에서 기존 공개 요약의 검사 코드 해시 외 수치·판정 전체 불변. Linux 수정 검증은 새 CI 결과와 구분해 기록한다.
