# 단일 관리자와 회원 유형·승인

2026-10-16 사용자 정정 우선. 결정 0001·0002·0005의 기관 역할 설명을 아래 계약으로 대체한다.

## 역할·유형

- 권한 역할: `ADMIN`, `MEMBER`. 관리자는 운영용 단일 계정. DB 유일 제약과 비공개 로컬 초기화 명령으로 생성, 공개 가입·관리 화면에서 추가 관리자 생성 금지.
- 회원 유형: `PLAYER`, `BUSINESS`, `INSTITUTION`, `GOVERNMENT`. 기업·기관·정부는 관리자가 아닌 회원이다.
- 플레이어는 가입 즉시 승인 상태로 이용. 기업·기관·정부는 `PENDING`으로 신청하고 관리자가 소속·이용 목적을 확인한 후 승인 또는 사유를 남겨 반려.
- 승인 상태: `PENDING`, `APPROVED`, `REJECTED`, `SUSPENDED`. 관리자 자신의 권한·정지 변경 API 금지. 상태 변경 시 기존 세션 무효화·감사 기록.
- 승인된 기업·기관·정부 회원은 리그 운영·소속 조직에 동의된 연구 기록 분석 가능. 관리자 계정은 승인·계정 운영 권한이며 연구 자료에 자동 접근하지 않는다.

## 가입·승인 흐름

가입 DTO는 회원 유형·조직명·이용 목적만 받으며 role·organizationId·승인 상태를 받지 않는다. 플레이어 가입에는 조직 정보가 없어야 한다. 조직 회원은 가입 접수 결과만 받고 로그인 세션은 발급되지 않는다. 올바른 비밀번호 확인 후 승인 상태를 안내한다.

관리자는 가입 신청·상태·검토 이력을 조회하고 신청자의 소속을 검토한다. 새 조직 생성 또는 관리자가 확인한 기존 조직 연결 후 승인한다. 이름만 같다는 이유로 기존 조직에 자동 편입하지 않는다. 승인한 유형·조직은 일반 회원이 변경할 수 없다.

관리자와 조직 회원은 TOTP 필수. 승인된 회원은 비밀번호 확인·CSRF·요청 제한을 거친 등록 세션에서 직접 인증 앱을 연결하고 OTP 검증으로 등록을 마친다. 이미 등록한 비밀키는 이 경로로 조회·덮어쓰기 불가. 등록 전에는 업무 세션·리그·연구 API 접근 불가. 운영자에게 회원 OTP 비밀키를 전달하는 이전 절차 제거.

기존 조직 회원은 새 승인 절차의 대기 상태로 이관하고 세션을 폐기한다. 일반 플레이어·플레이 기록·동의는 보존한다. 관리자 초기화는 계정·소속·승인 우회가 없는 별도 로컬 운영 명령으로 제한한다.

## 검증 기준

플레이어 즉시 이용, 조직 회원 대기·반려·정지 차단, 단일 관리자 유일성, 역할 주입 거부, 승인 API의 일반 회원 차단, 기관 격리, 관리자 연구 접근 차단, 승인/정지 직후 세션 폐기, MFA 등록·재등록 거부·OTP 재사용 차단, 실제 PostgreSQL 이관과 화면 검증.
