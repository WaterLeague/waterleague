## 원본과 파생 계산

기관은 현재 연구 열람이 허용된 성공 제출 계산 한 개를 선택하고 등록 모델 2~3개로 같은 배치를 재계산. 공개 제출 또는 해당 기관 소유 리그 제출이어야 하며, 동의되지 않은 개인 저장본·타 기관 비공개 제출 접근 금지. 대상 모델은 기존 비교 호환성 검사로 강우 외의 형상·시설·매개변수·단가·예산·엔진·빌더·점수 규칙 일치 확인.

원본 계산·불변 저장 버전·메모·연구 동의·순위 변경 없음. 기존 개인 비교 엔진으로 원래 플레이어 소유의 파생 설계/버전/작업을 만들고 별도 기관 분석 행에 원본 제출·비교 그룹·요청 기관·요청자·조건 해시·시각 연결. 기관 계정 소유로 설계를 복사하지 않아 동의 철회 후 소유자 API로 접근할 수 없도록 구성. 파생 계산은 플레이어의 계산·설계 목록에서 본인이 확인 가능하며 자동 제출 없음. 기관 요청임을 버전 이벤트에 기록.

POST /api/v1/research/comparisons: sourceJobId, modelHashes 2~3개, UUID requestKey. 기관+요청 키 유일, 대상 해시 정렬 후 요청 내용 해시 고정. 동일 키·동일 내용 재요청은 기존 그룹 반환, 다른 내용은 409. 성공 작업의 서버 점수를 재검증. 원본 소유자 잠금→공용 큐 입장 잠금 순서에서 동의·계정 상태를 재검사. 개인 활성 3개·전체 500개 기존 한도 유지, 기관 파생 활성 작업 9개 상한. 부족하면 429, 그룹·파생 버전·작업 모두 롤백. 기관별 생성 요청 시간당 12회 제한, 동일 요청의 재전송도 요청 제한 적용.

V9 research_comparisons: id, organization_id, requested_by, source_job_id, comparison_id, request_key, request_hash, created_at. FK·기관/키 및 비교 그룹 유일성 적용. 기존 개인 비교 원문·ID·스키마 유지, 새 선택적 생성 맥락 필드만 파생 이벤트에 추가.

## 읽기·철회·재현

- GET /api/v1/research/comparisons: 본 조직의 현재 열람 가능한 최근 50개 요약
- GET /api/v1/research/comparisons/{id}: 원본 작업/버전·생성 맥락·각 강우의 계산 상태/결과. 목록과 상세 모두 현재 조직 승인·회원 상태·원본 연구 동의 재검사
- GET /api/v1/research/comparisons/{id}/jobs/{jobId}/bundle: 해당 그룹의 파생 작업만 재현 ZIP. 파일 구성 전후 원본 동의·현재 조직 접근·작업 연결 재검사

원본 연구 동의 철회·계정 정지·기관 승인 해제 시 기관의 목록/상세/재현 파일 접근 차단. 이미 내려받은 파일은 자동 회수 불가. 진행 중인 수치 작업은 완료될 수 있으나 기관 접근 권한이 생기지 않음. 다른 조직은 같은 원본에 별도 동의가 있어도 이 분석 그룹에 접근 불가. 플레이어 소유권은 유지. 기관 구성원 교체 시 같은 승인 조직·MFA·원본 동의 조건으로 열람.

ZIP의 access-scope에 RESEARCH_RAINFALL_COMPARISON, 기관 분석 ID·원본 계산/버전·원본 모델 해시·대상 모델 해시·조건 해시 포함. 기존 고정 빌더·입력/출력·물수지·manifest 유지. 기관 자료 읽기·생성·다운로드 감사 기록. 관리자 자동 열람 금지. API 응답 no-store, 비밀값·개인 연락처 입력 없음.

## 패턴 분석의 모집단과 해석

POST /api/v1/research/patterns: jobIds 1~50개, topK 1~20. 모든 작업은 현재 기관에 동의된 성공 제출이며 동일한 모델 원문 해시 필요. 모델이 다르면 같은 강우·같은 조건의 순위로 혼합하지 않음. 비공개 후속 버전·다른 계산 메모 접근 없음. 계산 결과 품질/해시를 검사하고 서버 물수지에서 점수를 다시 계산.

면적의 불필요한 소수 0을 제거하고 구역 ID로 정렬한 별도 physicalHash가 같은 배치는 한 설계로 집계. 원본 inputHash는 보존. 요청 수·고유 배치 수·중복 수 공개. 고유 설계를 서버 8자리 점수로 정렬하고 topK 경계 동점 전부 포함; 실제 포함 수와 선택 작업 ID·원본 inputHash·정규화 physicalHash·점수·원화 비용을 반환. 이는 선택한 동의 자료 집합 안의 상위 설계이며 전체 시민·전체 리그의 대표 표본이 아님. 한 플레이어가 여러 설계를 포함할 수 있으므로 사람 수로 표시 금지.

같은 physicalHash의 점수 또는 원화 비용이 일치하지 않으면 품질 오류로 집계 거부. 작업 ID 사전순으로 동일 입력의 대표를 고정하며 통계에 제외된 중복도 요청 수에 포함. 기존 계산 결과의 점수 필드만 신뢰하지 않고 서버 물수지에서 재산출.

구역×시설별 등장 설계 수, 전체 포함 설계 수를 분모로 한 빈도, 설치한 설계의 최소/최대/평균 면적과 미설치를 0으로 포함한 평균 면적 제공. 시설 종류 쌍의 동시 등장 수, 비용/점수 범위 제공. 입력 배열 순서·중복 요청 순서에 따른 결과 변화 금지. 시설 합계·횟수는 실제 서버 저장 배치에서만 집계. 통계는 소수 반올림 규칙 명시, 조회마다 현재 동의를 검사하고 개인 자료를 포함한 집계를 공유 캐시에 보관하지 않음.

상위 집합의 반복 패턴은 효과 원인·통계적 유의성·현장 추천이 아님. 서로 다른 비용·시설 제약을 가진 제출이 포함될 수 있음. 특정 구역 선호·시설 조합을 보여 주는 기술 통계이며 학습 모델이나 AI 검증이라고 표시하지 않음. 시민 패턴의 추가 후보 생성은 아래 탐색 계약처럼 별도 물리 재평가와 명시한 탐색 예산을 적용한다.


## 저장 버전의 다강우 비교 그룹


### API·보관

- `POST /api/v1/comparisons`: `sourceVersionId`, 등록 모델 해시 `modelHashes` 2~3개, UUID `requestKey`. 현재 편집 배치가 아니라 저장된 불변 버전을 서버에서 읽음
- `GET /api/v1/comparisons`: 본인 그룹 최근 50개 요약
- `GET /api/v1/comparisons/{id}`: 본인 원본 버전·각 복사 버전/설계 ID·계산 작업과 상태. 다른 회원은 404
- 원본 설계명·생성 시각·요청 조건 해시·원본 버전·작업 연결 보존. 모델 해시 순서는 정렬하여 멱등 판정
- 각 대상에 새로운 개인 설계·불변 버전·작업 생성. 원본 버전과 기존 결과 수정 금지. 복사 이벤트에 비교 그룹·원본 버전 ID 기록
- 기관 동의·리그 제출·일반 순위 제출 자동 생성 금지

### 입력 일치·동시성

시설 셀/면적·단가·원화·예산·최대 시설 수·수문 매개변수·시설 제원·엔진·생성기·점수 규칙 일치 필요. 강우만 달라지는 등록 모델에 한정. 계산 가능 상태·배치 비용 재검증.

계정 잠금→멱등 조회→소유권·호환성 검증→공용 큐 입장 잠금→개인 활성 3개/전체 500개 한도 검사→전체 생성 순서. 기존 작업을 포함한 여유가 부족하면 429, 그룹·버전·작업 모두 생성하지 않음. 하나라도 저장/큐 등록에 실패하면 전체 트랜잭션 롤백. 대상 작업 수만큼 기존 `run` 시간당 요청 제한 차감. 재전송은 같은 키를 유지하며 다른 입력을 같은 키로 재사용하면 409.

### 화면·해석

로그인한 회원이 저장 버전을 선택해 비교 생성. 편집 내용이 아직 저장되지 않았으면 저장 버전을 비교한다는 문구와 버전 번호 표시. 비교 도중 이동해도 작업 유지. 각 행에 대기/계산/실패/성공 구분, 성공한 결과만으로 그룹 전체 성공 표시 금지. 완료 결과는 강우별 점수·평가체적·저류·물수지, 각 작업의 재현 ZIP과 개인 설계 열기 제공. 통합 순위·현장 적용 등급 생성 금지.

브라우저·실제 PostgreSQL 워커 검사와 소유권·중복 요청·부분 실패 롤백·호환성·동시 큐 한도 회귀 검사 완료 전 구현 완료로 표시하지 않음.


## 시민 배치 패턴 기반 후보 생성·물리 재평가

EXPLORATORY 범위의 결정적 후보 생성과 물리 재평가다. 전역 최적·현장 효과·학습 성능 우월을 주장하지 않는다.

### 학습 표본·목적

현재 조직에 연구 동의된 동일 모델의 성공 제출 2~50개 선택. 서버 물수지에서 점수 재산출, 불변 버전·입력 hash·비용 재검사. 동일 물리 입력은 한 번만 사용하고 서로 다른 배치 최소 2개 필요. 요청 상위 기준 2~20개와 경계 동점 전부를 학습 집합으로 사용. 중복 대표 작업은 UUID 문자열 사전순으로 고정. 요청한 모든 원본의 현재 동의가 조회·생성·다운로드 권한 조건이며, 상위에서 제외된 원본도 요청 표본의 일부로 보존.

물리 중복 판정은 배치를 구역 ID 순서로 정렬하고 면적의 불필요한 소수 0을 제거한 별도 physicalHash 사용. 원본 inputHash·배치 원문·버전 ID는 변경하지 않고 함께 보존. 원본 점수·비용이 다른데 physicalHash가 같으면 품질 오류로 학습 거부.

예산은 1원~모델 예산의 정수 원. 모든 선택 원본의 비용이 요청 예산 이내여야 비교 허용. 모든 후보는 동일 모델·예산·시설/면적/개수 제약 적용. 서로 다른 리그의 추가 조건까지 동일하다는 의미가 아니며 해당 리그 순위에 제출하지 않음. 파생 후보는 시민 원본이 아니므로 일반/리그 자동 제출·개인 전략 자동 복사 없음.

### 생성 방법 V1

정책 `ELITE_CATEGORICAL_SEARCH_V1`. 상위 배치에서 구역마다 NONE 또는 허용 시설×면적 비율(25%, 50%, 75%, 100%)의 범주 빈도를 추정. 원본 면적/maxArea를 가장 가까운 비율로 분류하고 거리 동률은 작은 비율 선택. NONE은 미설치. 범주마다 가산 평활 1개 적용; 독립 구역 가정이며 구역 간 상관·인과를 학습한 모델이 아님.

분포 추정 탐색의 개념적 근거: [Dang·Lehre·Nguyen, Level-Based Analysis of the Univariate Marginal Distribution Algorithm](https://link.springer.com/article/10.1007/s00453-018-0507-5), 2018 온라인/2019 수록. 본 구현은 혼합 시설/면적 범주의 한 세대 생성 변형이며 논문의 이진 문제 수렴·복잡도 결과를 물환경 문제의 성능 보증으로 전용하지 않음.

- 입력: 고정 모델·검증된 물리 배치/서버 점수·예산·상위 기준·seed(0~2,147,483,647)·방법당 후보 수(1~4, 기본 3)
- 두 방법: 학습 빈도+1 가중치 `PATTERN`, 모든 범주 가중치 1인 `UNIFORM`. 같은 후보 수·예산·최대 128번 생성 시도로 비교
- 구역 순서: 각 시도의 SHA-256 키로 정렬. 고정된 앞 구역만 예산을 먼저 쓰는 편향 축소. 동률은 구역 ID 사전순
- 구역 선택: 남은 예산/시설 개수/면적 한도 안의 범주만 허용, NONE 항상 허용. SHA-256 정수의 누적 정수 가중치 추첨. 예산을 초과한 배치를 사후 비례 축소하지 않음
- 범주 누적 순서: NONE, 시설 enum 이름 사전순, 각 시설 안의 비율 오름차순. 보고서 구역 순서는 구역 ID 사전순
- 실제 면적: maxArea×비율, 소수 2자리 HALF_UP. 0이 된 범주 제외. 구역 ID 순서로 배치 정렬, 불필요한 소수 0 제거 후 기존 Java 배치 직렬화와 동일 형식
- 시드 규약: `policy + '\n' + modelHash + '\n' + seed + '\n' + arm + '\n' + attempt + '\n' + purpose + '\n' + cellId`. attempt는 0부터, purpose는 ORDER 또는 CHOICE. 전체 SHA-256 unsigned 정수 사용. ORDER는 hex 문자열 사전순, CHOICE는 허용 가중치 합으로 나눈 나머지
- 빈 배치·선택 원본과 같은 물리 hash·같은 방법 안의 중복 후보 제외. 두 방법 사이 동일 후보는 허용하고 중복 수 공개; 별도 시민 성과로 세지 않음
- 목표 수를 128회 내 채우지 못하면 `CANDIDATE_SPACE_EXHAUSTED` 422, 작업/그룹 생성 없음. 실제 생성 시도 수·거부 사유별 수·모든 범주 빈도와 가중치·포함 원본·생성 결과 보존

확률 모형은 이 요청의 상위 표본에서 한 번 추정. 실행 결과로 다시 학습하는 반복 최적화나 신경망 아님. 무작위 대조와 후보 수가 같아도 한 표본·한 seed 결과만으로 알고리즘 우수성 검증 불가. 원본 최고점·각 방법의 모든 성공/실패·최고점·비용을 함께 공개하고 실패가 있으면 완전 비교로 표시하지 않음.

### 저장·권한

독립 optimization 도메인과 V10. `research_searches`에 기관/요청자/기관별 멱등키/요청 hash/모델 hash/예산/시드/상위 기준/방법당 개수/생성 계보/생성 시각. `research_search_sources`에 원본 계산 FK. `research_candidates`에 그룹 FK/방법/순번/배치 원문/모델·입력 hash/비용/상태/결과/오류/lease·시도·완료 시각. 그룹 내 방법·순번과 방법·입력 hash 유일성.

개인 전략 버전이나 개인 simulation_jobs를 만들지 않음. 원본 소유자 또는 기관 구성원의 개인 전략/계산 API로 후보가 조회되지 않으며, 연구 경로만 현재 기관 승인·MFA·모든 원본 동의 재검사. 다른 조직은 같은 원본에 동의가 있어도 이 그룹 접근 불가. 관리자 자동 열람 금지. 동의 철회 뒤 계산은 끝날 수 있으나 기관 결과·생성 계보·묶음 접근 차단. 이미 내려받은 자료는 회수 불가. 기존 연구 공유 설명에 패턴 학습·후보 생성/물리 재평가 범위 명시.

원본 소유자 UUID 정렬 순서로 잠금 후 공용 입장 잠금. 기관 활성 계산 9개는 다강우+새 후보를 합산, 전체 활성 500개도 개인+연구 후보 합산. 기존 개인 활성 3개는 개인 계산에 적용. 기관 생성 시간당 6회, 동일 요청 재전송 포함. 모든 후보 큐·그룹·원본 연결 한 트랜잭션, 부족하면 429와 전체 롤백. 같은 기관/키·같은 내용은 기존 그룹, 다른 내용 409.

### 큐·산출물

개인 계산과 연구 후보가 같은 워커 자원을 사용. 공용 입장 잠금 아래 두 큐의 처리 가능 작업 중 가장 오래된 작업 하나를 claim, 각 작업의 행 잠금·SKIP LOCKED·180초 lease·최대 3회·fencing 유지. 후보별 별도 프로세스의 기존 90초 wall/75초 CPU·파일/메모리 제한과 검증된 SWMM/캐시 재사용. 예약한 후보 수를 숨기거나 이후 무제한 계산 추가 금지.

개인 데이터가 없는 동일 물리 입력의 캐시만 재사용. 후보별 request/result·manifest는 독립. 원본과 같은 입력을 새 성과로 세지 않음. 원본 18개 파일의 검증·동일 엔진 재실행, `search-provenance.json`에 학습 입력/분포/seed/추첨 규약/시도 수/전체 후보, `access-scope.json`에 연구 목적·기관·검색/후보 ID·원본 연결·조건 해시. 모델/입력/파일 해시와 생성 계보를 별도로 검증할 재생 도구 제공.

후보 산출물은 `ARTIFACTS_PATH/research-candidates/{candidateId}/{leaseToken}`에 저장. 개인 작업의 기존 `{jobId}/{leaseToken}` 경로와 분리. 큐 종류는 코드의 고정 목록만 허용하며 요청 데이터로 테이블명·경로 종류를 지정하지 않음. 같은 생성 시각의 claim 순서는 큐 종류·UUID로 고정. 만료 작업의 최종 결과도 lease token·유효 시간으로 조건부 기록하고, 갱신 행이 없으면 완료로 보고하지 않음.

단계 2는 저장·공용 워커·큐 상한을 먼저 연결하고, 이후 기관 API·재현 묶음까지 확장. 워커 시험은 별도 임시 PostgreSQL DB에 실제 마이그레이션을 적용해 두 큐 경쟁·재시도·만료 결과 차단·공개 모델의 실제 SWMM 처리를 검증. 운영 원본에 시험 큐를 넣지 않음. API와 화면 연결 전에는 사용자 기능 완료로 표시하지 않음.

### API·화면

- POST `/api/v1/research/searches`: jobIds, topK, budgetKrw, seed, candidatesPerArm, requestKey. 202/no-store
- GET `/api/v1/research/searches`: 현재 모든 원본에 접근 가능한 소속 기관 최근 50개
- GET `/api/v1/research/searches/{id}`: 생성 계보·원본 최고 결과·두 방법의 후보 배치/비용/계산 상태/수치. 생성은 성능 개선 증거가 아님
- GET `/api/v1/research/searches/{id}/candidates/{candidateId}/bundle`: 해당 그룹 성공 후보의 재현 ZIP, 준비 전후 현재 권한 검사
- GET `/api/v1/research/searches/{id}/provenance`: 생성 계보 JSON, 현재 권한 검사

상세 응답은 원본 최고 점수·생성 계보 hash·모든 후보의 상태/비용/배치/서버 재산출 점수·방법별 성공/실패 수를 함께 제공. 모든 후보가 성공한 경우에만 completeComparison=true. 실행 전이나 일부 실패 시 최고점만으로 비교 완료를 표시하지 않음. 목록은 현재 모든 원본에 접근 가능한 그룹을 먼저 필터링한 뒤 최근 50개 선택.

조회 시 저장 계보 hash, 원본 연결 집합, 모델/설정, 방법·순번별 후보의 배치 원문/hash/비용을 대조. ZIP은 고정 파일명 19개(manifest 포함)와 생성 계보·접근 범위만 포함하고 합계 64MiB 제한. 디렉터리·파일 링크 거부, manifest의 18개 파일 hash와 모델/요청/결과 식별값 대조 후 응답. 준비 전후 기관·모든 원본 동의 검사. 재현 파일 손상은 품질 오류로 거부하고 내부 경로 노출 금지.
