# 리그 참가·초대·팀전

2026-10-16. 원기획 PDF 2쪽 및 붙여넣은 기획의 참가 자격·개인/팀 경쟁 구현 계약. 회원가입 승인과 리그 참가 승인은 별도 상태이며 일반 플레이어 가입에는 관리자 승인을 추가하지 않음.

## 고정 규칙

규칙 schemaVersion 3의 `participation`에 `access`(PUBLIC/INVITE), `admission`(OPEN/APPROVAL), `entryMode`(INDIVIDUAL/TEAM), `teamSizeLimit`(팀전 2~10명, 개인전 null)을 포함. 공개 시 규칙 원문·hash와 함께 고정. PUBLIC은 누구나 규칙·순위 열람, INVITE는 주최 조직과 승인 참가자만 순위 열람. 초대 코드 보유자는 로그인 후 규칙을 미리 보고 신청할 수 있으며 신청 대기자는 본인 상태와 규칙만 열람. 반려·탈퇴자는 코드 없이 비공개 규칙에 접근 불가.

기존 schema 1/2 원문·hash·제출 방식 유지. 이전 클라이언트가 `participation`을 생략한 초안은 기존 schema 2 공개 개인전으로 저장. 새 UI는 항상 schema 3 참가 규칙을 명시. schema 3은 규칙 확인 후 명시적 참가 절차 필수; OPEN은 즉시 승인, APPROVAL은 주최 조직의 승인 필요. 기관의 일반 가입 승인이나 연구 동의로 리그 참가 승인을 대체하지 않음.

## 참가와 초대

리그별 회원당 1개 참가 행, 상태 PENDING/APPROVED/REJECTED/WITHDRAWN·revision·동의 rulesHash·시각 보존. 신청·결정·탈퇴 이력은 별도 불변 이벤트에 기록. 반려·탈퇴 후 재신청 시 새 규칙 확인 및 비공개 리그의 현재 초대 코드 필요. 승인 변경은 최신 revision과 사유 필수. OPEN 리그라도 주최자가 반려한 회원은 `reviewRequired`를 유지하고 재신청을 PENDING으로 처리; 대기 중 탈퇴·재신청으로 우회 불가. 주최자의 명시적 APPROVED 결정으로만 해제. 탈퇴·재승인으로 제출 횟수 초기화 금지. 모집은 공개 후부터 마감 전까지, 제출은 기존 접수 시작·마감 조건 유지. 취소·마감 후 상태 변경 금지; 본인 탈퇴는 허용하되 기록 삭제 아님.

리그 초대와 팀 초대는 서로 다른 코드. 32바이트 CSPRNG를 URL-safe base64로 인코딩, DB에는 용도별 SHA-256만 저장. 신규 발급/회전 응답에서 한 번만 표시, 조회·감사·URL·브라우저 저장소에 평문 저장 금지. 로그인·CSRF·빈도 제한 적용. 코드의 유효기간은 리그 마감까지이며 회전/폐기는 즉시 신규 사용 차단. 기존 참가 승인에는 영향 없음. 잘못된 코드·다른 리그 코드는 공통 404로 응답.

## 팀전

승인된 플레이어는 리그당 한 팀만 소속. 팀장은 팀을 만들고 팀 초대 코드를 발급/회전/폐기. 초대받은 승인 참가자는 팀 이름·규칙을 확인하고 참가하며 팀원 수 상한은 서버에서 직렬화. 팀원은 본인이 계산한 설계만 제출, 팀 전체 제출 횟수 공유, 팀 최고 점수 하나로 순위 산정. 팀 가입은 다른 회원의 개인 설계·메모·다운로드·연구 동의 권한을 부여하지 않음. 동시 편집 기능을 구현한 것으로 표시하지 않음.

첫 제출이 성공한 트랜잭션에서 팀 구성 고정. 그 뒤 신규 가입·탈퇴·해산·팀 변경 금지. 리그 참가 철회는 가능하나 고정 팀 이력은 보존; 팀원 중 참가 철회/반려/계정 정지가 있으면 팀의 신규 제출 및 순위 표시 중지. 동일 참가 행 재승인 시 동일 팀·누적 횟수로 복귀. 첫 제출 전 일반 팀원 탈퇴 가능, 팀장은 혼자일 때만 해산 가능. 실패한 제출로 팀 고정 금지.

순위에는 개인 닉네임 또는 팀 이름·점수·원화 비용·시각만 표시. 팀 내부는 닉네임·팀장 여부·참가 가능 상태·팀 누적 횟수 제공, 제출 작업 ID는 각 소유자에게만 제공. 주최자는 참가 신청과 검토 이력을 관리하며 연구 세부 자료는 기존 별도 동의 필수. 다른 조직의 비공개 리그 제목·규칙은 동일 작업의 연구 맥락에서도 숨김.

## 경합·데이터

참가·초대·팀 변경·제출은 회원 행 다음 리그 행 잠금 순서 적용. PostgreSQL 회원 잠금은 FOR NO KEY UPDATE로 계정 변경과 경쟁 요청을 막으면서 참가 상태 변경의 외래키 KEY SHARE 검사는 허용. 회원 FOR UPDATE와 리그 잠금이 외래키 재검사에서 역순으로 교착되는 경로를 통합 검사로 재현·차단. 리그 행 잠금으로 취소, 승인 철회, 팀 정원, 첫 제출/팀 변경, 공유 제출 한도 경합 직렬화. 짧은 DB 트랜잭션 안에서만 처리하고 계산 실행은 포함하지 않음. 현재 규모에서는 리그별 직렬화를 선택하며 실제 Oracle 부하 검증 전 처리량 보장 없음.

DB V8: 참가/참가 이벤트/리그 초대/팀/팀원 테이블, 리그 공개 범위 색인 열과 제출 team_id 추가. 복합 FK로 팀과 참가/제출의 리그 일치 강제. 기존 제출 team_id=null. 참가 목록은 UUID 커서 100건, 본인 참가 리그는 최신 신청 100건. 코드 검증·신청·팀 생성/가입 호출 제한 및 리그당 참가자 10,000명 한도.

## 구현·검증 단계

1. 서버 계약·마이그레이션·권한·순위·연구 맥락·통합/경합 검증.
2. 초안 설정·코드 미리보기·참가 상태/승인·팀 관리·공유 한도 UI와 실제 PostgreSQL/브라우저 검증.

둘 다 통과해야 원기획 참가 방식 완료. 기존 공개 기록·연구 동의·규칙 원문 회귀 확인, 초대 회전/폐기/만료·코드 혼용·비공개 목록/직접 접근 차단, 대기/반려/탈퇴/재신청·revision 경합, 동시 팀 정원/제출·고정 구성·타인 계산 접근 차단, 조직 승인 철회 및 MFA 검사 포함. 시험용 계산 상태로 수행한 권한 시험은 실제 수문 계산 검증과 구분.

설계 근거: [PostgreSQL 행 잠금과 교착 방지](https://www.postgresql.org/docs/current/explicit-locking.html), [OWASP 난수 토큰의 안전한 저장·만료·요청 제한](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html). 후자는 비밀번호 복구 안내의 토큰 취급 원칙을 초대 코드에 적용한 설계 판단이며 초대 기능 표준 인증을 의미하지 않음.


## 진행 상태

서버 단계 구현 및 H2/실제 PostgreSQL HTTP 통합 검사 통과. UI는 새 규칙 해석·팀 한도/방식·연구 제출 팀 표시만 반영; 참가 신청·운영·팀 관리의 실제 사용자 흐름은 후속 구현. 서버 기능을 브라우저 완료로 계산하지 않음. 세부 근거는 [검증 기록](11-validation-log.md) 참조.
