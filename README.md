# WATER LEAGUE

작성 기준: 2026-10-19 현재 코드와 저장 데이터.

## 1. 게임 개요

WATER LEAGUE는 서울 지도에 빗물관리시설을 설치하고, 실제 관측 강우를 적용해 시설 설치 전후의 물 흐름·침투·저류 차이를 비교하는 웹 시뮬레이션 게임이다. 사용자는 원화 예산 안에서 시설 종류·위치·면적을 정하고, 주간 대항전이나 과거 집중호우 실험에 참여한다.

서울 25개 구를 3D·2D 지도로 탐색할 수 있다. 건물·도로·주차장·하천·지형은 공개 공간자료를 사용하고, 강우·기상·생활인구는 제공기관의 자료를 연결한다. 시설 효과는 EPA SWMM으로 계산한다. 현재 경쟁 지표는 시설별 독립 표면의 평가체적 차이이며, 현장 침수 피해 예측이나 실제 공사 효과의 검증값과 구분한다.

## 2. 게임 방식

### 주간 서울 대항전

회원은 소속 구를 정하고 해당 구의 후보 위치에 시설을 설치한다. 다른 구도 이동·조회할 수 있다. 같은 위치에 여러 회원이 설치할 수 있지만, 각 회원의 설계는 독립된 비교 시나리오로 계산한다. 다른 회원의 시설을 하나의 물리 공간에 중복 합성하지 않는다.

1. 소속 구와 설치 시설을 선택한다.
2. 지도·목록에서 후보를 선택하고 설치 면적·참고비·예산 잔액을 확인한다.
3. 설치를 확정한다. 같은 회원의 동일 위치 중복 설치는 차단한다.
4. 설치 시각 이후 실제 관측 강우에 따른 기여가 누적된다.
5. 구별·개인별 순위와 같은 위치의 회원별 시설 기록을 확인한다.

시즌은 월요일 00:00 KST를 경계로 구분한다. 확정한 시설은 해당 시즌 종료까지 변경·철거할 수 없다. 시즌 종료 시 활성 배정을 해제하고 예산을 복원하며 설치·비용·계산 기록은 보존한다.

이번 주·지난주 구별 순위, 개인 상위 100명, 내 순위, 지난주 우승 구를 제공한다. 동점은 공동 순위로 처리하고 음수 기여도 반영한다. 미계산·일부 미평가·집계 완료를 구분하며, 종료 주의 평가 구간이 모두 계산된 경우 양수 최고 기여 구를 우승으로 확정한다.

### 재해 실험

2010년·2011년·2022년 집중호우의 관측 구간을 재생하면서 개인 설계를 시험한다. 현재 공개 공간 형상에 당시 강우를 적용하는 방식이다.

1. 집중호우 사건을 선택한다.
2. 재생·일시정지·시간 이동·배속으로 사건을 살펴본다.
3. 원하는 재생 시각에 시설을 설치하거나 취소한다.
4. 설치 전 효과를 제외하고 현재 재생 시각까지의 누적 효과를 확인한다.
5. 로그인 후 설계를 저장하고 확정 제출한다.

여러 구에 배치한 시설을 하나의 설계·예산으로 관리한다. 구별 자동 계산, 계산 진행 상태·실패·재시도를 제공한다. 시간축에는 모든 구의 설치 시각과 시설 아이콘을 표시하며, 표식을 선택하면 해당 시각·위치로 이동한다. 1~3,600배속, 첫 비·강우 최대 시각 이동을 지원한다.

회원 설계는 설치·취소마다 저장본을 만들고 재접속 시 복원한다. 전체 취소의 빈 설계도 기록한다. 저장 재시도의 중복과 다른 창에서 수정한 저장본의 충돌을 검사한다. 같은 화면에 남아 있는 비회원 체험 설계를 로그인 후 가져올 수 있다.

### 재해 제출·기록 경쟁

제출은 최신 저장본을 확정한 별도 계산이다. 모든 구의 확정 시설을 설치 시각과 무관하게 사건 평가 시작부터 종료까지 적용한다. 실험 도중의 누적 효과와 제출 최종값을 분리한다.

제출 당시 배치·원가·설치 시각·계산 입력을 고정하고 이후 편집으로 변경하지 않는다. 제출별 대기·실행·성공·실패 상태와 재현 자료를 제공한다. 사건·평가 규칙이 같은 기록끼리 비교하며 회원별 최고 기록, 공동 순위, 설치비·제출 시각을 표시한다.

### 설치 후보와 제한

- 건물·지상 주차장 계열 후보 154,784개와 도로·보행로 추가 후보 541,486개를 등록했다. 합계 696,270개이며 설치 제한 대상도 포함한 후보 수다.
- 시설 선택 시 해당 시설을 허용하는 후보만 표시·선택한다.
- 투수포장은 차도, 인도·보행로, 주차장·기타 지상으로 후보를 나눈다. 지도 도로 클릭도 같은 후보 선택으로 연결한다.
- 면적 입력·슬라이더·미리보기, 후보별 면적 상한, 면적×단가, 예산 내 사용 가능액을 표시한다.
- 서버에서 소속 구·소유권·후보·시설 종류·면적·예산·중복 위치를 검사한다.
- 공개 기존 시설의 확인된 건물·부지와 같은 공간·층위의 신규 설치를 차단한다.
- 후보 등록은 구조안전·굴착·배수 연결·시공 허가의 확인을 의미하지 않는다.

### 예산·원가

개인 예산 20억 원은 서울시 2026년 빗물관리시설 확충사업의 공개 총사업비를 참고한 게임 규칙이다. 실제 개인 배정액이나 자치구별 교부액이 아니다. 여섯 시설은 같은 상위 사업 예산을 사용하며 시설마다 20억 원을 복제하지 않는다. 재해 설계는 주간과 별도의 한도에서 모든 구의 배치를 합산한다.

설치 당시 수량·단가·출처·포함 및 미산정 범위를 원가 기록으로 고정한다. 예산 차감액은 공개 참고비이며 완전한 현장 공사비는 미확정으로 보존한다. 과거 설치·제출에 새 단가를 소급하지 않는다.

- 서울 전체 보기, 구 검색·선택, 소속 구 강조, 이동·회전·확대·축소, 전체화면.
- 위치·선택·근접 배율을 유지하는 3D·2D 전환과 최소 확대 거리 18m.

- 사용자 시설 6종의 종류별 3D 기호·2D 도형과 본인 시설·선택 상태 구분.
- 공개 기존 시설의 위치·제원·출처 조회, 표시 켜기·끄기, 확인된 건물·부지 표현.
- 주간 현재 시각·재해 재생 시각에 따른 태양·하늘·그림자·수면 밝기, 야간 창문·가로등·차량 전후등.
- OSM 도로·일방통행·우측 차선을 따르는 차량과 보행로·보도를 따르는 보행자.
- 시간대별 생활인구에 따른 표시 객체 수 배분, 유효한 현재 장소 인구·평균 도로 속도 적용.
- 공개 지상 주차장 523곳의 경계·표시 주차 칸·정차 차량. 가까운 80곳과 3D 정차 차량 400대 상한.
- 주차장 내부 통로의 일반 차량 통과 제외, 설치한 지상 시설과 겹치는 표시 주차 칸 제외, 투수포장 위 주차 유지.
- 표시 침수 경계에 따른 차량 감속·정차·비상등, 보행자 회피·고립 신호, 정차 차량 노출 기호.
- 재해 시간 이동·배속·정지에 교통·조명·수면 표현 연결. 화면 숨김·동작 줄이기 설정 시 연속 애니메이션 중단.

건물 높이는 원문 높이 태그·층수 환산·표시 가정을 구분한다. 도로 폭·주차선·차량 수·창문·가로등은 실제 측량·개별 객체 추적과 구분한다. 교통·주차 연출과 표시 객체의 침수 반응은 시설 점수나 실제 피해 건수에 합산하지 않는다.

## 5. 물리 계산·결과 처리

### 게임의 평가 계산

공식 EPA SWMM 5.2.4를 고정해 기준안과 설치안을 계산한다. 공개 형상에서 구한 면적·유출 폭, 확보 범위의 지역 지형 경사, 포장 태그, 토성에 따른 문헌 물성, 시설 설계 제원과 관측 강우를 입력으로 사용한다.

선행 7일의 관측 강우·기상 기반 증발산을 연속 계산해 평가 시작 시의 수분·저류 상태로 이어간다. 선행 기간의 누적량은 평가 점수에서 제외한다. 이 초기 상태는 현장 수분 측정값과 구분한다.

평가체적은 다음 항목으로 구성한다.

```text
평가체적 = 표면 유출 + 시설 배수 + 최종 저류 − 초기 저류
기여 = 시설 없는 기준안의 평가체적 − 설치안의 평가체적
```

주간은 설치 이후의 관측 구간, 재해 진행 실험은 시설별 설치 이후 구간, 재해 제출은 사건 전체 평가 구간을 사용한다. 결과가 있는 경우 시설 전후 유출, 시설 상태·물수지, 원가 근거를 조회할 수 있다. 실패·결측·미계산은 효과 0으로 대체하지 않고 음수 차이도 보존한다.

### 관망·지표 계산 구현

게임의 독립 표면 평가와 별도로 SWMM 관망과 ANUGA 지표 2D 계산의 물 교환을 구현했다. 관로·빗물받이·저류·펌프 및 연결 시설의 기준안·설계안 계산, 관측 강우·경계수위 입력, 침투·증발·풍응력의 별도 계산 경로를 갖는다.

원 계산의 수심·운동량·유속 프레임을 저장하고 입력·결과 해시를 검사해 API와 공통 지도에 전달한다. 공개 현재 지표 계산의 연장·재생·원자적 게시 워커도 구현했다. 현재 공개 운영 모형 목록은 비어 있어 이 경로를 서울 전역의 운영 침수 결과로 제공하지 않는다. 공개 DEM·공개 연구 관망·합성 연결 영역에서의 계산과 재현 검증을 구분해 보존한다.

### 물 표시와 기록

과거 침수흔적은 보라색, 자연 하천은 청록색, 계산 침수는 수심·속력 색상으로 구분한다. 과거 흔적은 사건 전체의 사후 기록이며 특정 재생 시각의 침수 깊이로 바꾸지 않는다. 계산 결과가 없는 영역에 임의 물길·수심을 만들지 않는다.

계산 수심은 상대 두께로 표시하고 확보된 유향·유속을 사용한다. 수면의 반사·굴절·잔물결·빗방울은 화면 표현이다. 관측 바람은 해당 표현에 연결하지만 물결 재질을 물리 계산 효과로 합산하지 않는다.

프론트엔드와 백엔드는 도메인별로 나누고 화면·상태 제어·규칙·저장 접근의 책임을 분리한다. 설치·예산·저장본·제출은 서버 트랜잭션과 소유권 검사로 확정한다.

기존 서버에는 기관 리그 생성·참가·규칙 고정·제출, 기관별 연구 공유 동의·철회, 동의된 제출 버전 열람·재현 내보내기, 목적별 활용 동의, 다강우 비교·배치 패턴 분석·후보 탐색 기능도 보존돼 있다. 현재 기본 화면에서 기관 리그는 준비 중으로 표시하고 연구실 진입은 제공하지 않는다.

- 플레이어 가입·로그인·로그아웃과 소속 구 관리.

- 비회원 계산의 세션별·네트워크별·전역 호출 한도와 동시 작업 제한.
- 공통 오류 응답, 내부 스택·비밀값 노출 차단, 계산 자식 프로세스의 비밀 환경 제외.
- 공개 데이터의 출처·제작 및 관측 시점·취득 시각·좌표계·단위·이용조건·원본 및 변환 해시 보존.
- 과거 계산의 입력·정책·비용·자료 버전 보존. 새 데이터로 이전 기록을 덮어쓰지 않음.

자료별 상세 근거는 [자료 계보](docs/03-data-provenance.md), [공간자료 검사](docs/28-spatial-source-audit.md), [강우·관측 교차 점검](docs/15-seoul-observations.md), [관망·수위 자료](docs/16-sewer-observations.md), [게임 규칙](docs/01-product.md)에 기록돼 있다.

## 로컬 실행

JDK 25, Node 22.13 이상, pnpm 11.25.0, Python 3.12~3.14, uv, PostgreSQL, CMake·C 컴파일러 필요. macOS SWMM 빌드는 Homebrew libomp 사용.

`.env.example`은 빈 비밀값 템플릿이다. 기존 `.env.local`을 그대로 사용하고, 첫 설정에서만 예제를 복사한다. `.env`는 사용하지 않는다. DB 접속정보는 `DB_URL`, `DB_USER`, `DB_PASSWORD`, 워커는 `DATABASE_URL`; 외부 강우 재수집에만 `KMA_API_KEY` 필요. 공개된 파생 강우로 계산할 때는 기상청 키가 필요하지 않다.

지도·설치 후보·과거 사건·건물 대조는 저장된 버전의 자료를 사용한다. 주간 기상청 관측과 서울시 현재 도시데이터는 서버에서 직접 조회하며, 관측 시각·유효기간·실패 상태를 구분한다. 인증키를 사용하는 외부 자료 수집은 수집·진단 도구에서 수행하고 키를 브라우저·계산 자식 프로세스에 전달하지 않는다. 건물 대조는 번들 JSON·SHA-256을 서버 시작 시 검사한다. 자료 갱신 후에도 이전 계산의 자료 버전은 보존한다.

```sh
# 저장소 루트, 새 환경에서만 로컬 설정 파일 준비
cp -n .env.example .env.local
chmod 600 .env.local
# .env.local에 실제 DB 접속정보 설정, DB 준비 후 실행
uv sync --project simulation --locked
bash scripts/build_swmm.sh
pnpm --dir frontend install --frozen-lockfile
# 각각 별도 터미널
python3 scripts/run_local.py api
python3 scripts/run_local.py worker
python3 scripts/run_local.py frontend
```

macOS 다중 JDK 환경: `export JAVA_HOME=$(/usr/libexec/java_home -v 25)`. 개발 DB 기본 포트 55432, API 8080, [웹 5173](http://127.0.0.1:5173/). Spring Flyway가 스키마 적용. 테스트는 임시 H2, 실제 로컬 실행은 PostgreSQL 사용. 기본 관리자·우회 계정 없음.
